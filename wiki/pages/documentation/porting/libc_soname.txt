===== Why Alpha Has libc.so.6.1 =====

Every other currently supported Linux architecture that uses glibc 2.x has ''libc.so.6''. Alpha has ''libc.so.6.1'', and ''libm.so.6.1'' with it. The dynamic linker, ''ld-linux.so.2'', was not renamed.

==== Why ====

The reason is an ABI break in January 1997. As of the glibc 970104 snapshot, several basic types changed size on Alpha: ''dev_t'' became 64 bits wide and glibc's ''sigset_t'' changed from an array of ''unsigned int'' to an array of ''unsigned long'' (1024 bits in either case). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-January.mbox#L26971|"Re: glibc upgrade advice?"]], Richard Henderson, axp-list, 23 Jan 1997)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-May.mbox#L5740|"Re: Glibc 2.0.3 and LibX11"]], Richard Henderson, axp-list, 5 May 1997)] Alpha had already shipped binaries against ''libc.so.6'', and those binaries could not be allowed to load the incompatible library, so Richard Henderson changed Alpha's soname to 6.1 on 18 January 1997. [(>[[https://sourceware.org/git/?p=glibc.git;a=commit;h=0c5ecdc449ce581b56090758d5bb5673763ea909|"update from main arhive 970119"]], glibc, 20 Jan 1997)] The same change simplified ''clone()'' to take a single ''void *'' argument. It shipped in glibc 2.0.1. [(>[[https://sourceware.org/git/?p=glibc.git;a=commit;h=831372e7c1|"update from main archive 970127"]], glibc, 28 Jan 1997)]

Binaries built against one library do not work with the other. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-January.mbox#L26756|"Re: glibc upgrade advice?"]], Philip Blundell, axp-list, 23 Jan 1997)] The transition required rebuilding the whole system, and users upgrading from Red Hat 4.x, whose libc was a pre-release glibc snapshot, were still encountering it a year later. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-February.mbox#L18518|"Re: Explain Compilers Libc and Glibc, and what is causing the Probs."]], Richard Henderson, axp-list, 21 Feb 1998)]

Nothing in current Alpha glibc requires the ''.1''. It is a remnant of the 1997 ABI change, kept because changing it back would break every existing Alpha binary.

==== IA-64 ====

IA-64 also used ''libc.so.6.1'' and ''libm.so.6.1'', for undocumented reasons. It entered glibc at ''GLIBC_2.2'' already using 6.1, so it never shipped a ''libc.so.6'' and had no break to signal. IA-64 has since been removed from glibc, leaving Alpha as the only architecture using 6.1.
