===== Operating Systems =====

Digital supported three operating systems on Alpha: OpenVMS, DEC OSF/1 (renamed Digital UNIX and then Tru64 UNIX), and Microsoft Windows NT. Linux, NetBSD, and OpenBSD are still maintained on Alpha; FreeBSD dropped Alpha in 7.0. Current Linux distributions for Alpha are listed on [[:distributions|Distributions]].

^ Operating system ^ Current status ^
| Linux | Maintained in the mainline kernel; since Linux 6.10 an EV56 (21164A) or later processor is required (see [[#linux|Linux]]) [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] |
| NetBSD | Maintained; supported in NetBSD 11.0 (July 2026) [(>[[https://www.netbsd.org/releases/formal-11/NetBSD-11.0.html|NetBSD 11.0 release notes]], The NetBSD Project, 30 Jul 2026)] |
| OpenBSD | Maintained; supported in OpenBSD 7.9 (May 2026) [(>[[https://www.openbsd.org/79.html|OpenBSD 7.9]], The OpenBSD Project, 19 May 2026)] |
| FreeBSD | Removed in FreeBSD 7.0; 6.x was the last series [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)] |
| OpenVMS | VSI releases V8.4-2L1 and V8.4-2L2, with standard support through 2035 [(>[[https://products.vmssoftware.com/alpha|"Future Proof Your Alpha System"]], VMS Software Inc.)] |
| Tru64 UNIX | HP's engineering support ended at the end of 2012, followed by Mature Product Support without further releases [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-tru64-mbox/googlegroups-2011-April.mbox#L1264|"Re: Tru64 licenses"]], Martin, comp.unix.tru64, 23 Apr 2011)] |
| Windows NT | Windows NT 4.0 was the last release; Alpha development ended in 1999 (see [[#windows_nt|Windows NT]]) |

Which of these a system can run depends mostly on its [[software:firmware|firmware]]:

^ Operating system ^ Firmware ^
| OpenVMS, Tru64 UNIX | [[software:firmware:srm|SRM console]] |
| Windows NT | [[software:firmware:arc|ARC or AlphaBIOS]] |
| Linux | SRM (with [[software:boot_loaders:aboot|aboot]]), or ARC, AlphaBIOS, or ARCSBIOS (with [[software:boot_loaders:milo|MILO]]) |
| FreeBSD, NetBSD, OpenBSD | SRM |

OpenVMS, Tru64 UNIX, and the BSDs boot only from the SRM console; [(>{{wiki:hardware:motherboards:common:srm_console_user_guide.pdf?linkonly|Alpha SRM Console for Alpha Microprocessor Motherboards User's Guide}}, p. 1-2)] systems without SRM, such as the Alpha XL and XLT, can run only Windows NT and Linux (with MILO). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L25578|"Re: Does DEC have a clue?"]], Jay Estabrook, axp-list, 20 Jan 1998)] The SRM console for evaluation boards and OEM motherboards was licensed separately (see [[software:firmware:srm#licensing|SRM licensing]]).

==== Systems without Linux support ====

  * **DEC 3000, DEC 4000, and DEC 7000:** the kernel has no support for these systems, before or after Linux 6.10. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.10|arch/alpha/kernel/setup.c]], Linux 6.10)]
  * **AlphaServer 8200, 8400, GS60, and GS140 (TurboLaser):** the kernel has no support for these systems, before or after Linux 6.10. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.10|arch/alpha/kernel/setup.c]], Linux 6.10)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-September.mbox#L17415|"Re: AlphaServer GS140 (8400)"]], Jay Estabrook, debian-alpha, 23 Sep 2003)]
  * **Systems and processors removed in Linux 6.10:** the Jensen, all EV4 and EV45 systems, the EB164, and any system fitted with an EV5 (21164) rather than an EV56 (21164A); see [[#linux|Linux]].

==== Linux ====

Linux runs on most Alpha systems, booting from SRM with aboot or from ARC, AlphaBIOS, or ARCSBIOS with MILO. Systems without SRM, such as the Alpha XLT and the Ruffian, need MILO, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L5923|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] and a current kernel needs a MILO built from the alphalinux-org repository; see [[software:boot_loaders:milo|MILO]] and [[software:boot_loaders|Boot Loaders]]. Current distributions are listed on [[:distributions|Distributions]], and the installation procedure is described in [[documentation:installation|Installation]]. Alpha/Linux can also be run without Alpha hardware under [[documentation:qemu|QEMU]].

Linux 6.10 removed support for processors without the BWX extension (the EV4, EV45, and EV5 generations) and for the systems that can only use them. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] The removed systems are:

  * the Jensen (DEC 2000 AXP and DECpc AXP 150), [(>[[https://git.kernel.org/torvalds/c/f81f335a56a8|"alpha: remove DECpc AXP150 (Jensen) support"]], Linux 6.10)]
  * all systems with the LCA processors or the APECS chipset: the AlphaStation 200, 250, 255, and 400 and AlphaServer 300 and 400 (Avanti), the Alpha XL, the Multia and AXPpci 33 (Noname), the AlphaBook 1, the Platform 2000, the EB64+, EB66, EB66+, and AlphaPC 64, and the EV4 versions of the AlphaServer 1000 and 1000A, [(>[[https://git.kernel.org/torvalds/c/430ad3f0ddd7|"alpha: remove LCA and APECS based machines"]], Linux 6.10)]
  * the EV4 and EV45 versions of the AlphaServer 2000 and 2100, and the AlphaServer 2100A (Lynx), [(>[[https://git.kernel.org/torvalds/c/d2b1e353dacc|"alpha: sable: remove early machine support"]], Linux 6.10)]
  * the EB164, which only supports EV5 processors. [(>[[https://git.kernel.org/torvalds/c/4bf859076b16|"alpha: cabriolet: remove EV5 CPU support"]], Linux 6.10)]

Systems sold with both EV5 and EV56 processors, such as the AlphaStation 500 and the AlphaServer 1000, are still supported in their EV56 models. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)]

The Titan (AlphaServer DS15, DS25, and ES45), Wildfire (GS80, GS160, and GS320), and Marvel (ES47, ES80, and GS1280) systems need kernels built without ''CONFIG_ALPHA_LEGACY_START_ADDRESS'', which ''make defconfig'' enables; see [[documentation:kernel#kernel_start_address|Kernel]]. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig.debug?h=v7.3-rc1|arch/alpha/Kconfig.debug]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/configs/defconfig?h=v7.3-rc1|arch/alpha/configs/defconfig]], Linux 7.3)]

==== BSD ====

NetBSD and OpenBSD boot only from the [[software:firmware:srm|SRM console]], because they use the OSF/1 PALcode and cannot use the PALcode that ARC and AlphaBIOS provide. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1998-October.mbox#L4692|"PALcode"]], David Seifert, freebsd-alpha, 9 Oct 1998)] There is no BSD equivalent of MILO. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1999-April.mbox#L3081|"Re: MILO for fbsd?"]], Andrew Gallatin, freebsd-alpha, 8 Apr 1999)]

=== NetBSD ===

NetBSD/alpha is the oldest of the BSD ports to Alpha. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/1996-October.mbox#L134|"alpha 1.2 release"]], Michael Graff, port-alpha, 7 Oct 1996)] It is still maintained, and its ''port-alpha@netbsd.org'' mailing list remains active. Alpha is supported in NetBSD 11.0 (30 July 2026) and 10.2. [(>[[https://www.netbsd.org/releases/formal-11/NetBSD-11.0.html|NetBSD 11.0 release notes]], The NetBSD Project, 30 Jul 2026)] Install images are published for each release, such as ''NetBSD-11.0-alpha.iso''. [(>[[https://cdn.netbsd.org/pub/NetBSD/NetBSD-11.0/images/|NetBSD-11.0/images]], cdn.netbsd.org)] NetBSD also runs under QEMU; see [[software:emulators#other_operating_systems|Emulators]]. The supported systems are listed on the [[https://wiki.netbsd.org/ports/alpha/|NetBSD/alpha]] port page.

=== FreeBSD ===

FreeBSD 6.x was the last series to support Alpha, which was removed in FreeBSD 7.0. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)]

=== OpenBSD ===

OpenBSD/alpha is still supported, including SMP, in the current release, OpenBSD 7.9 (19 May 2026). [(>[[https://www.openbsd.org/79.html|OpenBSD 7.9]], The OpenBSD Project, 19 May 2026)] The installation media are ''install79.iso'' and ''cd79.iso'', and the procedure is described in the release's ''INSTALL.alpha''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/openbsd-alpha-mbox/2026-February.mbox#L1|"Re: SMP on AlphaServer DS20E"]], Miod Vallat, openbsd-alpha, 14 Feb 2026)] The supported systems are listed on the [[https://www.openbsd.org/alpha.html|OpenBSD/alpha]] page.

==== Windows NT ====

Windows NT ran on Alpha from version 3.1 [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-December.mbox#L1768|"Alpha Wiki"]], Marco Benton, axp-list, 18 Dec 2006)] and needs ARC or AlphaBIOS firmware. Digital Semiconductor's evaluation boards and OEM motherboards shipped with this firmware and supported Windows NT 3.51 and 4.0. [(>{{wiki:hardware:motherboards:common:windows_nt_installation_guide.pdf?linkonly|Alpha Microprocessors Motherboard Windows NT 3.51 and 4.0 Installation Guide}}, p. 28)]

Compaq ended Windows NT development for Alpha in August 1999. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L31035|"Re: Done: Experience with large IDE drive and Promise Ultra/66 card"]], Jeff Bolle, axp-list, 22 Aug 1999)] Windows NT 4.0 was the last released version; Windows 2000 for Alpha reached only prerelease builds, up to at least Release Candidate 1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-January.mbox#L2396|"w2k alpha"]], Steven Moix, axp-list, 9 Jan 2009)] The last Windows NT firmware was AlphaBIOS V5.71, for the AlphaServer DS10, AlphaStation XP900, and AlphaServer DS20 and DS20E. [(>{{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10)] On systems with both consoles, Linux is booted from SRM; see [[software:firmware|Firmware]]. ES40-Emu runs Windows NT and Windows 2000 for Alpha; see [[software:emulators|Emulators]].

==== OpenVMS ====

The first OpenVMS for Alpha was OpenVMS AXP. The DEC 2000 was added with OpenVMS AXP V1.5-1H1, a limited hardware release. [(>{{wiki:software:operating_systems:openvms_axp_1.5_vax_6.0_vmscluster_release_notes_addendum.pdf?linkonly|OpenVMS AXP Version 1.5 and OpenVMS VAX Version 6.0 Release Notes Addendum for VMScluster Systems}}, October 1993, p. 1-5)] Later systems required later versions.

From at least 1998, OpenVMS was licensed for non-commercial use through the OpenVMS Hobbyist program run with DECUS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-vms-mbox/googlegroups-1998-August.mbox#L306|"Re: HELP needed with an old DEC/MicroVAX II"]], Hoff Hoffman, comp.sys.vms, 31 Aug 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-vms-mbox/googlegroups-1998-April.mbox#L2260|"Re: Unix geek with a VAX"]], Hoff Hoffman, comp.sys.vms, 15 Apr 1998)]

In July 2014 HP named VMS Software Inc. (VSI) the exclusive developer of future versions of OpenVMS, and licensed it the source code. [(>[[https://www.infoworld.com/article/2608367/hp-gives-openvms-new-life.html|"HP gives OpenVMS new life"]], Computerworld, 31 Jul 2014)] VSI's releases for Alpha are OpenVMS V8.4-2L1 and V8.4-2L2; V8.4-2L2 is built for EV6 and later processors, so older systems need V8.4-2L1. [(>[[https://vmssoftware.com/products/versions/|Versions]], VMS Software Inc.)] VSI offers standard support for both through 2035. [(>[[https://products.vmssoftware.com/alpha|"Future Proof Your Alpha System"]], VMS Software Inc.)] OpenVMS does not run under QEMU, but several other emulators run it; see [[software:emulators|Emulators]].

==== Tru64 UNIX ====

Digital's UNIX for Alpha was called DEC OSF/1 until 1995, when it was renamed Digital UNIX, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1995-March.mbox#L2459|"Press/Digital To Rename DEC OSF/1 Operating Systems 'Digital UNIX'"]], Digital Press and Analysts News, biz.digital.announce, 15 Mar 1995)] and Compaq renamed it Tru64 UNIX in 1999. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1999-February.mbox#L27502|"News/announcement: Compaq Tru64 UNIX and new Web site.."]], Tom Blinn, alpha-osf-managers, 1 Feb 1999)] Its releases, hardware requirements, licensing, and end of support are described in [[software:operating_systems:tru64|Tru64 UNIX]].

==== Dual booting ====

Linux can share a machine with OpenVMS or Tru64 UNIX, since all of them boot from the SRM console. One arrangement is to install each system on its own disk, make Linux the default with ''bootdef_dev'', ''boot_file'', and ''boot_osflags'', and boot the other system by naming its disk, for example ''boot -file vmunix -flags a dka0'' for Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L2675|"Re: Dual boot a DS20.."]], 이준문, axp-list, 3 May 2000)] Adding a disk can change the names that Linux gives to the disks already present, so that the kernel no longer finds its root file system; [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-April.mbox#L26637|"RE: Dual boot a DS20.."]], Frank Tiels, axp-list, 27 Apr 2000)] referring to file systems by UUID or label rather than by device name avoids this. With an initramfs that supports it, such as Debian's, the root file system can be given as ''root=LABEL=''//name// in ''aboot.conf'', and ''/etc/fstab'' can use ''LABEL='' entries. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2008-January.mbox#L4010|"RE: Change the order of scsi Controller"]], Uwe Schindler, debian-alpha, 18 Jan 2008)] The kernel alone cannot do this on a BSD disklabel: without an initramfs, ''root='' accepts a partition UUID or label only from GPT or MS-DOS partition tables. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/block/early-lookup.c?h=v7.3-rc1|block/early-lookup.c]], Linux 7.3)]

NetBSD and OpenBSD also boot only from SRM (see [[#bsd|BSD]]), so they can share a machine with Linux in the same way, each on its own disk.

A disk labeled by Tru64 UNIX can also hold aboot. Its whole-disk ''c'' partition does no harm, but an installer may refuse to write the boot block because no space lies outside the partitions, and ''swriteboot -f'' then writes it by hand. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L8415|"Re: Bootstrap Failure after Installation of Red Hat Linux 7.0"]], Michal Jaegermann, axp-list, 9 Mar 2001)]

OpenVMS, Tru64 UNIX, and ARC each keep the time-of-year clock relative to a different epoch; see [[software:firmware:srm#known_issues|SRM Console: Known issues]].

=== Exchanging files ===

Linux reads the BSD-style disk label that Tru64 UNIX writes, through its OSF partition support (''CONFIG_OSF_PARTITION''), which is enabled by default on Alpha. Partition ''a'' of the label appears as partition 1, ''b'' as 2, and so on. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/block/partitions/Kconfig?h=v7.3-rc1|block/partitions/Kconfig]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/block/partitions/osf.c?h=v7.3-rc1|block/partitions/osf.c]], Linux 7.3)]

The kernel's ''ufs'' driver reads UFS file systems. It cannot detect which variant of UFS a file system is, so the variant is given with the ''ufstype'' mount option; the default is ''old'', and ''44bsd'' is the variant used by NetBSD and OpenBSD. Write support (''CONFIG_UFS_FS_WRITE'') is experimental. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/Documentation/admin-guide/ufs.rst?h=v7.3-rc1|Documentation/admin-guide/ufs.rst]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/fs/ufs/Kconfig?h=v7.3-rc1|fs/ufs/Kconfig]], Linux 7.3)] Digital UNIX UFS file systems have been mounted with ''ufstype=old'', [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-November.mbox#L3728|"Re: reading D-Unix filesystems in Linux"]], Alfredo Palace Carvalho, debian-alpha, 23 Nov 1999)] and NetBSD/alpha file systems with ''ufstype=44bsd'', read-only. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-1999-February.mbox#L18223|"Re: UFS and Linux"]], Joseph Sarkes, comp.os.linux.alpha, 3 Feb 1999)]

Linux has no driver for AdvFS, the other file system of Tru64 UNIX, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-November.mbox#L3127|"Re: reading D-Unix filesystems in Linux"]], Christopher Browne, debian-alpha, 22 Nov 1999)] or for the OpenVMS file systems ODS-2 and ODS-5. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/fs/Kconfig?h=v7.3-rc1|fs/Kconfig]], Linux 7.3)] HP released the AdvFS source code under the GPLv2 in June 2008, but not as a working Linux port. [(>[[https://lwn.net/Articles/287108/|"HP open-sources the Tru64 filesystem"]], LWN.net, 23 Jun 2008)] Archives made on Tru64 UNIX with ''tar'', ''pax'', or ''cpio'' can be read on Linux, but ''vdump'' archives cannot; see [[software:operating_systems:tru64#tru64_unix_and_linux|Tru64 UNIX]].

==== History ====

=== The first port ===

Linux on Alpha began at Digital, before any of the Alpha/Linux mailing lists existed, with a 32-bit kernel on the [[hardware:systems:jensen|Jensen]], followed by the Avanti. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-July.mbox#L572|"first Linux port"]], Jay Estabrook, axp-list, 13 Jul 2006)] The Jensen booted Linux from SRM, since no evaluation board PALcode was ever available for it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-December.mbox#L2127|"Re: booting from MILO and SRM: how is it possible?"]], Jay Estabrook, axp-list, 1 Dec 1997)] Jim Paradis of Digital's Alpha Migration Tools Group described the work in a "Linux/AXP Progress Report", dated 9 September 1994: a port of the Linux 1.0 kernel that kept every kernel data type to 32 bits except where the kernel met the hardware, so that code such as the file systems would work unmodified. It was cross-developed on a DEC 3000 running DEC OSF/1, with the kernel debugged under Digital's ISP simulator, and its drivers used the console callbacks. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-September.mbox#L14204|"Linux/AXP Progress Report"]], Jim Paradis, comp.os.linux.announce, 12 Sep 1994)]

By November 1994 the port, renamed Linux/Alpha in keeping with Digital's policy, ran from the hard disk. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-November.mbox#L36280|"Linux/Alpha Progress Report - Part 2"]], Jim Paradis, comp.os.linux.announce, 18 Nov 1994)] The Linux/Alpha Software Developers' Kit, the first public release of Linux components for Alpha, followed on 23 January 1995. It was cross-compiled from another host and had only console-callback drivers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-January.mbox#L2126|"ANNOUNCEMENT: Linux/Alpha Developers' Kit!"]], Jim Paradis, comp.os.linux.announce, 23 Jan 1995)]

BLADE 0.1 (Basic Linux/Alpha Distribution Eyesore), released on 1 July 1995, was the first Alpha/Linux distribution that could be installed without a second machine. It was a set of floppy images for the AXPpci 33 (Noname), built on a 1.2.8 kernel, and was 64-bit, the port having moved to 64 bits in the meantime. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-July.mbox#L10349|"Linux/Alpha installable kit now available!"]], Jim Paradis, comp.os.linux.announce, 1 Jul 1995)]

HP officially supported Red Hat Linux 7.2 for Alpha on the AlphaServer DS10, DS20, ES40, and ES45. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-June.mbox#L12427|"Re: RedHat 7.2 Linux for Alpha"]], Jay Estabrook, axp-list, 11 Jun 2002)] The DS25 and ES45 firmware release notes list Red Hat Linux 7.2 among the supported operating systems. ==== Conflicting information ====

The following sources conflict with each other or with the account given above. They are listed here for further investigation.

  * **OpenVMS on the EB164**
    * {{wiki:hardware:motherboards:eb164:21164_motherboard_user_manual.pdf?linkonly|Digital Semiconductor 21164 Alpha Microprocessor Motherboard User's Manual}}, p. 3-10: "The EB164 does not support the OpenVMS operating system."
    * {{wiki:hardware:motherboards:common:srm_console_user_guide.pdf?linkonly|Alpha SRM Console for Alpha Microprocessor Motherboards User's Guide}}, p. vii, describes its SRM console for boards "running the DIGITAL UNIX and OpenVMS operating systems", including the EB164.
  * **OpenVMS on the Multia**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L1226|"Re: digital unix libs"]], Jay Estabrook, axp-list, 1 Oct 1996: "VMS does NOT run on the UDB!"
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-June.mbox#L10065|"Re: Multia/UDB Comments"]], Mihaly HOMONNAI, axp-list, 20 Jun 1996: "it is possible to run OVMS on Multias."
  * **Tru64 UNIX on the UP2000**
    * {{wiki:hardware:motherboards:up1000:up1000_spec_sheet.pdf?linkonly|UP1000 Spec Sheet}}, January 2000, p. 2, lists "Tru64 UNIX" among the UP2000's supported operating systems.
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L43541|"RE: UP2000 and Tru64?"]], Mike Foley, axp-list, 23 Dec 1999: "The UP2000 is not a officially supported platform for running Tru64."
  * **Tru64 UNIX on the CS20**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L27001|"Re: DS20L"]], Rich Payne, axp-list, 30 May 2002: "Tru64 ran on the CS20 from day 1, though it wouldn't use the onboard SCSI controller."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L27072|"Re: DS20L"]], Maurice Hilarius, axp-list, 30 May 2002: the CS20 "could not run TRU64."
  * **Windows NT on the ES40**
    * ''FWREADME.TXT'' for the ES40 on the V7.3 firmware CD lists AlphaBIOS V5.71.
    * {{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10, lists no Windows NT firmware for the ES40.
  * **Windows NT on the XP900**
    * {{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10, lists AlphaBIOS V5.71 for the "DS10, AlphaStation XP900".
    * {{wiki:hardware:systems:alphastation_xp900:alphastation_xp900_catalog.pdf?linkonly|AlphaStation XP900}}, Systems and Options Catalog, September 1999: "available in a Desktop configuration with either Compaq's Tru64 UNIX, OpenVMS, or LINUX-ready (operating-system less)."
  * **Windows NT on the DS10**
    * {{wiki:hardware:systems:alphaserver_ds10:alphaserver_ds10_brochure.pdf?linkonly|Compaq AlphaServer DS10}}, June 1999, p. 6: "Operating Systems Tru64 UNIX 4.0F, OpenVMS 7.1-2, Windows NT, Linux"
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-February.mbox#L31980|"RE: UP2000"]], KirkE@paccessglobal.com, axp-list, 28 Feb 2001: "I don't think DS10/DS10L ever supported NT (at least publicly), I've never seen an AlphaBIOS for either of them."
  * **Last Tru64 UNIX release for older systems**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-September.mbox#L37862|"end of life for DEC branded Alphas (and Tru64)"]], William H.
