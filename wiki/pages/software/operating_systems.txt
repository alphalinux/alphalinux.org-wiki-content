===== Operating Systems =====

Digital supported three operating systems on Alpha: OpenVMS, DEC OSF/1 (renamed Digital UNIX and then Tru64 UNIX), and Microsoft Windows NT. Linux, FreeBSD, NetBSD, and OpenBSD were ported by others. Which of these a system can run depends mostly on its [[software:firmware|firmware]]:

^ Operating system ^ Firmware ^
| OpenVMS, Digital UNIX / Tru64 UNIX | [[software:firmware:srm|SRM console]] |
| Windows NT | [[software:firmware:arc|ARC or AlphaBIOS]] |
| Linux | SRM (with [[software:boot_loaders:aboot|aboot]]), or ARC, AlphaBIOS, or ARCSBIOS (with [[software:boot_loaders:milo|MILO]]) |
| FreeBSD, NetBSD, OpenBSD | SRM |

"All motherboard systems that run the DIGITAL UNIX or OpenVMS operating system require the Alpha SRM Console." [(>{{wiki:hardware:motherboards:common:srm_console_user_guide.pdf?linkonly|Alpha SRM Console for Alpha Microprocessor Motherboards User's Guide}}, p. 1-2)] Systems designed only for Windows NT, such as the Alpha XL, have no SRM console, and so cannot run OpenVMS or Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L25578|"Re: Does DEC have a clue?"]], Jay Estabrook, axp-list, 20 Jan 1998)] The SRM console for evaluation boards and OEM motherboards was licensed separately (see [[software:firmware:srm#licensing|SRM licensing]]).

==== Windows NT ====

Windows NT ran on Alpha from version 3.1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-December.mbox#L1768|"Alpha Wiki"]], Marco Benton, axp-list, 18 Dec 2006)] The DECpc AXP 150 was bundled with Windows NT, and the otherwise identical DEC 2000 AXP with OpenVMS or DEC OSF/1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)] Digital's workstations were sold in Windows NT and UNIX/OpenVMS versions, e.g. the Personal Workstation "a" series with Windows NT 4.0 and "au" series with Tru64 UNIX or OpenVMS. [(>{{wiki:hardware:systems:personal_workstation:personal_workstation_a_au_series_catalog.pdf?linkonly|Compaq DPW Enhanced a-Series & au-Series}}, Systems and Options Catalog, September 2000)] Digital Semiconductor's evaluation boards and OEM motherboards shipped with Windows NT firmware, and supported Windows NT 3.51 and 4.0. [(>{{wiki:hardware:motherboards:common:windows_nt_installation_guide.pdf?linkonly|Alpha Microprocessors Motherboard Windows NT 3.51 and 4.0 Installation Guide}}, p. 28)]

In August 1999, Compaq laid off the more than 100 people who ported Windows NT to Alpha. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L31035|"Re: Done: Experience with large IDE drive and Promise Ultra/66 card"]], Jeff Bolle, axp-list, 22 Aug 1999)] According to Phillip Ezolt of Compaq, Compaq stopped supporting 32-bit Windows NT, and within a week Microsoft dropped the 64-bit version. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L54447|"Re: Off topic: NT on Alpha (was: Alpha Users in the Toronto area.)"]], Phillip Ezolt, axp-list, 30 Sep 1999)] Windows NT 4.0 was the last released version. Prerelease builds of Windows 2000 for Alpha were distributed, up to at least Release Candidate 1 (build 2072), which expired 444 days after installation. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-January.mbox#L2396|"w2k alpha"]], Steven Moix, axp-list, 9 Jan 2009)] The last Windows NT firmware was AlphaBIOS V5.71, for the AlphaServer DS10, AlphaStation XP900, and AlphaServer DS20 and DS20E. [(>{{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10)]

==== Tru64 UNIX ====

Early versions were called DEC OSF/1. [(>{{wiki:hardware:systems:alphaserver_1000:alphaserver_1000_owners_guide.pdf?linkonly|AlphaServer 1000 Owner's Guide}}, p. 3-1)] Digital's product was based on the Open Software Foundation's OSF/1 Release 1.0.4, with the virtual memory system heavily modified. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1993-April.mbox#L2838|"Re: wither OSF? (was Re: alpha OSF/1 1.2)"]], Tom Jordahl, comp.unix.osf.osf1, 14 Apr 1993)] It soon diverged: when OSF announced in 1994 that its June 1994 release of OSF/1 would be its last, Digital's position was that "Since the initial releases, development of Digital's product has not been dependent on OSF code." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1995-August.mbox#L8638|"DEC OSF/1 AXP Frequently Asked Questions"]], Steve Lionel, comp.unix.osf.osf1, 21 Aug 1995)] V1.0 ran on MIPS DECstations, and V1.2 was the version that shipped on Alpha, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1992-November.mbox#L514|"Re: Is DEC OSF stable?"]], Stephen Carpenter, comp.unix.osf.misc, 24 Nov 1992)] but the DECstation version, meant to replace ULTRIX, "was cancelled before any official releases". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-2000-March.mbox#L2139|"RESULT: comp.unix.tru64 rename and removal of comp.unix.osf.misc pass"]], Neil Crellin, comp.unix.osf.misc, 21 Mar 2000)]

The rename to Digital UNIX came on 14 March 1995, when Digital received an X/Open license to use the UNIX trademark and the UNIX Brand for the release then current, which became Digital UNIX Version 3.2: "Our branded UNIX system is the same high-quality software, but now we can call it UNIX. [...] With the branding program in place, changing the name of DEC OSF/1 to Digital UNIX is the logical step." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1995-March.mbox#L2459|"Press/Digital To Rename DEC OSF/1 Operating Systems 'Digital UNIX'"]], Digital Press and Analysts News, biz.digital.announce, 15 Mar 1995)] Compaq announced the rename of Digital UNIX to Tru64 UNIX on 1 February 1999, together with V4.0F, the AlphaServer DS20, and the XP1000. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1999-February.mbox#L27502|"News/announcement: Compaq Tru64 UNIX and new Web site.."]], Tom Blinn, alpha-osf-managers, 1 Feb 1999)] [(>''Tru64 UNIX Operating System, Version 4.0F'', SPD 41.61.22, Compaq, April 1999)] The Tru64 UNIX V4.0F Software Product Description lists these supported systems: [(>''Tru64 UNIX Operating System, Version 4.0F'', SPD 41.61.22, Compaq, April 1999, Hardware Support Tables)]

  * DEC 2000, DEC 3000, DEC 4000, and DEC 7000
  * AlphaServer 300, 400, 800, 1000, 1000A, 1200, 2000, 2100, 2100A, 4000, 4100, 8200, 8400, DS20, ES40, GS60, and GS140
  * AlphaStation 200, 250, 255, 400, 500, 600, and 600A, the Personal Workstation au series, and the Professional Workstation XP1000
  * the [[hardware:motherboards:axppci33|AXPpci 33]], [[hardware:motherboards:alpha_vme|AXPvme and Alpha VME]] boards, and the single board computers EB66+, EB164, AlphaPC 64, AlphaPC 164, AlphaPC 164LX, and AlphaPC 164SX

The list omits some systems that V4.0F did support, such as the AlphaServer DS10, [(>{{wiki:software:firmware:alphaserver_ds10_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer DS10 V7.3 Console Firmware Release Notes}})] so the absence of a system from it does not show that the system was unsupported.

=== End of support for older systems ===

In 2000 Tom Blinn announced that "V5.1 is the last release that will support the older "DEC" branded Alpha systems (the ones that do NOT have PCI buses for I/O -- the DEC 2000, DEC 3000, DEC 4000, DEC 7000/10000)", and recommended V4.0G to their owners, since it was "planned to have a long service life". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2000-September.mbox#L10241|"Tru64 UNIX V5.1 and TruCluster software"]], Tom Blinn, tru64-unix-managers, 20 Sep 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-September.mbox#L37862|"end of life for DEC branded Alphas (and Tru64)"]], William H. Magill, axp-list, 20 Sep 2000)] In the event, the TURBOchannel systems lost support one release earlier. By 2002 Blinn wrote that "the support for the very old TURBOchannel type systems has been dropped in V5.1 and later", [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-May.mbox#L46415|"Summary: Firmware revision and tru64 version lifelimit on Alpha 1 000A 5/400 and Alpha 800"]], Mike Kirkland, tru64-unix-managers, 30 May 2002)] and a 2003 summary concluded that V5.0A was the last release supported on the DEC 3000, V5.1 ran on it without support, and V5.1A would not run at all because "All turbochannel code was removed". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2003-January.mbox#L30858|"SUMMARY: DEC3000 300s and DEC 3000 400s with Tru64 v5"]], Robert Bannocks, tru64-unix-managers, 30 Jan 2003)] The AlphaServer 8200 and 8400 remained supported after V5.1, but without their XMI bus. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-September.mbox#L39979|"Re: end of life for DEC branded Alphas (and Tru64)"]], Peter Rival, axp-list, 22 Sep 2000)] The EV7 systems require V5.1B. [(>{{wiki:hardware:systems:alphaserver_es47:alphaserver_es47_tower_quickspecs.pdf?linkonly|HP AlphaServer ES47 Tower QuickSpecs}}, November 2003, p. 2)]

Minimum versions on the OEM motherboards were Digital UNIX 4.0 for the AlphaPC 164, [(>{{wiki:hardware:motherboards:pc164:pc164_digital_unix_product_brief.pdf?linkonly|AlphaPC 164 DIGITAL UNIX Product Brief}}, p. 2)] 4.0D for the AlphaPC 164SX and 164LX, [(>{{wiki:hardware:motherboards:pc164sx:pc164sx_digital_unix_user_manual.pdf?linkonly|AlphaPC 164SX DIGITAL UNIX User's Manual}}, p. 7-29)] [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_tru64_unix_user_manual.pdf?linkonly|AlphaPC 164LX Tru64 UNIX User's Manual}}, p. 7-29)] and Tru64 UNIX 4.0E for the AlphaPC 264DP. [(>{{wiki:hardware:motherboards:pc264dp:pc264dp_user_manual.pdf?linkonly|AlphaPC 264DP User's Manual}}, p. 8-44)] The PC164 was sold in a Windows NT and Linux version and a Digital UNIX version that included a license. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L32037|"Re: Alpha-Boards"]], Stephen J. Gaudet, axp-list, 21 Oct 1996)] For the EB164 the license was QL-MT4AG-6K, and the SRM console carried a separate price. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1996-February.mbox#L13392|"SUMMARY: EB164s and Digital Unix"]], Martyn Johnson, alpha-osf-managers, 9 Feb 1996)]

=== Development tools and licensing ===

The base license included a C compiler, but only "to rebuild and configure the kernel"; general development needed the separate Developers' Extensions (later Developers' Toolkit) license. The only enforcement was a license check in the ''dbx'' and DECladebug debuggers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1995-June.mbox#L1053|"Re: Really quick question on OSF1 ?"]], Jon Reeves, comp.unix.osf.misc, 19 Jun 1995)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-September.mbox#L25101|"Re: Any compiler in the OSF/1"]], Steve Lionel, comp.unix.osf.osf1, 1 Sep 1994)] The compilers themselves are described in [[documentation:toolchains#dec_c_on_dec_osf_1|Toolchains]]. Each release shipped with the "Alpha AXP Freeware CD" of ported free software, which could also be ordered from DECdirect as QA-0PSAA-H8 for US$12. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-December.mbox#L6409|"DEC OSF/1 AXP Frequently Asked Questions"]], Steve Lionel, comp.unix.osf.osf1, 16 Dec 1994)] Universities could buy the source code: in 1998 the Education Source License (QB-MT4BA-E8) listed at US$1,236, plus prerequisite licenses from The Open Group costing "a few thousand dollars more", because the system "includes sources derived from both System V and OSF". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1998-June.mbox#L1341|"Re: DIGITAL UNIX SOURCE CODE"]], Jeffrey Mogul, comp.unix.osf.misc, 30 Jun 1998)]

Digital also let anyone try the system over the Internet. From 14 April 1993 two DEC 4000 systems, ''axposf.pa.dec.com'' running DEC OSF/1 V1.2 and ''axpvms.pa.dec.com'' running OpenVMS, accepted guest registrations from anyone logging in as ''axpguest''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1993-April.mbox#L2734|"Demo Alpha Machines on the Internet"]], Gail L. Grant, comp.unix.osf.osf1, 14 Apr 1993)]

The kernel configuration option for AdvFS is ''MSFS'', for MegaSafe, AdvFS's name during development. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-July.mbox#L1910|"Re: What is MSFS?"]], Steve Strange, comp.unix.osf.osf1, 28 Jul 1994)] In May 1997 Digital had over 600 staff working on Digital UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1997-May.mbox#L24457|"Digital and its support of Linux"]], Jon 'maddog' Hall, alpha-osf-managers, 5 May 1997)]

=== Under HP ===

After the HP and Compaq merger, HP's roadmap of 7 May 2002 made HP-UX its UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-May.mbox#L9640|"HPs roadmap for HPQ..."]], Arrigo Triulzi, tru64-unix-managers, 8 May 2002)] The plan was to carry the best of Tru64 over. A June 2002 HP survey of customers running both systems found that AdvFS (77%) and TruCluster (63%) were the Tru64 features they liked best, which "verified our initial plans for the merged Tru64UNIX and HP-UX, namely to add TruCluster and AdvFS to HP-UX". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-June.mbox#L27456|"SUMMARY: HP Survey. If you use both Tru64UNIX and HP-UX, what do you like about them?"]], Paul Henderson, tru64-unix-managers, 24 Jun 2002)] By November 2002 the TruCluster engineers "are off working on porting TruCluster functionality to HP-UX". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-November.mbox#L16953|"SUMMARY: handle advfs filesets with autofs ?"]], Udo Grabowski, tru64-unix-managers, 15 Nov 2002)] Tom Blinn summed up HP's public commitment in December 2002: "to continue to manufacture and market Alpha hardware systems that run Tru64 UNIX through at least 2006 or there abouts, and to continue to support Tru64 UNIX on Alpha systems into 2011 or there abouts", but "we are not going to port Tru64 UNIX / TruCluster in its current form to Itanium." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-December.mbox#L17609|"Summary: Some questions regarding Alpha and Itanium"]], Robert Honore, tru64-unix-managers, 19 Dec 2002)] V5.1B was to be supported "until at least 2011". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2005-January.mbox#L2619|"SUMMARY: probleme booting a cluster member"]], Malek Shabou, tru64-unix-managers, 13 Jan 2005)]

HP abandoned the port to HP-UX in December 2004. List members passed around The Register's report under the subject "OT but related IT appears HP has lied to us all", [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2004-December.mbox#L686|"OT but related IT appears HP has lied to us all"]], Greg Rudd, tru64-unix-managers, 3 Dec 2004)] and the replies included the first call on the list to open source AdvFS: "maybe this is a good time to donate the AdvFS code to the opensource community?" [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2004-December.mbox#L767|"OT but related IT appears HP has lied to us all"]], Dennis Voetelink, tru64-unix-managers, 3 Dec 2004)]

HP never ported ''vrestore'' to Linux, so data kept in ''vdump'' archives has to be restored on a Tru64 system; Blinn advised writing archives meant for Linux with ''tar'', ''pax'', or ''cpio''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2007-January.mbox#L2157|"SUMMARY: vrestore on linux"]], Emanuele Lombardi, tru64-unix-managers, 23 Jan 2007)]

==== Linux ====

=== The first port ===

Linux on Alpha began at Digital, before any of the Alpha Linux mailing lists existed. Jim Paradis of Digital's Alpha Migration Tools Group published a "Linux/AXP Progress Report", dated 9 September 1994, to ''comp.os.linux.announce''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-September.mbox#L14204|"Linux/AXP Progress Report"]], Jim Paradis, comp.os.linux.announce, 12 Sep 1994)] It describes a port of the Linux 1.0 kernel that was deliberately 32-bit:

<blockquote>
Linux/AXP is a 32-bit operating system. Except for those cases where the kernel must interface with the Alpha AXP hardware, no kernel data type is wider than 32 bits. [...] The decision to remain with 32-bit data types was based on our group's experience with migrating legacy software to a 64-bit environment. By not changing the size of any data types, those parts of Linux that are unaffected by the port (such as the file system code) should continue to work without modification.
</blockquote>

It was aimed at "PC-class Alpha AXP platforms that support ISA, EISA, VLB, and PCI devices", and cross-developed on a DEC 3000 Model 500 running DEC OSF/1, with ''gcc'' 2.5.8 configured for ''alpha-linux'' and a ''gdb'' patched to debug the kernel running under the [[software:emulators#isp|ISP]] simulator. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-September.mbox#L14204|"Linux/AXP Progress Report"]], Jim Paradis, comp.os.linux.announce, 12 Sep 1994)] At that point the kernel booted from a 1.44 MB ext2 floppy image into a RAM disk, had no disk drivers, and ran a hand-written "hello, world" in place of ''/etc/init'', because there was no ''libc'' yet. Its drivers used console callbacks, which Paradis described as "the Alpha AXP equivalents of BIOS calls on an Intel system", slow because they run synchronously with interrupts disabled. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-September.mbox#L14204|"Linux/AXP Progress Report"]], Jim Paradis, comp.os.linux.announce, 12 Sep 1994)]

A month later the port reached a shell prompt, with "only a VERY slow, primitive hard-disk driver" and still running essentially from the RAM disk. Paradis also put down a rumor that it had gone 64-bit: "My port is 32 bits, and will be for the forseeable future." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-1994-October.mbox#L18982|"Re: LINUX AXP?"]], Jim Paradis, comp.sys.dec, 12 Oct 1994)]

The November 1994 report records the milestones and the rename: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-November.mbox#L36280|"Linux/Alpha Progress Report - Part 2"]], Jim Paradis, comp.os.linux.announce, 18 Nov 1994)]

<blockquote>
  * Linux/Alpha now boots to shell prompt.
  * Linux/Alpha is no longer called Linux/AXP (in keeping with current company policy).
  * New addresses for email contact.
  * Linux/Alpha now runs off the hard disk -- no RAMdisk needed.
</blockquote>

The first shell was ''rc'', the Plan 9 shell, chosen because it "was the first freeware shell I found that compiled cleanly on my somewhat cantankerous cross-development environment", with ''init'' a stub that ran it, and about twenty coreutils ported alongside. A console-callback disk driver replaced the RAM disk, so the root filesystem was no longer limited to a floppy image. Booting from floppy was not an option: the console firmware in use "only recognizes SCSI devices and does not understand disk partitioning", so the kernel had to be written to a SCSI disk from another system. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-November.mbox#L36280|"Linux/Alpha Progress Report - Part 2"]], Jim Paradis, comp.os.linux.announce, 18 Nov 1994)] Paradis also announced the project's mailing list, ''linux-axp@amt.tay1.dec.com'', [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-November.mbox#L36280|"Linux/Alpha Progress Report - Part 2"]], Jim Paradis, comp.os.linux.announce, 18 Nov 1994)] which moved to majordomo as ''alpha-linux'' two months later. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-January.mbox#L2126|"ANNOUNCEMENT: Linux/Alpha Developers' Kit!"]], Jim Paradis, comp.os.linux.announce, 23 Jan 1995)]

The Linux/Alpha Software Developers' Kit followed on 23 January 1995, from ''gatekeeper.dec.com'', as "the first public release of Linux operating system components for Digital's Alpha family of microprocessors". It was frank about its state: not self-hosting, cross-compiled from a Linux, DEC OSF/1, ULTRIX or SunOS host, with console-callback drivers only and, for the [[hardware:systems:jensen|Jensen]], exactly three of them: keyboard, text-mode VGA, and Adaptec 1742 SCSI. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-January.mbox#L2126|"ANNOUNCEMENT: Linux/Alpha Developers' Kit!"]], Jim Paradis, comp.os.linux.announce, 23 Jan 1995)]

<blockquote>
In other words, Linux/Alpha is currently in a state that only a kernel hacker could love.
</blockquote>

On 1 July 1995 came BLADE 0.1, "Basic Linux/Alpha Distribution Eyesore", the first Linux/Alpha anyone could install without a second machine: a set of floppy images needing only an SRM console, built on a 1.2.8 kernel carrying "the Linus' Alpha patches", supporting the AXPpci 33 (NoName), and published under a ''1.2-64bit'' directory, the port having gone 64-bit in the meantime. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-July.mbox#L10349|"Linux/Alpha installable kit now available!"]], Jim Paradis, comp.os.linux.announce, 1 Jul 1995)] It was explicitly a stopgap "until such time as the more professional distributions (Slackware, Debian, Red Hat, etc) have been ported to Linux/Alpha". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-July.mbox#L10349|"Linux/Alpha installable kit now available!"]], Jim Paradis, comp.os.linux.announce, 1 Jul 1995)]

The machine the original 32-bit port ran on was the [[hardware:systems:jensen|Jensen]]: Jay Estabrook later recalled the first Linux port as "a 32-bit kernel on a JENSEN, followed by AVANTI (as400)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-July.mbox#L572|"first Linux port"]], Jay Estabrook, axp-list, 13 Jul 2006)]

Linux runs on most Alpha systems, booting from SRM with aboot or from ARC, AlphaBIOS, or ARCSBIOS with MILO. Systems without SRM, such as the Alpha XL and XLT and the Ruffian, can only boot Linux with MILO. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L5923|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] See [[software:boot_loaders|Boot Loaders]].

Linux 6.10 removed support for processors without the BWX extension (the EV4, EV45, and EV5 generations) and for the systems that can only use them. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] The removed systems are:

  * the Jensen (DEC 2000 AXP and DECpc AXP 150), [(>[[https://git.kernel.org/torvalds/c/f81f335a56a8|"alpha: remove DECpc AXP150 (Jensen) support"]], Linux 6.10)]
  * all systems with the LCA processors or the APECS chipset: the AlphaStation 200, 250, 255, and 400 and AlphaServer 300 and 400 (Avanti), the Alpha XL, the Multia and AXPpci 33 (Noname), the AlphaBook 1, the Platform 2000, the EB64+, EB66, EB66+, and AlphaPC 64, and the EV4 versions of the AlphaServer 1000 and 1000A, [(>[[https://git.kernel.org/torvalds/c/430ad3f0ddd7|"alpha: remove LCA and APECS based machines"]], Linux 6.10)]
  * the EV4 and EV45 versions of the AlphaServer 2000 and 2100, and the AlphaServer 2100A (Lynx), [(>[[https://git.kernel.org/torvalds/c/d2b1e353dacc|"alpha: sable: remove early machine support"]], Linux 6.10)]
  * the EB164, which only supports EV5 processors. [(>[[https://git.kernel.org/torvalds/c/4bf859076b16|"alpha: cabriolet: remove EV5 CPU support"]], Linux 6.10)]

Systems with EV5 processors that also support EV56 processors, such as the AlphaStation 500 and 600 and Personal Workstation, are still supported, but need an EV56 processor. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)]

The kernel does not support the DEC 3000, DEC 4000, DEC 7000, or the AlphaServer 8200, 8400, GS60, and GS140 (TurboLaser): it has no machine vector for them, before or after Linux 6.10. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.10|arch/alpha/kernel/setup.c]], Linux 6.10)]

Hewlett-Packard's Red Hat Linux 7.2 for Alpha was officially supported on the AlphaServer DS10, DS20, ES40, and ES45. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-June.mbox#L12427|"Re: RedHat 7.2 Linux for Alpha"]], Jay Estabrook, axp-list, 11 Jun 2002)] The DS25 and ES45 firmware release notes list Red Hat Linux 7.2 among the supported operating systems. [(>{{wiki:software:firmware:alphaserver_ds25_v7.2_firmware_release_notes.pdf?linkonly|AlphaServer and AlphaStation DS25 V7.2 Firmware Release Notes}})] [(>{{wiki:software:firmware:alphaserver_es45_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer and AlphaStation ES45 V7.3 Firmware Release Notes}}, p. 6)] Installing it on the ES47, ES80, and AlphaServer 2100A required an HP installation wrapper CD. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-July.mbox#L2911|"Installation HPWrapper ISO for ES47, ES80, 2100A and DAC960 systems for RH-7.2."]], George France, axp-list, 11 Jul 2003)]

The DS15, DS25, and ES45 (Titan), the GS80, GS160, and GS320 (Wildfire), and the ES47, ES80, and GS1280 (Marvel) need kernels built without ''CONFIG_ALPHA_LEGACY_START_ADDRESS''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2006-February.mbox#L7443|"Re: testing wanted: debian-installer, now with 2.6.15"]], Jay Estabrook, debian-alpha, 9 Feb 2006)] Debian 3.1's prepackaged kernels did not support the Titan systems for this reason. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1252|"Sanity checking needed of Alpha subarch codenames in d-i manual"]], Steve Langasek, debian-alpha, 7 Nov 2004)] Linux support for the Marvel systems returned "after a long hiatus" in Alpha Core 3 in 2007. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2007-March.mbox#L1087|"Torrents galore...but has anyone actually tried it?"]], Jay Estabrook, axp-list, 7 Mar 2007)]

==== BSD ====

All three BSDs boot only from the [[software:firmware:srm|SRM console]], because they use the OSF/1 PALcode and cannot use the PALcode that ARC and AlphaBIOS provide. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1998-October.mbox#L4692|"PALcode"]], David Seifert, freebsd-alpha, 9 Oct 1998)] There is no BSD equivalent of MILO: asked in 1999 how to boot FreeBSD on an Alpha XL, which has no SRM, Andrew Gallatin answered that SRM was the only option, and that work on booting FreeBSD from AlphaBIOS had stalled for lack of documentation. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1999-April.mbox#L3081|"Re: MILO for fbsd?"]], Andrew Gallatin, freebsd-alpha, 8 Apr 1999)]

=== NetBSD ===

NetBSD/alpha was started by Chris Demetriou and is the oldest of the three. Snapshots of the 1.2 development line were circulating by June 1996, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/1996-June.mbox#L1468|"Another NetBSD/Alpha 1.2_ALPHA snapshot (960615) available!"]], Chris G Demetriou, port-alpha, 16 Jun 1996)] and users were running the 1.2 release by October 1996. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/1996-October.mbox#L134|"alpha 1.2 release"]], Michael Graff, port-alpha, 7 Oct 1996)] That release was statically linked ECOFF; ELF and shared libraries were still being finished at the end of 1996, blocked on identifying NetBSD/alpha ELF binaries, on weak references in ''libc'', and on integrating the shared linker. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/1996-October.mbox#L149|"Re: alpha 1.2 release"]], Chris G Demetriou, port-alpha, 8 Oct 1996)]

The port is still maintained: ''port-alpha@netbsd.org'' carries traffic to the present day.

=== FreeBSD ===

FreeBSD/alpha was Doug Rabson's work and was the first non-x86 port added to FreeBSD, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)] which is why its history is bound up with the project's 64-bit and machine-independence cleanups. The Release Engineering Team said so when it demoted the port to Tier 2 in June 2004: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2004-June.mbox#L2662|"Demotion of alpha to Tier 2"]], Scott Long, freebsd-alpha, 14 Jun 2004)]

<blockquote>
Alpha was a very important platform for FreeBSD. It paved the way both for 64-bit cleanliness and for being able to support multiple architectures. [...] Thanks to Doug Rabson for porting to it in the first place and thanks to everyone who supported it afterwards.
</blockquote>

Tier 2 meant no guaranteed release images, no prebuilt packages and no guaranteed security advisories from FreeBSD 5.3 onward, though 4.x releases and errata kept their support. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2004-June.mbox#L2662|"Demotion of alpha to Tier 2"]], Scott Long, freebsd-alpha, 14 Jun 2004)] The port was retired outright two years later, announced by John Baldwin in May 2006: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)]

<blockquote>
After considering all of this, it is time to part with Alpha for 7.0 and beyond. At this time it is still planned to provide 6.x releases for FreeBSD/alpha. [...] Users with Alpha systems are welcome to use existing releases of FreeBSD/alpha or another BSD such as NetBSD/alpha.
</blockquote>

FreeBSD 6.x was therefore the last series to support Alpha. The ''freebsd-alpha'' list ran on until the end of 2010.

=== OpenBSD ===

OpenBSD 2.2, announced on 14 December 1997, included an Alpha binary release. It supported the DEC 3000, the AlphaStation 200, 250, 255, 400, and 500, the AXPpci 33, and the Multia, from SRM only, with "weak binary compatibility with OSF/1 binaries". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1997-December.mbox#L2919|"OpenBSD 2.2 released for the alpha"]], Theo de Raadt, comp.unix.osf.misc, 14 Dec 1997)]

OpenBSD/alpha is still supported, and has SMP support. Miod Vallat, February 2026, on a dual-processor AlphaServer DS20E: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/openbsd-alpha-mbox/2026-February.mbox#L1|"Re: SMP on AlphaServer DS20E"]], Miod Vallat, openbsd-alpha, 14 Feb 2026)]

<blockquote>
Yes, OpenBSD/alpha has SMP support and will use the two processors of the DS20.
</blockquote>

==== Systems without support for every operating system ====

=== No OpenVMS or Tru64 UNIX ===

  * **Alpha XL and XLT:** these have no SRM console. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L25578|"Re: Does DEC have a clue?"]], Jay Estabrook, axp-list, 20 Jan 1998)] "OpenVMS will not run on an XL266. It would need an SRM console, and there isn't one for that model workstation." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-November.mbox#L791|"OpenVMS for Alpha"]], Jeff Donsbach, axp-list, 15 Nov 2004)]
  * **Digital Server 3300, 5300, and 7300:** these Windows NT servers "can switch the 33,53,73 to srm console, but they will still not boot unix or vms." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L13782|"RE: Compaq to offer Tru64 for $99"]], John Jemiolo, axp-list, 5 Nov 1999)] The restriction appears to come from the system ID in the serial ROM, and Linux is not affected: Red Hat Linux 6.0 ran on the 3300. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1999-November.mbox#L12890|"SUMMARY: AS 3300 support for Tru64UNIX/Linux?"]], Stephen Dowdy, tru64-unix-managers, 10 Nov 1999)]
  * **AlphaPC 164RX:** no SRM console was released for it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L9150|"Re: switching from ARC back to SRM"]], Jay Estabrook, axp-list, 16 Aug 2000)] It was only sold for Windows NT. [(>{{wiki:hardware:motherboards:pc164rx:pc164rx_product_brief.pdf?linkonly|AlphaPC 164RX Product Brief}}, p. 2)]
  * **AlphaPC 164UX and 164BX (Ruffian):** the only firmware is DeskStation's ARCSBIOS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L29483|"Re: AlphaBios vs SRM"]], Rich Payne, axp-list, 15 Sep 1999)]
  * **Multia:** Jay Estabrook wrote in 1996, "VMS does NOT run on the UDB!" [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L1226|"Re: digital unix libs"]], Jay Estabrook, axp-list, 1 Oct 1996)] and "Digital UNIX is not sold for the UDB." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-April.mbox#L47743|"Re: UDB OS questions, looking for OSF/1 media"]], Maurice W. Hilarius, axp-list, 27 Apr 1997)] Later, Tru64 UNIX ran under a hobbyist license, and OpenVMS with special firmware, but "Neither Tru64 nor VMS is officially supported on the box". OpenVMS does not support its serial ports. Digital UNIX nevertheless ran on it from early on: a 24 MB Multia installed from CD in 1996 "all worked nicely (but very slowly)", [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1996-May.mbox#L1837|"Re: ?DEC MULTIA (VX42B-F2) and OSF UNIX"]], Huw Davies, comp.unix.osf.misc, 28 May 1996)] and in 1998 a Compaq UNIX system administrator installed V3.2G and V4.0D on one after updating its SRM firmware. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1998-November.mbox#L808|"Re: Digital Unix 4.0D on a Multia ?"]], Matthew P Cheek, comp.unix.osf.misc, 22 Nov 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L36|"Re: Multia/166MHz"]], Dan O'Reilly, axp-list, 1 Jan 2000)]
  * **UP1000:** Mike Foley of API: "Tru64 knows nothing about the Irongate chipset, nor is it a licensed platform." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-February.mbox#L18082|"RE: UP1000 & SRM"]], Mike Foley, axp-list, 16 Feb 2000)] API's manuals for the UP1000, UP1100, and UP1500 only mention Linux. [(>{{wiki:hardware:motherboards:up1000:up1000_technical_reference_manual.pdf?linkonly|UP1000 Technical Reference Manual}})] [(>{{wiki:hardware:motherboards:up1100:up1100_technical_reference_manual.pdf?linkonly|UP1100 Technical Reference Manual}})] [(>{{wiki:hardware:motherboards:up1500:up1500_user_s_manual.pdf?linkonly|UP1500 User's Manual}}, p. 4-2)]
  * **UP2000:** "The UP2000 is not a officially supported platform for running Tru64." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L43541|"RE: UP2000 and Tru64?"]], Mike Foley, axp-list, 23 Dec 1999)] Tru64 UNIX 4.0F has nevertheless been run on it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-October.mbox#L16386|"Re: Consigned to Oblivion, Alpha and Firmware"]], Maurice Hilarius, axp-list, 11 Oct 1999)] It does not run OpenVMS.   * **CS20 and DS20L:** API NetWorks sold the CS20 for Linux; its onboard SCSI controller was not supported by Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L27576|"RE: DS20L"]], Peter Petrakis, axp-list, 30 May 2002)] Compaq's version, the DS20L, lists only Tru64 UNIX V5.1A in its firmware release notes.
