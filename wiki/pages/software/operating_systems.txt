===== Operating Systems =====

Digital supported three operating systems on Alpha: OpenVMS, DEC OSF/1 (renamed Digital UNIX and then Tru64 UNIX), and Microsoft Windows NT. Linux, FreeBSD, NetBSD, and OpenBSD were ported later; the first Linux port was done by a group inside Digital (see [[#the_first_port|The first port]]).

^ Operating system ^ Current status ^
| Linux | Maintained in the mainline kernel; since Linux 6.10 an EV56 (21164A) or later processor is required (see [[#linux|Linux]]) [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] |
| NetBSD | Maintained; supported in NetBSD 11.0 (July 2026) [(>[[https://www.netbsd.org/releases/formal-11/NetBSD-11.0.html|NetBSD 11.0 release notes]], The NetBSD Project, 30 Jul 2026)] |
| OpenBSD | Maintained; supported in OpenBSD 7.9 (May 2026) [(>[[https://www.openbsd.org/79.html|OpenBSD 7.9]], The OpenBSD Project, 19 May 2026)] |
| FreeBSD | Removed in FreeBSD 7.0; 6.x was the last series [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)] |
| OpenVMS | VSI releases V8.4-2L1 and V8.4-2L2, with standard support through 2035 [(>[[https://products.vmssoftware.com/alpha|"Future Proof Your Alpha System"]], VMS Software Inc.)] |
| Tru64 UNIX | HP's engineering support ended at the end of 2012, followed by Mature Product Support without further releases [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-tru64-mbox/googlegroups-2011-April.mbox#L1264|"Re: Tru64 licenses"]], Martin, comp.unix.tru64, 23 Apr 2011)] |
| Windows NT | Windows NT 4.0 was the last release; Alpha development ended in 1999 (see [[#windows_nt|Windows NT]]) |

Which of these a system can run depends mostly on its [[software:firmware|firmware]]:

^ Operating system ^ Firmware ^
| OpenVMS, Tru64 UNIX | [[software:firmware:srm|SRM console]] |
| Windows NT | [[software:firmware:arc|ARC or AlphaBIOS]] |
| Linux | SRM (with [[software:boot_loaders:aboot|aboot]]), or ARC, AlphaBIOS, or ARCSBIOS (with [[software:boot_loaders:milo|MILO]]) |
| FreeBSD, NetBSD, OpenBSD | SRM |

OpenVMS and Tru64 UNIX boot only from the SRM console. [(>{{wiki:hardware:motherboards:common:srm_console_user_guide.pdf?linkonly|Alpha SRM Console for Alpha Microprocessor Motherboards User's Guide}}, p. 1-2)] Systems designed only for Windows NT, such as the Alpha XL, have no SRM console, and so cannot run OpenVMS or Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L25578|"Re: Does DEC have a clue?"]], Jay Estabrook, axp-list, 20 Jan 1998)] The SRM console for evaluation boards and OEM motherboards was licensed separately (see [[software:firmware:srm#licensing|SRM licensing]]).

==== Systems without support for every operating system ====

=== No OpenVMS or Tru64 UNIX ===

  * **Alpha XL and XLT:** these have no SRM console, which OpenVMS and Tru64 UNIX require. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L25578|"Re: Does DEC have a clue?"]], Jay Estabrook, axp-list, 20 Jan 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-November.mbox#L791|"OpenVMS for Alpha"]], Jeff Donsbach, axp-list, 15 Nov 2004)]
  * **Digital Server 3300, 5300, and 7300:** these Windows NT servers can be switched to the SRM console, but still do not boot Tru64 UNIX or OpenVMS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L13782|"RE: Compaq to offer Tru64 for $99"]], John Jemiolo, axp-list, 5 Nov 1999)] Linux is not affected. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1999-November.mbox#L12890|"SUMMARY: AS 3300 support for Tru64UNIX/Linux?"]], Stephen Dowdy, tru64-unix-managers, 10 Nov 1999)]
  * **AlphaPC 164RX:** no SRM console was released for it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L9150|"Re: switching from ARC back to SRM"]], Jay Estabrook, axp-list, 16 Aug 2000)] It was only sold for Windows NT. [(>{{wiki:hardware:motherboards:pc164rx:pc164rx_product_brief.pdf?linkonly|AlphaPC 164RX Product Brief}}, p. 2)]
  * **AlphaPC 164UX and 164BX (Ruffian):** the only firmware is Deskstation's ARCSBIOS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L29483|"Re: AlphaBios vs SRM"]], Rich Payne, axp-list, 15 Sep 1999)]
  * **Multia:** neither Tru64 UNIX nor OpenVMS was officially supported on the Multia, although both have been run on it unofficially. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L36|"Re: Multia/166MHz"]], Dan O'Reilly, axp-list, 1 Jan 2000)]
  * **UP1000:** Tru64 UNIX does not support the UP1000's Irongate chipset, and the board is not a licensed platform. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-February.mbox#L18082|"RE: UP1000 & SRM"]], Mike Foley, axp-list, 16 Feb 2000)] API's manuals for the UP1000, UP1100, and UP1500 only mention Linux. [(>{{wiki:hardware:motherboards:up1000:up1000_technical_reference_manual.pdf?linkonly|UP1000 Technical Reference Manual}})] [(>{{wiki:hardware:motherboards:up1100:up1100_technical_reference_manual.pdf?linkonly|UP1100 Technical Reference Manual}})] [(>{{wiki:hardware:motherboards:up1500:up1500_user_s_manual.pdf?linkonly|UP1500 User's Manual}}, p. 4-2)]
  * **UP2000:** the UP2000 is not an officially supported platform for Tru64 UNIX, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L43541|"RE: UP2000 and Tru64?"]], Mike Foley, axp-list, 23 Dec 1999)] although Tru64 UNIX 4.0F has been run on it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-October.mbox#L16386|"Re: Consigned to Oblivion, Alpha and Firmware"]], Maurice Hilarius, axp-list, 11 Oct 1999)] It does not run OpenVMS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-June.mbox#L21700|"Re: OT: True64 on UP2000?"]], clc31@cornell.edu, axp-list, 28 Jun 2000)]
  * **CS20 and DS20L:** API NetWorks sold the CS20 for Linux; its onboard SCSI controller was not supported by Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L27576|"RE: DS20L"]], Peter Petrakis, axp-list, 30 May 2002)] Compaq's version, the DS20L, lists only Tru64 UNIX V5.1A in its firmware release notes. [(>{{wiki:software:firmware:alphaserver_ds20l_v6.6_firmware_release_notes.pdf?linkonly|AlphaServer DS20L V6.6 Console Firmware Release Notes}}, p. 5)]

=== No OpenVMS ===

  * **EB164:** the board's manual states that it does not support OpenVMS. [(>{{wiki:hardware:motherboards:eb164:21164_motherboard_user_manual.pdf?linkonly|Digital Semiconductor 21164 Alpha Microprocessor Motherboard User's Manual}}, p. 3-10)]
  * **Other evaluation boards and OEM motherboards:** no document states that OpenVMS was supported on them. The EB66+ manual lists "OpenVMS firmware (not included)", [(>{{wiki:hardware:motherboards:eb66plus:eb66plus_user_guide.pdf?linkonly|EB66+ User's Guide}}, p. 3-32)] and the AlphaPC 64 manual refers questions about Digital UNIX and OpenVMS to the local distributor. [(>{{wiki:hardware:motherboards:pc64:pc64_motherboard_user_manual.pdf?linkonly|AlphaPC 64 Motherboard User's Manual}}, p. 1-8)] OpenVMS under a hobbyist license has been run on a PC164 or 164SX converted to SRM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L33343|"Re: New life for PC164 (Was: SX164 ARC to SRM)"]], Evan, axp-list, 16 Nov 1999)]

=== No Windows NT ===

[(>{{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10)] The EV7 systems support only Tru64 UNIX and OpenVMS, with Linux as an option. [(>{{wiki:hardware:systems:alphaserver_es47:alphaserver_es47_es80_quickspecs.pdf?linkonly|HP AlphaServer/AlphaStation ES47 Tower, AlphaServer ES47, and AlphaServer ES80 Systems QuickSpecs}}, July 2007, p. 6)]
  * **AlphaServer GS60 and GS140:** these were sold with Tru64 UNIX or OpenVMS. [(>{{wiki:hardware:systems:alphaserver_gs60:alphaserver_gs60_8200_tru64_openvms_systems_catalog.pdf?linkonly|Compaq AlphaServer GS60 and AlphaServer 8200 Tru64 UNIX and OpenVMS Systems}}, Systems and Options Catalog, April 1999)] The older AlphaServer 8200 and 8400 were also sold with Windows NT Server 4.0. [(>{{wiki:hardware:systems:alphaserver_8400:alphaserver_8200_8400_windows_nt_systems_catalog.pdf?linkonly|AlphaServer 8200 and 8400 Windows NT Systems}}, Systems and Options Catalog, June 1999)]
  * **AlphaStation XP900:** Compaq's 1999 catalog offered it with Tru64 UNIX, OpenVMS, or without an operating system for Linux. [(>{{wiki:hardware:systems:alphastation_xp900:alphastation_xp900_catalog.pdf?linkonly|AlphaStation XP900}}, Systems and Options Catalog, September 1999)] However, the V7.3 firmware includes AlphaBIOS for it (see [[#conflicting_information|Conflicting information]]).

=== No Linux ===

  * **DEC 3000, DEC 4000, and DEC 7000:** the kernel has no support for these systems, before or after Linux 6.10. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.10|arch/alpha/kernel/setup.c]], Linux 6.10)]
  * **AlphaServer 8200, 8400, GS60, and GS140 (TurboLaser):** the kernel has no support for these systems, before or after Linux 6.10. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.10|arch/alpha/kernel/setup.c]], Linux 6.10)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-September.mbox#L17415|"Re: AlphaServer GS140 (8400)"]], Jay Estabrook, debian-alpha, 23 Sep 2003)]
  * **Systems and processors removed in Linux 6.10:** the Jensen, all systems and processors of the EV4, EV45, and EV5 generations, and the EB164; see [[#linux|Linux]].

==== Linux ====

Linux runs on most Alpha systems, booting from SRM with aboot or from ARC, AlphaBIOS, or ARCSBIOS with MILO. Systems without SRM, such as the Alpha XL and XLT and the Ruffian, can only boot Linux with MILO. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L5923|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] See [[software:boot_loaders|Boot Loaders]].

Linux 6.10 removed support for processors without the BWX extension (the EV4, EV45, and EV5 generations) and for the systems that can only use them. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] The removed systems are:

  * the Jensen (DEC 2000 AXP and DECpc AXP 150), [(>[[https://git.kernel.org/torvalds/c/f81f335a56a8|"alpha: remove DECpc AXP150 (Jensen) support"]], Linux 6.10)]
  * all systems with the LCA processors or the APECS chipset: the AlphaStation 200, 250, 255, and 400 and AlphaServer 300 and 400 (Avanti), the Alpha XL, the Multia and AXPpci 33 (Noname), the AlphaBook 1, the Platform 2000, the EB64+, EB66, EB66+, and AlphaPC 64, and the EV4 versions of the AlphaServer 1000 and 1000A, [(>[[https://git.kernel.org/torvalds/c/430ad3f0ddd7|"alpha: remove LCA and APECS based machines"]], Linux 6.10)]
  * the EV4 and EV45 versions of the AlphaServer 2000 and 2100, and the AlphaServer 2100A (Lynx), [(>[[https://git.kernel.org/torvalds/c/d2b1e353dacc|"alpha: sable: remove early machine support"]], Linux 6.10)]
  * the EB164, which only supports EV5 processors. [(>[[https://git.kernel.org/torvalds/c/4bf859076b16|"alpha: cabriolet: remove EV5 CPU support"]], Linux 6.10)]

Systems sold with EV5 processors that also accept EV56 processors, such as the AlphaStation 500 and 600, are still supported, but need an EV56 processor. [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)]

The Titan (AlphaServer DS15, DS25, and ES45), Wildfire (GS80, GS160, and GS320), and Marvel (ES47, ES80, and GS1280) systems need kernels built without ''CONFIG_ALPHA_LEGACY_START_ADDRESS'', which ''make defconfig'' enables; see [[documentation:kernel#kernel_start_address|Kernel]]. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig.debug?h=v7.3-rc1|arch/alpha/Kconfig.debug]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/configs/defconfig?h=v7.3-rc1|arch/alpha/configs/defconfig]], Linux 7.3)]

==== BSD ====

All three BSDs boot only from the [[software:firmware:srm|SRM console]], because they use the OSF/1 PALcode and cannot use the PALcode that ARC and AlphaBIOS provide. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1998-October.mbox#L4692|"PALcode"]], David Seifert, freebsd-alpha, 9 Oct 1998)] There is no BSD equivalent of MILO, and work on booting FreeBSD from AlphaBIOS stalled for lack of documentation. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/1999-April.mbox#L3081|"Re: MILO for fbsd?"]], Andrew Gallatin, freebsd-alpha, 8 Apr 1999)]

=== NetBSD ===

NetBSD/alpha was started by Chris Demetriou and is the oldest of the three BSD ports; users were running NetBSD 1.2 on Alpha by October 1996. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/1996-October.mbox#L134|"alpha 1.2 release"]], Michael Graff, port-alpha, 7 Oct 1996)]

The port is still maintained, and its ''port-alpha@netbsd.org'' mailing list remains active. Alpha is a supported port in NetBSD's current releases, 11.0, released on 30 July 2026, and 10.2; NetBSD 11.0 added support for Secure PLT binaries on Alpha. [(>[[https://www.netbsd.org/releases/formal-11/NetBSD-11.0.html|NetBSD 11.0 release notes]], The NetBSD Project, 30 Jul 2026)] Install images are published for each release, such as ''NetBSD-11.0-alpha.iso''. [(>[[https://cdn.netbsd.org/pub/NetBSD/NetBSD-11.0/images/|NetBSD-11.0/images]], cdn.netbsd.org)] NetBSD also runs under QEMU; see [[software:emulators#other_operating_systems|Emulators]]. The supported systems are listed on the [[https://wiki.netbsd.org/ports/alpha/|NetBSD/alpha]] port page.

=== FreeBSD ===

FreeBSD/alpha was Doug Rabson's work and was the first non-x86 port added to FreeBSD. FreeBSD 6.x was the last series to support Alpha, which was removed in FreeBSD 7.0. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/freebsd-alpha-mbox/gmane-2006-May.mbox#L972|"HEADSUP: Alpha support is being retired in 7.0"]], John Baldwin, freebsd-alpha, 11 May 2006)]

=== OpenBSD ===

OpenBSD first shipped an Alpha release with OpenBSD 2.2 in December 1997. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-misc-mbox/googlegroups-1997-December.mbox#L2919|"OpenBSD 2.2 released for the alpha"]], Theo de Raadt, comp.unix.osf.misc, 14 Dec 1997)]

OpenBSD/alpha is still supported, including SMP, and is part of the current release, OpenBSD 7.9 of 19 May 2026, whose changes include reworked TLB shootdown on Alpha. [(>[[https://www.openbsd.org/79.html|OpenBSD 7.9]], The OpenBSD Project, 19 May 2026)] The installation media are ''install79.iso'' and ''cd79.iso'', and the procedure is described in the release's ''INSTALL.alpha''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/openbsd-alpha-mbox/2026-February.mbox#L1|"Re: SMP on AlphaServer DS20E"]], Miod Vallat, openbsd-alpha, 14 Feb 2026)] The supported systems are listed on the [[https://www.openbsd.org/alpha.html|OpenBSD/alpha]] page.

==== Windows NT ====

Windows NT ran on Alpha from version 3.1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-December.mbox#L1768|"Alpha Wiki"]], Marco Benton, axp-list, 18 Dec 2006)] The DECpc AXP 150 was bundled with Windows NT, and the otherwise identical DEC 2000 AXP with OpenVMS or DEC OSF/1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)] Digital's workstations were sold in Windows NT and UNIX/OpenVMS versions, e.g. the Personal Workstation "a" series with Windows NT 4.0 and "au" series with Tru64 UNIX or OpenVMS. [(>{{wiki:hardware:systems:personal_workstation:personal_workstation_a_au_series_catalog.pdf?linkonly|Compaq DPW Enhanced a-Series & au-Series}}, Systems and Options Catalog, September 2000)] Digital Semiconductor's evaluation boards and OEM motherboards shipped with Windows NT firmware, and supported Windows NT 3.51 and 4.0. [(>{{wiki:hardware:motherboards:common:windows_nt_installation_guide.pdf?linkonly|Alpha Microprocessors Motherboard Windows NT 3.51 and 4.0 Installation Guide}}, p. 28)]

Compaq ended Windows NT development for Alpha in August 1999, when it laid off its porting team. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L31035|"Re: Done: Experience with large IDE drive and Promise Ultra/66 card"]], Jeff Bolle, axp-list, 22 Aug 1999)] After Compaq stopped supporting 32-bit Windows NT, Microsoft dropped the 64-bit version within a week. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L54447|"Re: Off topic: NT on Alpha (was: Alpha Users in the Toronto area.)"]], Phillip Ezolt, axp-list, 30 Sep 1999)] Windows NT 4.0 was the last released version. Prerelease builds of Windows 2000 for Alpha were distributed, up to at least Release Candidate 1 (build 2072). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-January.mbox#L2396|"w2k alpha"]], Steven Moix, axp-list, 9 Jan 2009)] The last Windows NT firmware was AlphaBIOS V5.71, for the AlphaServer DS10, AlphaStation XP900, and AlphaServer DS20 and DS20E. [(>{{wiki:software:firmware:alpha_systems_firmware_update_v7.3_release_notes_overview.pdf?linkonly|Alpha Systems Firmware Update V7.3 Release Notes Overview}}, p. 10)]

==== Tru64 UNIX ====

Digital's UNIX for Alpha was called DEC OSF/1 until 1995, when it was renamed Digital UNIX, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1995-March.mbox#L2459|"Press/Digital To Rename DEC OSF/1 Operating Systems 'Digital UNIX'"]], Digital Press and Analysts News, biz.digital.announce, 15 Mar 1995)] and Compaq renamed it Tru64 UNIX in 1999. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/1999-February.mbox#L27502|"News/announcement: Compaq Tru64 UNIX and new Web site.."]], Tom Blinn, alpha-osf-managers, 1 Feb 1999)] Its releases, hardware requirements, licensing, and end of support are described in [[software:operating_systems:tru64|Tru64 UNIX]].

==== Dual booting ====

Linux can share a machine with OpenVMS or Tru64 UNIX, since all of them boot from the SRM console. One arrangement is to install each system on its own disk, make Linux the default with ''bootdef_dev'', ''boot_file'', and ''boot_osflags'', and boot the other system by naming its disk, for example ''boot -file vmunix -flags a dka0'' for Tru64 UNIX. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L2675|"Re: Dual boot a DS20.."]], 이준문, axp-list, 3 May 2000)] Adding a disk can change the names that Linux gives to the disks already present, so that the kernel no longer finds its root file system. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-April.mbox#L26637|"RE: Dual boot a DS20.."]], Frank Tiels, axp-list, 27 Apr 2000)]

A disk labeled by Tru64 UNIX can also hold aboot. Its whole-disk ''c'' partition does no harm, but an installer may refuse to write the boot block because no space lies outside the partitions, and ''swriteboot -f'' then writes it by hand. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L8415|"Re: Bootstrap Failure after Installation of Red Hat Linux 7.0"]], Michal Jaegermann, axp-list, 9 Mar 2001)]

OpenVMS, Tru64 UNIX, and ARC each keep the time-of-year clock relative to a different epoch; see [[software:firmware:srm#known_issues|SRM Console: Known issues]].

==== History ====

=== The first port ===

Linux on Alpha began at Digital, before any of the Alpha/Linux mailing lists existed, with a 32-bit kernel on the [[hardware:systems:jensen|Jensen]], followed by the Avanti. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-July.mbox#L572|"first Linux port"]], Jay Estabrook, axp-list, 13 Jul 2006)] The Jensen booted Linux from SRM, since no evaluation board PALcode was ever available for it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-December.mbox#L2127|"Re: booting from MILO and SRM: how is it possible?"]], Jay Estabrook, axp-list, 1 Dec 1997)] Jim Paradis of Digital's Alpha Migration Tools Group described the work in a "Linux/AXP Progress Report", dated 9 September 1994: a port of the Linux 1.0 kernel that kept every kernel data type to 32 bits except where the kernel met the hardware, so that code such as the file systems would work unmodified. It was cross-developed on a DEC 3000 running DEC OSF/1, with the kernel debugged under the [[software:emulators#isp|ISP]] simulator, and its drivers used the console callbacks. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-September.mbox#L14204|"Linux/AXP Progress Report"]], Jim Paradis, comp.os.linux.announce, 12 Sep 1994)]

By November 1994 the port, renamed Linux/Alpha in keeping with Digital's policy, ran from the hard disk. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1994-November.mbox#L36280|"Linux/Alpha Progress Report - Part 2"]], Jim Paradis, comp.os.linux.announce, 18 Nov 1994)] The Linux/Alpha Software Developers' Kit, the first public release of Linux components for Alpha, followed on 23 January 1995. It was cross-compiled from another host and had only console-callback drivers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-January.mbox#L2126|"ANNOUNCEMENT: Linux/Alpha Developers' Kit!"]], Jim Paradis, comp.os.linux.announce, 23 Jan 1995)]

BLADE 0.1 (Basic Linux/Alpha Distribution Eyesore), released on 1 July 1995, was the first Alpha/Linux distribution that could be installed without a second machine. It was a set of floppy images for the AXPpci 33 (Noname), built on a 1.2.8 kernel, and was 64-bit, the port having moved to 64 bits in the meantime. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-announce-mbox/googlegroups-1995-July.mbox#L10349|"Linux/Alpha installable kit now available!"]], Jim Paradis, comp.os.linux.announce, 1 Jul 1995)]

=== Vendor support ===

HP officially supported Red Hat Linux 7.2 for Alpha on the AlphaServer DS10, DS20, ES40, and ES45. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-June.mbox#L12427|"Re: RedHat 7.2 Linux for Alpha"]], Jay Estabrook, axp-list, 11 Jun 2002)] The DS25 and ES45 firmware release notes list Red Hat Linux 7.2 among the supported operating systems. [(>{{wiki:software:firmware:alphaserver_ds25_v7.2_firmware_release_notes.pdf?linkonly|AlphaServer and AlphaStation DS25 V7.2 Firmware Release Notes}})] [(>{{wiki:software:firmware:alphaserver_es45_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer and AlphaStation ES45 V7.3 Firmware Release Notes}}, p. 6)]
