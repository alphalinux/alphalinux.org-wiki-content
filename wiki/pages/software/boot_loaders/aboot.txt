===== aboot =====

aboot is the Linux boot loader for Alpha systems with the [[software:firmware:srm|SRM console]]. It loads a Linux kernel, optionally with an initial ramdisk, from an ext2, ext3, ext4, XFS, ISO 9660, or UFS file system or from raw disk blocks, and supports a configuration file, ''/etc/aboot.conf''. [(>[[https://github.com/alphalinux-org/aboot/blob/master/README.md|README.md]], aboot 2.0)] Systems with the [[software:firmware:arc|ARC or AlphaBIOS]] firmware use [[software:boot_loaders:milo|MILO]] instead. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/aboot.sgml|aboot(8)]], aboot 2.0)]

aboot is free software under the GNU GPL. [(>[[https://github.com/alphalinux-org/aboot/blob/master/COPYING|COPYING]], aboot 2.0)] The current source repository is [[https://github.com/alphalinux-org/aboot]].

==== How it works ====

The SRM console "knows nothing about filesystems or disk-partitions". The first sector of the disk holds the size of the secondary boot loader in 512-byte blocks at offset 480, its starting sector at offset 488, a flag word at offset 496, and a checksum of the first 63 quadwords at offset 504. SRM loads the loader at virtual address 0x20000000 and jumps to it. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004, "Loading The Secondary Bootstrap Loader")] ''swriteboot'' writes aboot starting at sector 2. [(>[[https://github.com/alphalinux-org/aboot/blob/master/sdisklabel/swriteboot.c|sdisklabel/swriteboot.c]], aboot 2.0)]

aboot then:

  - switches from the console PALcode to the OSF/1 PALcode, [(>[[https://github.com/alphalinux-org/aboot/blob/master/utils.c|utils.c]], aboot 2.0)]
  - reads the boot device, file, and flags from the SRM environment, [(>[[https://github.com/alphalinux-org/aboot/blob/master/aboot.c|aboot.c]], aboot 2.0)]
  - reads the disk through the SRM console callbacks, [(>[[https://github.com/alphalinux-org/aboot/blob/master/cons.c|cons.c]], aboot 2.0)]
  - finds the partition in the BSD disklabel, mounts its file system, and loads the kernel and initrd, [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)]
  - and jumps to the kernel.

aboot does no low-level hardware setup of its own. Richard Henderson: "It relies entirely on SRM services." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L18895|"Re: Boot failure on AS2100"]], Richard Henderson, axp-list, 7 Nov 1999)] Errors such as ''c000000000000000'' when opening the boot device therefore come from SRM, not aboot. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L35715|"RE: installing rh 7.0"]], Will Woods, axp-list, 27 Mar 2001)]

=== Disklabels ===

A disk booted from SRM must use a BSD disklabel, because a PC (DOS) partition table occupies the same place in the first sector as the SRM boot block. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-April.mbox#L4626|"Re: Newbie question about booting."]], Larry Sendlosky, axp-list, 5 Apr 2000)] With Linux ''fdisk'', a BSD disklabel is created with the ''b'' command. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L281|"Re: Linux on a Sable working!"]], Jay Estabrook, axp-list, 1 Apr 1999)] ARC and AlphaBIOS cannot read BSD disklabels, so a disk cannot be booted from both SRM and AlphaBIOS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-February.mbox#L38849|"RE: srm / ide"]], Larry Sendlosky, axp-list, 29 Feb 2000)]

aboot only tries the file system drivers that match the partition type in the disklabel. ext2, ext3, ext4, and XFS use type 8, and UFS type 7. ISO 9660 is only found on devices without a disklabel, such as CDs. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] Recycled disks with an old PC partition table can confuse installers; overwriting the first sectors with zeros avoids this. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L11200|"Re: swriteboot ?"]], Michal Jaegermann, axp-list, 23 Jan 2003)]

==== Installing ====

=== swriteboot ===

''swriteboot'' writes aboot (''bootlx'') to the start of a disk and updates the boot block: [(>[[https://github.com/alphalinux-org/aboot/blob/master/sdisklabel/swriteboot.c|sdisklabel/swriteboot.c]], aboot 2.0)] [(>[[https://github.com/alphalinux-org/aboot/blob/master/README.md|README.md]], aboot 2.0)]

<code>
swriteboot [-f1-8] [-c1-8] [-v] disk bootfile [kernel]
swriteboot -c2 /dev/sda /boot/bootlx
</code>

  * The target is the whole disk (e.g. ''/dev/sda''), not a partition. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-October.mbox#L268|"Re: aboot install fails"]], Steve Langasek, debian-alpha, 1 Oct 2004)]
  * The space before the first partition must be free. If a partition overlaps aboot, ''swriteboot'' stops with "bootcode overlaps with partition #//n//. If you really want this, use -f//n//". [(>[[https://github.com/alphalinux-org/aboot/blob/master/sdisklabel/swriteboot.c|sdisklabel/swriteboot.c]], aboot 2.0)] ''-f3'' is usually needed for the whole-disk ''c'' partition. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)] Some users create a small first partition to reserve the space, and write aboot over it with ''-f1''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L22583|"Re: aboot problems with AlphaStation 200"]], Maciej W. Rozycki, axp-list, 15 Sep 1998)] Debian's installer does this. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2005-May.mbox#L1908|"Re: swriteboot vs debian installer wrt Tru64 disklabel"]], Steve Langasek, debian-alpha, 4 May 2005)]
  * ''-c'' sets the partition that holds ''/etc/aboot.conf''. Without it, ''swriteboot'' keeps the setting of an aboot already on the disk. [(>[[https://github.com/alphalinux-org/aboot/blob/master/sdisklabel/swriteboot.c|sdisklabel/swriteboot.c]], aboot 2.0)]
  * A kernel given as the third argument is written directly after aboot, and can be booted as partition ''0''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L31540|"Re: Boot via SRM on poweron"]], Michael Schwingen, axp-list, 21 Oct 1996)] Since 0.7a, such a kernel must be an uncompressed ELF image. [(>[[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/README|README]], aboot 0.9, 25 Oct 2001)]
  * On a disk shared with Tru64 UNIX, installing aboot makes the first and third partitions unusable, since they must start at offset 0. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)]

=== abootconf ===

''abootconf'' //disk// [//partition//] shows or sets the partition that aboot searches for ''/etc/aboot.conf''. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/abootconf.sgml|abootconf(8)]], aboot 2.0)] The device is the drive, e.g. ''/dev/sda'', and the setting is stored in the aboot image on the disk. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L9993|"Re: AW: installing kernel-image"]], Tyson Whitehead, debian-alpha, 15 Jul 2003)] Since 0.7, ''swriteboot -c'' does the same. [(>[[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/README|README]], aboot 0.9, 25 Oct 2001)]

=== Floppies ===

''e2writeboot'' writes aboot as a contiguous file, ''/linuxboot'', on an ext2 file system and points the boot block at it. It is normally used for floppies, and may fail on a fragmented file system: [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/e2writeboot.8|e2writeboot(8)]], aboot 2.0)] [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)]

<code>
fdformat /dev/fd0
mke2fs /dev/fd0
e2writeboot /dev/fd0 bootlx
</code>

''srmbootfat'', written by Nikita Schmidt, makes a file on a FAT floppy bootable in the same way. [(>[[https://github.com/alphalinux-org/aboot/blob/master/srmbootfat/srmbootfat.sgml|srmbootfat(1)]], aboot 2.0)] Older SRM versions, notably the Jensen's, cannot boot from a floppy. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)]

=== CDs ===

''isomarkboot'' //image// //bootlx// [//root.bin//] makes an ISO 9660 image bootable, which works because files on ISO 9660 are contiguous. [(>[[https://github.com/alphalinux-org/aboot/blob/master/tools/isomarkboot.c|tools/isomarkboot.c]], aboot 2.0)] For example, a rescue CD: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-February.mbox#L5894|"Re: equivalent of mkrescue for the alpha ??? rescue CDs"]], Steve Langasek, debian-alpha, 19 Feb 2004)]

<code>
cp -L /vmlinuz /initrd.img /boot/bootlx iso-root/
cp /etc/aboot.conf iso-root/etc/
mkisofs -r -J -o rescue.iso iso-root/
isomarkboot rescue.iso /bootlx
</code>

  * Booting a CD from SRM required a CD-ROM drive that could be set to 512-byte blocks. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-November.mbox#L23168|"Re: Bootable CD ?"]], Martin Ostermann, axp-list, 9 Nov 1998)]
  * The optional third argument stores the location of a root file system image in the ISO volume descriptor, for Debian's modified ramdisk driver. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-March.mbox#L1724|"news about CD booting"]], Loic Prylli, debian-alpha, 4 Mar 1999)]
  * ''isomarkboot'' originally assumed 64-bit ''long''s and only worked on Alpha hosts. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L8227|"isomarkboot for 32 bit machines"]], Martin Ostermann, axp-list, 7 Oct 1996)] Since 2004 it can be built on other architectures. [(>[[https://github.com/alphalinux-org/aboot/commit/68d6393|alphalinux-org/aboot commit 68d6393]])]

==== Booting ====

aboot takes its arguments from the SRM ''boot'' command: [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)] [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)]

<code>
>>> boot dka0 -file 2/vmlinux.gz -flags "root=/dev/sda2"
>>> boot dka0 -flags 0
>>> boot dka0 -flags "2:1 single"
>>> boot dka0 -flags i
</code>

  * **''-file'' //partition///''path'':** the partition is a digit from 1 to 8, corresponding to BSD partitions ''a'' to ''h''. It can be omitted on a floppy or CD. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L58087|"Re: SRM unplugged"]], His Holiness the Reverend Doktor Xenophon Fenderson, the Carbon(d)ated, axp-list, 5 Oct 1998)] [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/aboot.conf.sgml|aboot.conf(5)]], aboot 2.0)] Partition ''0'' is a kernel written directly after aboot. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)]
  * **''-flags'' with kernel arguments** passes them to the kernel. The quotes are required when there are spaces. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-March.mbox#L22902|"RE: Alpha Server 2000:Up and Running:THANKS!!"]], Jay Estabrook, axp-list, 20 Mar 1997)]
  * **''-flags'' //n//** boots entry //n// from ''/etc/aboot.conf'' on the configured partition. **''-flags'' //p//'':''//n//** reads ''aboot.conf'' from partition //p// instead. Extra kernel arguments can follow after a space. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] The single-character form exists because some SRM versions, such as the Jensen's, only allow 8 or 16 characters in the option string. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L58087|"Re: SRM unplugged"]], His Holiness the Reverend Doktor Xenophon Fenderson, the Carbon(d)ated, axp-list, 5 Oct 1998)]
  * **''-flags i''**, or empty flags, starts the interactive prompt. If a kernel fails to load, aboot also falls back to the prompt. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)]
  * **Unattended booting:** set ''boot_osflags'' to ''0'', ''boot_file'' to an empty string, ''bootdef_dev'' to the boot disk, and ''auto_action'' to ''boot''. [(>[[https://github.com/alphalinux-org/aboot/blob/master/README.md|README.md]], aboot 2.0)] Pressing Ctrl-C repeatedly during startup returns to the SRM prompt. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-June.mbox#L1499|"Re: Getting out of aboot in SRM?"]], Jay Estabrook, axp-list, 2 Jun 1997)]

=== aboot.conf ===

aboot searches the configured partition for ''/etc/aboot.conf'', ''/aboot.conf'', ''/etc/aboot.cfg'', and ''/aboot.cfg'', in that order. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] Each line is a single-character label, a colon, a partition and path, and kernel arguments. A ''#'' starts a comment, and a line starting with ''-'' ends the file. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/aboot.conf.sgml|aboot.conf(5)]], aboot 2.0)]

<code>
0:2/vmlinux.gz root=/dev/sda3
1:2/vmlinux.gz root=/dev/sda3 single
2:2/vmlinux.old.gz root=/dev/sda3
3:2/vmlinux.gz initrd=/initrd.img root=/dev/sda3
</code>

Paths are relative to the root of the partition. If ''/boot'' is a separate partition, the file is ''/boot/etc/aboot.conf'', and kernels are given as e.g. ''2/vmlinux.gz''. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/aboot.conf.sgml|aboot.conf(5)]], aboot 2.0)] Red Hat created a symbolic link from ''/etc/aboot.conf'' to ''/boot/etc/aboot.conf''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-December.mbox#L899|"RedHat 7.2 on ES40 AlphaServer - Boot Problem - Help Solving"]], Jim McCarthy, axp-list, 13 Dec 2009)]

aboot.conf has no default entry. The default is chosen with the SRM variable ''boot_osflags''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L15878|"Re: SRM vs. AlphaBIOS"]], Michal Jaegermann, axp-list, 8 Sep 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L8817|"Re: installing kernel-image"]], Ionut Georgescu, debian-alpha, 15 Jul 2003)]

=== Interactive mode ===

The interactive prompt accepts these commands: [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)]

^ Command ^ Description ^
| ''h'', ''?'' | Display the command summary |
| ''q'' | Halt and return to SRM |
| ''p'' //1-8// | Use this partition for ''aboot.conf'' and kernels |
| ''l'' | List the entries in ''aboot.conf'' |
| ''d'' //dir// | List a directory |
| ''b'' //file// //args// | Boot a kernel with arguments; ''-'' for a kernel written after aboot |
| ''i'' //file// | Use a file as the initial ramdisk |
| ''0''-''9'' | Boot an ''aboot.conf'' entry |

For example, ''b 3/vmlinux.gz root=/dev/sda3 single''. [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, 14 Feb 2004)] Directory listing on ext2 was added in 0.6. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-March.mbox#L571|"Improved aboot (with updated documentation) from boot floppies"]], David Huggins-Daines, debian-alpha, 3 Mar 2000)] In 0.5, the prompt did not work after a failed boot, and the system had to be reset. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L16627|"Problem with aboot 0.5"]], B. James Phillippe, axp-list, 8 Jul 1998)]

=== initrd ===

An initial ramdisk is given with ''initrd=''//path// in the flags, or with the ''i'' command. It is loaded from the same partition as the kernel, as high in memory as possible. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] The option must be inside the ''-flags'' string, e.g.: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-December.mbox#L16134|"Re: boot failures"]], Jay Estabrook, axp-list, 12 Dec 2002)]

<code>
>>> boot dkc0 -fi 2/boot/vmlinuz-2.4.9-32.5 -fl "initrd=/boot/initrd-2.4.9-32.5.img root=/dev/sda2"
</code>

initrd support was added in 0.7; TurboLinux had shipped a different patch for it earlier. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L2892|"aboot 0.7 released"]], David Huggins-Daines, axp-list, 2 May 2000)] Red Hat 7 depended on it for installation from CD. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-January.mbox#L14535|"Re: Upgrading my XL266 from 6.2 to 7.0 MILO"]], Matt Wilson, axp-list, 11 Jan 2001)]

=== Network booting ===

SRM fetches a network boot image itself with BOOTP and TFTP, e.g. ''boot ewa0 -protocol bootp''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-April.mbox#L45126|"Re: Remote boot Multia..."]], Maciej W. Rozycki, axp-list, 27 Apr 1998)] aboot can build such an image, containing aboot, a compressed kernel, an initrd, and default arguments, with ''netabootwrap'': [(>[[https://github.com/alphalinux-org/aboot/blob/master/doc/man/netabootwrap.sgml|netabootwrap(1)]], aboot 2.0)]

<code>
netabootwrap -t netboot.img -k vmlinux.gz -i initrd.gz -a "root=/dev/hda2"
</code>

Soohoon Lee wrote ''netabootwrap'' in 2000. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-December.mbox#L32373|"net aboot + initrd"]], Soohoon Lee, axp-list, 27 Dec 2000)] By 2007, Debian built all its netboot installer images with it. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2007-August.mbox#L3772|"Re: [BUG] 2.6.23-rc3 won't boot on alpha (fwd)"]], Steve Langasek, debian-alpha, 21 Aug 2007)] Unlike the kernel's own ''bootpfile'' target, the image can be compressed and include an initrd. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L7159|"Re: kernel build targets"]], Jay Estabrook, axp-list, 12 Dec 2001)]

aboot does not read FAT, ReiserFS, or Tru64 AdvFS. [(>[[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0)] Will Woods tried to port GRUB's ReiserFS code for 0.9, but it crashed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L2850|"Re: reiserfs on all my SRM-alpha drives: how I did it"]], Will Woods, debian-alpha, 6 Nov 2001)]

aboot 2.0 refuses ext4 file systems with features it cannot read safely, including ''meta_bg'', ''bigalloc'', ''quota'', and more than 2^32 blocks. It only reads extents stored directly in the inode, not deeper extent trees, so a kernel file split into more than four extents cannot be loaded. [(>[[https://github.com/alphalinux-org/aboot/blob/master/fs/ext2.c|fs/ext2.c]], aboot 2.0)] [(>[[https://github.com/alphalinux-org/aboot/commit/707f7af|"ext4: add initial ext4 support with 64-bit group descriptors and multi-extent reads"]], alphalinux-org/aboot)]

==== Known issues ====

  * **Kernel position on large partitions:** older versions failed to load kernels far into large ext2 partitions, so a small ''/boot'' partition was recommended. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L2820|"RE: Hard Drive size on Jensen"]], Will Woods, axp-list, 3 Apr 2001)] In 1996 the ext2 code had a hardcoded 1 GiB limit, [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-April.mbox#L1293|"Re: Are these known bugs?"]], David Mosberger-Tang, axp-list, 2 Apr 1996)] and later a limit of 256 block groups, about 2 GiB. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L77425|"Re: Can't boot LX164: trying netboot"]], Ruediger Oertel, axp-list, 25 Mar 1999)]
  * **ext2 features:** before 0.6, aboot could not read file systems with 4 KiB blocks, sparse superblocks, or file types in directory entries. ''mke2fs -O none'' creates a file system that older versions can read. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L52432|"Re: Red Hat Rawhide/Alpha"]], Bill Nottingham, axp-list, 29 Nov 1999)] aboot 0.9b does not support ext3 directory indexes (htree). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-March.mbox#L7212|"Re: Couple quick questions 164Lx milo/aboot/ext3 AlphaBIOS versus SRM"]], Falk Hueffner, debian-alpha, 19 Mar 2003)]
  * **Kernel format:** aboot requires the ELF headers in the first block of the kernel, which binutils 2.9 and later did not guarantee. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L3659|"Re: Spooky Alpha log messages. Whatsit?"]], Maciej W. Rozycki, axp-list, 3 Aug 1998)] With Linux 2.2, aboot 0.5 printed "block-size smaller than expected!"; aboot-0.5-7 fixed this. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L45764|"Kernel 2.2 and aboot"]], Tom Langley, axp-list, 15 Mar 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L47495|"RE: Kernel 2.2 and aboot"]], John Jemiolo, axp-list, 15 Mar 1999)] Linux 2.4 moved the kernel start address; aboot 0.7 and later read it from the ELF headers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-June.mbox#L18501|"Re: Linux-2.4.0-test2"]], Richard Henderson, axp-list, 24 Jun 2000)] Linux 2.6.23 and later need the ''PT_NOTE'' fix from 2007. [(>[[https://github.com/alphalinux-org/aboot/commit/27fd1f1|alphalinux-org/aboot commit 27fd1f1]])]
  * **"unknown compression method":** aboot first tries to load a kernel uncompressed, then compressed, and prints this if both fail, whatever the actual cause. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-December.mbox#L2652|"New Red Hat 7.2 Alpha install on DEC PWS 600au"]], Jim McCarthy, axp-list, 11 Dec 2004)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-November.mbox#L1928|"Re: Jensen DECPC150 install!"]], Sebastian Moeller, debian-alpha, 15 Nov 1999)] In 2024, a user reported it with kernels after 6.4 on an XP1000, while another booted 6.11 on the same model. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2024-November.mbox#L679|"aboot unzip "unknown compression method" on recent (post 6.4) kernels?"]], Alex Winbow, debian-alpha, 22 Nov 2024)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2024-November.mbox#L958|"Re: aboot unzip "unknown compression method" on recent (post 6.4) kernels?"]], Michael Cree, debian-alpha, 24 Nov 2024)]
  * **Kernel headers:** aboot "uses a lot of kernel structure definitions", so it has broken with new kernel headers. aboot 0.9 would not build against 2.6 headers, and in 2004 Jay Maynard built it by installing 2.4 sources temporarily. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/gentoo-alpha-mbox/2004-April.mbox#L435|"Re: [gentoo-alpha] alpha-sources: obsolete in a 2.6 world?"]], Jay Maynard, gentoo-alpha, 2 Apr 2004)] The sanitized headers of 2.6.19 broke it again until Mike Frysinger's fixed Gentoo package in 2007. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/gentoo-alpha-mbox/2007-July.mbox#L68|"[gentoo-alpha] Gentoo/Alpha status report 2007"]], Jose Luis Rivero, gentoo-alpha, 21 Jul 2007)]
  * **Creating the disklabel:** ''fdisk'' from util-linux has been unable to create BSD disklabels since about version 2.23, and Gentoo's install images still had the problem in 2024. ''parted'' works: ''mktable bsd''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/gentoo-alpha-mbox/2024-April.mbox#L85|"Re: [gentoo-alpha] fdisk on mini-installer iso"]], Matt Turner, gentoo-alpha, 8 Apr 2024)]
  * **Version string:** Debian's aboot 1.0~pre20200212 still printed "1.0_pre20040408", so the console did not show which version was installed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2024-November.mbox#L1305|"Re: aboot unzip "unknown compression method" on recent (post 6.4) kernels?"]], Alex Winbow, debian-alpha, 24 Nov 2024)]
  * **Serial console:** with the SRM ''console'' variable set to ''serial'', aboot prints nothing on the screen. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L29944|"Re: aboot gives no output on SX164"]], Falk Hueffner, axp-list, 23 Jul 2001)]
  * **IDE on the PC164LX:** ''boot dqa0'' failed with "Failed to send Read to dqa0" with a slave drive attached; ''boot dqa0.0'' worked. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-August.mbox#L5457|"Success with RAID1 on Alpha"]], Doug Larrick, debian-alpha, 16 Aug 2003)]
  * **Network booting and UFS:** these are "not well exercised and may be broken". [(>[[https://github.com/alphalinux-org/aboot/blob/master/README.md|README.md]], aboot 2.0)] Reading ''aboot.conf'' from UFS can hang if the entry is not found. [(>[[https://github.com/alphalinux-org/aboot/blob/master/README.md|README.md]], aboot 2.0)]
  * **SRM without support for the boot controller:** aboot can only boot from devices that SRM can read. Alternatives are a network boot, or aboot and the kernel on a disk on a supported controller. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-October.mbox#L4288|"Re: howto boot alpha via SRM without supported SCSI controller"]], Måns Rullgård, debian-alpha, 15 Oct 2004)]

==== Conflicting information ====

The following sources conflict with each other or with the account given above. They are listed here for further investigation.

  * **Space to reserve before the first partition**
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/man/swriteboot.8|swriteboot(8)]]: "It is therefore suggested to reserve the first 512 sectors of a harddisk for boot purposes."
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1: "We suggest that the disk be partitioned such that the first partition starts at an offset of 2048 sectors."
    * The same document, later: "Partition 'a' should start about 1M into the disk: don't start it at sector 1, try starting at sector 10 (for example)."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L30392|"Re: Boot via SRM on poweron"]], Jay Estabrook, axp-list, 20 Oct 1996: "aboot fits fine in front of partition 1 if you offset the start of partition 1, say 512-1024 sectors"
  * **Default partition for ''aboot.conf''**
    * [[https://github.com/alphalinux-org/aboot/blob/master/include/config.h|include/config.h]], aboot 2.0, sets ''CONFIG_FILE_PARTITION'' to 1.
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1: "A newly compiled aboot will search the second partition (e.g., /dev/sda2)."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-March.mbox#L3941|"Re: potato alpha install experience..."]], David Huggins-Daines, debian-alpha, 22 Mar 2000: "So if you installed aboot manually, you got the default of 2."
  * **Command that lists ''aboot.conf''**
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/man/aboot.conf.sgml|aboot.conf(5)]], aboot 2.0: booting "with the flag "i") and then issuing "h" at the aboot-prompt."
    * [[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/README|README]], aboot 0.9, on version 0.3: "The contents of /etc/aboot.conf can be displayed with a commandline argument consisting of a single 'h'."
    * [[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0: ''h'' displays the help, and ''l'' lists the entries.
  * **Whether there can be a partition 0**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L30392|"Re: Boot via SRM on poweron"]], Jay Estabrook, axp-list, 20 Oct 1996: "note that you can't have a "0 partition"; both minlabel and fdisk start numbering partitions with "1"."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L31540|"Re: Boot via SRM on poweron"]], Michael Schwingen, axp-list, 21 Oct 1996: "aboot uses the '0' to mean a kernel that is written directly behind the aboot code"
  * **Whether ''swriteboot'' accepts more than one ''-f''**
    * [[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/ChangeLog|ChangeLog]], aboot, 17 Aug 1996: "Make force_overlap a bitset so we can force more than one overlapping partition."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2005-May.mbox#L1908|"Re: swriteboot vs debian installer wrt Tru64 disklabel"]], Steve Langasek, debian-alpha, 4 May 2005: "it only lets you ignore overlaps with a *single* partition."
  * **Whether ''swriteboot'' can be given a partition**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-October.mbox#L268|"Re: aboot install fails"]], Steve Langasek, debian-alpha, 1 Oct 2004: "Yes, the target for swriteboot must be a drive, not a partition."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-December.mbox#L6128|"Re: Upgrade from AlphaBIOS to SRM Console mess"]], Robert Williams, axp-list, 6 Dec 2000: "You must use sda3 here because that is partition c on the BSD label, which includes the entire disk"
  * **Disks without a disklabel**
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1: "If a disk has no partition table, aboot pretends the disk contains one ext2 partition starting at the first diskblock."
    * [[https://github.com/alphalinux-org/aboot/blob/master/disk.c|disk.c]], aboot 2.0, tries every file system driver on a disk without a disklabel.
  * **ECOFF kernels**
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/faq/SRM-HOWTO.sgml|SRM Firmware Howto]], v0.8.1, describes aboot as supporting "booting of executable object files (both ELF and ECOFF)".
    * [[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/README|README]], aboot 0.9: "(as of 0.7a) "raw" booting no longer is - you must use an uncompressed ELF kernel." aboot 2.0 only loads ELF kernels.
  * **Input to ''e2writeboot''**
    * [[https://github.com/alphalinux-org/aboot/blob/master/doc/man/e2writeboot.8|e2writeboot(8)]]: "The boot loader file must be an ECOFF object file."
    * [[https://github.com/alphalinux-org/aboot/blob/c91a39e9a735/README|README]], aboot 0.9: "IMPORTANT: e2writeboot now expects a _raw_ file, not an ECOFF object file."

    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-July.mbox#L1865|"aboot size limitation in Woody"]], Bob Lindell, debian-alpha, 12 Jul 2004: "I could get aboot to fail to read either the /etc/aboot.conf file or the kernel images if they were too far into the 20GB partition."
