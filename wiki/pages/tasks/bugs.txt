==== How to report a bug ====

The right place for a report depends on where the bug is. When in doubt, a message to the list for the project, or to linux-alpha@vger.kernel.org, is a good start: someone there can usually say where it belongs.

^ Bug in ^ Report to ^
| The kernel | linux-alpha@vger.kernel.org, with the Alpha maintainers on Cc. See [[documentation:kernel#reporting_bugs|Kernel: Reporting bugs]] |
| GCC | [[https://gcc.gnu.org/bugzilla/|GCC Bugzilla]], with the target set to ''alpha-linux-gnu'' |
| glibc, binutils | [[https://sourceware.org/bugzilla/|Sourceware Bugzilla]], with the host set to ''alpha*-*-linux-gnu'' |
| A Gentoo package | [[https://bugs.gentoo.org/|Gentoo Bugzilla]], with ''alpha@gentoo.org'' on Cc |
| A Debian package | The Debian bug tracking system, with ''reportbug''. Add the user tag with ''User: debian-alpha@lists.debian.org'' and ''Usertags: alpha'' pseudo-headers, and send a copy to the debian-alpha list with ''X-Debbugs-Cc'' |
| QEMU's Alpha emulation | The [[https://gitlab.com/qemu-project/qemu/-/issues|QEMU issue tracker]]. Include the full command line and QEMU version |
| Other software | The software's own tracker. If the bug is Alpha-specific, include the output of ''uname -a'' and the CPU from ''/proc/cpuinfo'' |

A useful report says which system and processor the bug happens on, since behavior can differ between an EV56 and an EV67 system, and whether it also happens under [[documentation:qemu|QEMU]]. For a crash, the kernel log, and for a failed build, the full build log. Some common symptoms have well-known causes; see the [[:faq|FAQ]] for "unaligned trap" messages, "Illegal instruction", and "relocation truncated to fit".
