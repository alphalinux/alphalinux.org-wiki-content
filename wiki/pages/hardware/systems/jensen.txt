The Jensen is an EISA system with a 150 MHz 21064. The DECpc AXP 150 and DEC 2000 AXP differ only in their bundled software. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)] The DEC 2000 Model 500 was code-named Culzean. [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, p. D-2)]

==== Specifications ====

  * [[wp>Alpha_21064|21064]] at 150 MHz [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)], given in Digital's specification table as the "DECchip 21064 (EV4 P2 or P3)"; 1 MiB of boot and diagnostic firmware ROM; 16 MiB of DRAM expandable to 128 MiB [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, EK-A0636-TM.001, p. E-2)]
  * EISA only: it was the only Alpha platform in the kernel without PCI [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/sys_jensen.c?h=v6.9|arch/alpha/kernel/sys_jensen.c]], Linux 6.9)], and apart from a few VME OEM boards the only Alpha system Digital built without PCI [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/alphant-mbox/1996-February.mbox#L4643|"RE: Re[2]: Win/NT on AXP 3000-300LX?"]], James Livingston, alphant, 15 Feb 1996)]
  * No dense memory space, only sparse [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-May.mbox#L13068|"Re: Beta Xservers based on 3.1.2E for the Alpha"]], Jay Estabrook, axp-list, 19 May 1996)]
  * The real-time clock is a PC part at a non-standard address, one of several unusual features of the Jensen I/O subsystem [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-May.mbox#L6117|"Re: /dev/rtc on Jensen?"]], Linus Torvalds, axp-list, 8 May 1996)]
  * Memory goes in eight connectors on the system module, grouped in two banks. A memory option consists of four memory modules, every connector in a bank must be filled, the two module types must not be mixed within a bank, and bank 0 must always hold an option. The only options were 16 MiB and 64 MiB, and the DEC 2000 Model 300 AXP required at least 32 MiB. [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, pp. 12-6 to 12-7)] See Conflicting information.
  * The deskside DECpc AXP 150 and DEC 2000 Model 300 have one keyboard port, one mouse port, two serial ports, one parallel port, and six EISA connectors; the pedestal DEC 2000 Model 500 has one serial port and no keyboard or mouse port in its specification table, the same six EISA slots, and weighs 54 kg against the 21 kg of the deskside box. [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, p. E-2)] [(>{{wiki:hardware:systems:dec_2000:dec_2000_model_500_customer_technical_information.pdf?linkonly|DEC 2000 Model 500 AXP Customer Technical Information}}, EK-A0676-TM.001, p. E-2)]
  * SCSI bus letters follow EISA slot order, with bus letter A assigned to the SCSI adapter in the lowest-numbered EISA slot, and the console's ''SET SCSI_{A | B}'' command sets each adapter's host ID. [(>{{wiki:hardware:systems:dec_2000:dec_2000_model_500_customer_technical_information.pdf?linkonly|DEC 2000 Model 500 AXP Customer Technical Information}}, p. 11-6)]

==== Firmware ====

Which console the machine runs is held in the ''OS_TYPE'' environment variable, whose values are ''VMS'', ''OSF'', and ''NT'', and which can be changed from either console. A second variable, ''AUTO_ACTION'', sets the power-up action (''RESTART'', ''HALT'', or ''BOOT'') and applies only to OpenVMS and OSF/1. [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, p. 1-2)] Linux needs the OSF console. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)]

From SRM, ''SET OS_TYPE NT'' followed by <key>C-p</key> or the halt button brings up the ARC "Boot menu", which identifies itself as "ARC Multiboot DEC Version n.nn". [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, pp. 1-6 to 1-7)] Going back is a menu walk rather than a command: Supplementary menu, Set up the system, "Switch to OpenVMS or OSF console", then the reboot selection menu, and finally a full power cycle with a 15 second wait. [(>{{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, pp. 1-8 to 1-9)]

There are separate EISA Configuration Utilities for Windows NT and for OpenVMS and OSF/1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-August.mbox#L3273|"Re: Installing OSF/1 on axp-150 pc (HELP!)"]], Wilko Bulte, comp.unix.osf.osf1, 25 Aug 1994)]

==== Linux ====

Linux 6.9 was the last version to support the Jensen, with ''CONFIG_ALPHA_JENSEN''; Linux 6.10 removed support for processors older than the EV56 (21164A). [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] The Jensen needs its own kernel and cannot boot a generic kernel image. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-May.mbox#L8369|"Re: Debian on Alpha DEC 2000 AXP"]], Falk Hueffner, debian-alpha, 11 May 2002)]

There is no MILO for the Jensen, so Linux runs under the OSF PALcode of the SRM console. The disk is prepared from the ARC console, which can read the floppy drive, and the kernel is then booted from SRM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)] Early versions of aboot required firmware version 1.7 (see Conflicting information). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-November.mbox#L37622|"Re: Error received Installing RedHat AXP150"]], Jim Paradis, axp-list, 21 Nov 1996)]

==== History ====

The machine was developed by the group that designed the 21064, through the Beta and Theta demonstration systems, as a low-cost PC-style design whose base system deliberately contained little, leaving most capabilities to ISA and EISA option cards. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-articles-mbox/googlegroups-1994-June.mbox#L7939|"The Evolution of the Alpha AXP PC"]], David G. Conroy, Thomas E. Kopec, and Joseph R. Falcone, Digital Technical Journal, biz.digital.articles, 7 Jun 1994)] Olivetti sold a rebadged version as the R7-600. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L2952|"RE: How to complete a Jensen system..."]], Jay Estabrook, axp-list, 10 Mar 1996)]

The Jensen was the first machine to run Alpha/Linux, initially with a 32-bit kernel, followed by the Avanti (AlphaStation 400). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-July.mbox#L572|"first Linux port"]], Jay Estabrook, axp-list, 13 Jul 2006)]

==== Conflicting information ====

The following sources conflict with each other or with the account given above. They are listed here for further investigation.

  * **Jensen firmware needed for Linux**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-December.mbox#L16885|"VGA problems in a Jensen, was: Re: headless boot"]], Martin Ostermann, axp-list, 11 Dec 1996: "make sure you got v1.7 disks to switch back, because aboot doesn't work with later versions."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-June.mbox#L2006|"Re: Installing linux on axp150"]], Sebastian Moeller, axp-list, 3 Jun 2000: "IIRC v1.7 is only required for the ELSA Winner 1000 ISA/EISA (twinbus)"
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-February.mbox#L19873|"RE: Downgrade firmware"]], H.C.vanderVegt@DTO.TUDelft.nl, axp-list, 20 Feb 2001: "the old aboot till 0.5 needs rom version 1.7 and the new aboot 0.7 supports the new roms (not official)"
  * **Memory modules per bank**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008: the Jensen and Noname "had only 64-bit mem bus, and thus required SIMMS in pairs, not quartets".
    * {{wiki:hardware:systems:dec_2000:decpc_axp_150_dec_2000_model_300_customer_technical_information.pdf?linkonly|DECpc AXP 150 and DEC 2000 Model 300 AXP Customer Technical Information}}, pp. 12-6 to 12-7: "A memory option consists of four memory modules. When you install a memory option in a memory bank, you must install a memory module in all of the connectors in that bank."
