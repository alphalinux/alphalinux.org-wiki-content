===== AlphaServer ES40 (Clipper) =====

The ES40 is a four processor 21264 server, sold in tower, pedestal, and rackmount enclosures. [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_tru64_openvms_catalog.pdf?linkonly|AlphaServer ES40 Tru64 UNIX and OpenVMS}}, Systems and Options Catalog, June 1999, p. 2.1)] Its firmware also covers the ES40cv, ES40lp, TS40, and TS20. [(>{{wiki:software:firmware:alphaserver_es40_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer ES40 V7.3 Firmware Release Notes}}, April 2007, p. 1)] QEMU emulates an ES40 (see [[software:emulators|Emulators]]).

==== Specifications ====

Except where noted, the following comes from the systems and options catalog. [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_tru64_openvms_catalog.pdf?linkonly|AlphaServer ES40 Tru64 UNIX and OpenVMS}}, Systems and Options Catalog, June 1999, p. 2.1)]

  * Up to four 500 MHz [[wp>Alpha_21264|21264]] CPUs with 4 MiB of secondary cache each
  * 21272 (Tsunami) core logic [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.10|arch/alpha/Kconfig]], Linux 6.10)]
  * "Model 1 supports six 64-bit PCI I/O expansion slots and four memory options", and "Model 2 supports ten 64-bit PCI I/O expansion slots and eight memory options"
  * Memory options are sets of four DIMMs; each memory array must use one DIMM type, because the stacked and monolithic MS610-DA and MS610-EA options share part numbers but are "NOT interchangeable" [(>{{wiki:software:firmware:alphaserver_es40_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer ES40 V7.3 Firmware Release Notes}}, April 2007, p. 29)]
  * The Model 2 has 32 DIMM slots. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2000-September.mbox#L10316|"SUMMARY: How to determine DIMM configuration on ES40"]], Kevin Dea, tru64-unix-managers, 20 Sep 2000)] The console configures memory four-way interleaved when all four arrays hold the same size, and two-way plus one separate array when three do. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2001-August.mbox#L12096|"SUMMARY: Memory interleaving"]], Peter Stern, tru64-unix-managers, 22 Aug 2001)]
  * 1.44 MB floppy drive, CD-ROM, two EIA-232 serial ports, one bidirectional enhanced parallel port, a dedicated serial port for the remote management console (RMC), keyboard and mouse ports
  * Up to two internal disk drive cages, each with a one-port Ultra2 SCSI adapter and four 3.5-inch disks; StorageWorks shelves are also supported

==== Console heap resizing ====

The SRM console sizes its own heap for the installed options, and a machine with enough cards in it goes through a visible crash and reboot cycle the first time. The drivers fail to allocate heap space, the console prints "CPU0: insufficient dynamic memory for a request of 4592 bytes / Console heap space will be automatically increased in size by 64KB", takes an exception, and restarts with the larger heap; this "can occur several times until the console has allocated enough memory", after which no further action is needed. ''show heap_expand'' confirms the new size, and ''set heap_expand none'' puts it back to the default, which is worth doing after a configuration change. [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_release_notes.pdf?linkonly|AlphaServer ES40 Release Notes}}, EK-ES240-RN.B01, June 1999, pp. 3-4)]

Two slot restrictions come with the release notes: a KZPAC RAID controller under OpenVMS "must be installed in a slot on PCI bus 1. It cannot be installed on PCI bus 0", and under Tru64 UNIX "multifunction PCI options cannot be installed in PCI bus 0, slot 1 or slot 2", which at the time meant the KZPCM-DA SCSI and Ethernet combination card and the DE504-BA quad Ethernet adapter. In the field, an ES40 with two KZPCM-DA cards on hose 0 would not boot the Tru64 V4.0E or V4.0F installation CD until the cards were moved to hose 1. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2000-February.mbox#L21524|"SUMMARY: booting OS CDs (4.0e & 4.0f) on an ES40"]], Charlotte Barsby, tru64-unix-managers, 9 Feb 2000)] The notes also correct the owner's guide on leaving Windows NT for SRM (shut down, press Reset, then press Halt) and on a fan fault message, where "Fan 5, 6 failed" means the main fan (6) and the redundant fan (5). [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_release_notes.pdf?linkonly|AlphaServer ES40 Release Notes}}, pp. 9-10)]

==== Linux ====

  * "THere is no MILO for ES40 - you MUST use SRM console." Red Hat 7.0 "will NOT install with more than 2GB of memory, unless you add "memsize=2G" to the boot command flags." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L10001|"Re: HELP Linux on ES40"]], Jay Estabrook, axp-list, 10 Jul 2001)] See also [[hardware:systems#tsunami_systems|Tsunami Systems]].
  * "ES40's are very sensitive to how memory is inserted. It is easy to get a bad connection." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-July.mbox#L11473|"Re: 630/670 machine checks on SMP's"]], Phillip Ezolt, axp-list, 28 Jul 2000)]

==== Firmware ====

  * The SRM console treats Linux as a first-class operating system on the ES40: ''os_type'' takes ''unix'', ''vms'', or ''linux'', and setting it to ''linux'' starts the SRM firmware at power-up or reset. [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_user_interface_guide.pdf?linkonly|AlphaServer ES40 and AlphaStation ES40 User Interface Guide}}, EK-ES240-UI.B01, p. 2-78)] An HP engineer later said otherwise; see [[software:firmware:srm#conflicting_information|SRM Console]].
  * The manual gives the per-distribution boot settings: ''boot_file'' is ''2/boot/vmlinux.gz'' for Red Hat and ''2/boot/vmlinuz'' for SuSE, and ''boot_osflags'' takes the root device and run level, as in ''set boot os_flags "root=/dev/sda2 1 rw"'' for Red Hat single-user mode with read and write privileges. [(>{{wiki:hardware:systems:alphaserver_es40:alphaserver_es40_user_interface_guide.pdf?linkonly|AlphaServer ES40 and AlphaStation ES40 User Interface Guide}}, pp. 2-51 to 2-53)]
  * "Only one VGA graphic controller card, that is VGA-Enabled, is supported in PCI0 bus slots", and removing the mouse at the SRM console "will prevent any response from the keyboard (until the mouse is plugged back in)." [(>{{wiki:software:firmware:alphaserver_es40_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer ES40 V7.3 Firmware Release Notes}}, April 2007, p. 20)]
  * A failed update to SRM V5.8 could leave a TIG error on the operator control panel. Michael Renda of Compaq gave a recovery that avoids replacing the system board: remove MMB1 and move jumper J21, to its upper right, to position 2-3, which "will force loading the TIG NVRAM from the serial rom". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2000-September.mbox#L15269|"SUMMARY: firmware 5.8 on ES40 ==> motherboard damage"]], Emanuele Lombardi, tru64-unix-managers, 14 Sep 2000)]
  * Some ES40s shipped with jumper J31 in position 1-2 rather than the documented default of 2-3, which made COM1 unreachable through the RMC's modem port; J31 is not described in the owner's guide. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/2000-November.mbox#L4684|"SUMMARY: COM1/modem port on ES40"]], Nikita Schmidt, tru64-unix-managers, 27 Nov 2000)]
  * SRM V5.6 added "an X86 bios emulator" to support the KZPCC-CE RAID controller (see [[hardware:other|Other Hardware]]). [(>{{wiki:software:firmware:alphaserver_es40_v7.3_firmware_release_notes.pdf?linkonly|AlphaServer ES40 V7.3 Firmware Release Notes}}, April 2007, p. 38)]
