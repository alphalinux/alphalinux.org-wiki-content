The UP1000 is a motherboard built by Samsung and Alpha Processor, Inc. (API), later API NetWorks, and introduced in late 1999. [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}}, p. iii)]

==== Specifications ====

  * 600 MHz EV67 with 2 MiB L2 cache or 700 MHz EV67 with 4 MiB L2 cache, L2 cache bandwidth 3.2 GiB/s [(>{{wiki:hardware:motherboards:up1000:up1000_spec_sheet.pdf?linkonly|UP1000 Spec Sheet}}, Alpha Processor, Inc. and Samsung Electronics, January 2000)]
  * AMD-751 Chipset, ALi M1543C south bridge
  * 3x 168-pin DIMMs, supports 64 MiB to 768 MiB of ECC unbuffered PC100 SDRAM
  * 1x AGP 2x (see [[#known_issues|Known issues]])
  * 4x 33 MHz 32-bit PCI slots
  * 2x ISA slots [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}})]
  * 2x Ultra DMA33 IDE connectors, a floppy controller, 2x serial ports, a parallel port, PS/2 keyboard and mouse, and 2x USB ports, all provided by the M1543C [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}}, p. 1-1)]
  * 2 MiB flash ROM
  * ATX form factor, 12 in x 9.6 in (30.48 cm x 24.38 cm)

==== Firmware ====

Initial shipments of the UP1000 came with AlphaBIOS only [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-November.mbox#L16749|"RE: UP1000 & UP2000 Installation."]], Tom Morris, axp-list, 6 Nov 1999)], and Linux was booted from AlphaBIOS using APB, which needs kernels built with the legacy start address (see [[documentation:kernel#kernel_start_address|Kernel]]). API released SRM for the UP1000 in May 2000. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-June.mbox#L412|"Re: SRM For the UP1000?"]], Rich Payne, axp-list, 1 Jun 2000)] There is no MILO for Nautilus systems. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L9754|"Re: Upgrading to RedHat 7.1 on UP1000"]], Rich Payne, axp-list, 9 Apr 2002)]

SRM is installed using the Alpha Diagnostic Environment (ADE), a firmware maintenance console unique to API boards that is invoked by a jumper. The SRM package contains three images (two ADE images and the SRM console) that are flashed over AlphaBIOS. To return to AlphaBIOS, the SRM console image is overwritten with ''nautilus.rom''. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L11016|"Re: Upgrading to RedHat 7.1 on UP1000"]], Rich Payne, axp-list, 10 Apr 2002)]

The UP1000 and UP1100 SRM images are different revisions and cannot be used on each other's boards. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L30608|"Re: 2.40test10 working?"]], Rich Payne, axp-list, 17 Nov 2000)]

The [[https://github.com/alphalinux/firmware/tree/master/api/UP1000|alphalinux/firmware]] repository keeps API's UP1000 firmware: ''up1000_srm_5.6_beta.zip'', the May 2000 package that replaces AlphaBIOS with SRM console A5.6-4.1-9 and adds the fail-safe recovery modules, and ''nautilus.rom'' for AlphaBIOS. [(>''install.txt'' and ''readme.1st'' in [[https://github.com/alphalinux/firmware/blob/master/api/UP1000/up1000_srm_5.6_beta.zip|up1000_srm_5.6_beta.zip]], alphalinux/firmware repository)] The package's instructions start ADE by setting jumper J43 (Recover Firmware); the manual's Reload ADE setting also moves J42 to 1-2 (see [[#firmware_recovery|Firmware recovery]]). The instructions then load each of the three images from floppy and write it to flash with ADE's ''burn'' command. [(>''install.txt'' in [[https://github.com/alphalinux/firmware/blob/master/api/UP1000/up1000_srm_5.6_beta.zip|up1000_srm_5.6_beta.zip]], alphalinux/firmware repository)] Which SRM release was the last for the UP1000 is unclear; see [[#conflicting_information|Conflicting information]].

==== Firmware recovery ====

Six jumpers (J42, J43, J44, J15, J16, and J37) select the firmware recovery modes. Each is a 3-pin header; by default all six have the shunt on pins 2 and 3 (pin 1 is nearest the board edge). [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}}, pp. 2-8, 5-4)]

^ Mode ^ J42 ^ J43 ^ Use ^
| Normal boot (default) | 2-3 | 2-3 | |
| Restore factory defaults | 1-2 | 2-3 | Firmware settings that prevent booting, or a forgotten password |
| Reload ADE | 1-2 | 1-2 | Flash left corrupt by an interrupted firmware upgrade |

J44, J15, J16, and J37 stay on pins 2 and 3. The shunts are returned to the default positions after the recovery. [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}}, pp. 5-4 to 5-5)] Jumpers J38, J41, J45, J50, and J51 and switch block SW4, which set the SROM format and the clocks, must be left at their factory settings. [(>{{wiki:hardware:motherboards:up1000:up1000_user_manual.pdf?linkonly|UP1000 User Manual}}, pp. 2-9 to 2-10)]

==== Linux ====

Current kernels support the UP1000 with ''CONFIG_ALPHA_NAUTILUS'' or a generic kernel; it boots from SRM with [[software:boot_loaders:aboot|aboot]]. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v7.3-rc1|arch/alpha/Kconfig]], Linux 7.3)] The onboard devices use these drivers:
  * IDE (ALi M1543C): ''pata_ali'' [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/ata/pata_ali.c?h=v7.3-rc1|drivers/ata/pata_ali.c]], Linux 7.3)]
  * USB (the M1543C's M5237 OHCI controller): ''ohci-pci'' [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/usb/host/pci-quirks.c?h=v7.3-rc1|drivers/usb/host/pci-quirks.c]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/usb/host/ohci-pci.c?h=v7.3-rc1|drivers/usb/host/ohci-pci.c]], Linux 7.3)]
  * System management: an ADM9240 on the M1543C's SMBus monitors the supply voltages and fan speeds, [(>{{wiki:hardware:motherboards:up1000:up1000_technical_reference_manual.pdf?linkonly|UP1000 Technical Reference Manual}}, p. 4-8)] and is handled by the ''adm9240'' driver, with ''i2c-ali15x3'' for the SMBus. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/hwmon/adm9240.c?h=v7.3-rc1|drivers/hwmon/adm9240.c]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/i2c/busses/i2c-ali15x3.c?h=v7.3-rc1|drivers/i2c/busses/i2c-ali15x3.c]], Linux 7.3)]

  * The UP1000 has an LM75 temperature sensor. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L16086|"RE: UP2000 Temperature"]], Rich Payne, axp-list, 24 May 2000)] A well cooled UP1000 has a heatsink temperature of about 45 to 50 C. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L16402|"Re: UP2000 Temperature"]], Maurice Hilarius, axp-list, 24 May 2000)]

==== Known issues ====

  * The IDE controller's DMA engine cannot perform 48-bit LBA transfers on ALi revisions before C5, so the ''pata_ali'' driver uses PIO for accesses beyond the first 128 GiB of a disk. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/ata/pata_ali.c?h=v7.3-rc1|drivers/ata/pata_ali.c]], Linux 7.3)]
  * The AGP slot of the UP1000, UP1100, and UP1500 operates only as a PCI slot. Alpha is fully cache coherent and provides no non-cacheable mappings or software cache flushing, which the x86 AGP support in Linux depends on for native AGP transfers.
  * The AMD-751 can address at most 768 MiB of memory. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-March.mbox#L30727|"Re: UP1100 delivery problems"]], Rich Payne, axp-list, 26 Mar 2002)]
  * ATI Rage II and Rage Pro based video cards do not work in the UP1000 or [[hardware:motherboards:up1100|UP1100]], although they work in the UP2000 and DP264. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L17091|"Re: (no subject)"]], Maurice Hilarius, axp-list, 22 Aug 2000)]
  * The BIOS emulator in the UP1000 and UP1100 SRM firmware is older than the one in the UP1500's firmware. No AGP Radeon card has been made to work with it on a UP1100. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2003-December.mbox#L2218|"Re: PCI Video Card?"]], Jay Estabrook, debian-alpha, 4 Dec 2003)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-April.mbox#L2650|"AW: Some observations regarding FC* on UP2000+"]], Jay Estabrook, axp-list, 24 Apr 2008)]

==== History ====

Samsung developed the UP1x00 family of boards, while API took over development of the UP2000. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L6772|"RE: Samsung EV69"]], Maurice Hilarius, axp-list, 8 Aug 2002)]
