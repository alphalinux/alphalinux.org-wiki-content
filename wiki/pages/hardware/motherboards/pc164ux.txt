The AlphaPC 164UX is an ATX form factor motherboard based on the EV56 (21164A) microprocessor and the 21174 core logic chip. It was designed by DeskStation Technology under the code name "Ruffian", which is also the name of its Linux platform. It can only boot Linux through MILO, and no current kernel has been reported to boot on it; see [[#linux|Linux]].

==== Specifications ====

  * Alpha 21164A CPU at 466, 533, or 600 MHz, the same CPUs as the [[hardware:motherboards:pc164lx|AlphaPC 164LX]]; the clock is selected by jumpers [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}})]
  * 2 or 4 MiB onboard L3 backup cache (synchronous SSRAM)
  * 21174 core logic chip
  * 6x 168-pin DIMMs (three banks), supports 32 MiB to 1.5 GiB of unbuffered ECC SDRAM. The manual's specifications give 3 GiB, but its configuration table ends at 1.5 GiB with 256 MiB DIMMs, [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}, pp. 10, 34)] and 1.5 GiB is the largest configuration reported in use. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-1999-April.mbox#L6572|"Re: HELP! 1GB on 164UX-4"]], Michael Müller, comp.os.linux.alpha, 24 Apr 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-May.mbox#L1680|"Problems on Ruffian ??"]], Peter Biechele, debian-alpha, 1 Jun 1999)]
  * 1x 33 MHz 64-bit PCI slot
  * 5x 33 MHz 32-bit PCI slots
  * 1x ISA slot
  * DEC 21052 PCI-to-PCI bridge
  * Intel 82371SB PCI-to-ISA bridge and EIDE
  * DEC 21143 10/100 Mbit Ethernet
  * Symbios 53C875 Ultra Wide SCSI controller
  * SMC FDC37C666 Super I/O controller (floppy, 2x serial, parallel)
  * PS/2 keyboard and mouse
  * 1 MiB flash ROM
  * DeskStation ARCSBIOS firmware (for Windows NT)
  * ATX board, 30.48 cm x 24.38 cm (12.0 in x 9.6 in), with mounting holes to the ATX 2.01 specification; the board exceeds the ATX height limits at the CPU and at the SCSI connectors [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}, p. 14)]

==== AlphaPC 164BX ====

The AlphaPC 164BX is the same board as the 164UX, except that it lacks the Ethernet and Ultra Wide SCSI controllers and has only a 2 MiB L3 cache.

==== Firmware ====

The only firmware for the board is DeskStation's ARCSBIOS, which is distinct from both ARC and AlphaBIOS. No SRM console or AlphaBIOS was ever released for it, so operating systems and installers that require SRM cannot be used. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L29483|"Re: AlphaBios vs SRM"]], Rich Payne, axp-list, 15 Sep 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)]

  * ARCSBIOS updates are flashable, and the last versions (a few Y2K updates) were distributed by API, which never had the ARCSBIOS sources. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-September.mbox#L3760|"Re: Dekstation Raptor Reflex"]], Rich Payne, debian-alpha, 14 Sep 2000)]
  * There is no flash management utility for loading MILO into the flash ROM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L2209|"Re: Flash management utility for ruffian?"]], Jay Estabrook, axp-list, 2 May 1999)]

==== Linux ====

Current kernels include support for the board (''CONFIG_ALPHA_RUFFIAN'', or a generic kernel), [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v7.3-rc1|arch/alpha/Kconfig]], Linux 7.3)] but it can only boot Linux through [[software:boot_loaders:milo|MILO]], and Linux 2.6.22.19 is the last kernel reported to boot on it; 2.6.23 was the first that did not. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2010-August.mbox#L709|"kernel regression on 164UX"]], Ian Las, debian-alpha, 3 Aug 2010)] The cause is the PT_NOTE program header that Linux 2.6.23 added to the kernel image, which MILO mistook for a loadable segment. A MILO fix was committed in May 2026, but has not yet been tested on a 164UX. [(>[[https://github.com/alphalinux-org/milo/commit/7a6701b734208c4fd36bb628996b32f811f6542a|"boot: skip non-PT_LOAD segments when loading kernel image"]], Matt Turner, MILO, 31 May 2026)]

ARCSBIOS starts MILO through a DeskStation-specific loader, ''ldmilo.exe''; the ''linload.exe'' used on AlphaBIOS systems does not work, because ARCSBIOS has its own console application interface. The version of ''ldmilo.exe'' later rebuilt by DEC works much like ''linload.exe'', except that the MILO image must be named ''milo''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-January.mbox#L43156|"Re: DeskStation/Ruffian booting methods"]], Jay Estabrook, axp-list, 18 Jan 1999)]

  * ''ldmilo.exe'', MILO, and the PALcode go on a small FAT partition, and an ARCSBIOS boot entry points ''OsLoader'' at ''ldmilo.exe'' and passes MILO commands in ''OsLoadOptions''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L17406|"Problem booting Samsung 164UX ("Ruffian") MB"]], Ivor Dvorecky, axp-list, 18 Oct 1998)]
  * Use a Ruffian MILO based on MILO 2.2-18 or later, such as those released in May 2002; earlier MILO versions hang when loading 2.4 kernels or on reboot. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L9610|"milo on ruffian does not like kernel 2.4.x"]], Ingo T. Storm, axp-list, 18 Dec 2001)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L492|"XLT-PC164-Ruffian MILOs available for test"]], Jay Estabrook, axp-list, 1 May 2002)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L1679|"Re: XLT-PC164-Ruffian MILOs available for test"]], Ingo T. Storm, axp-list, 2 May 2002)]
  * The board cannot boot from CD-ROM, only from floppy or a FAT partition on a hard disk. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2007-December.mbox#L616|"Re: Debian Etch on Samsung 164UX/BX Alpha"]], Lennart Sorensen, debian-alpha, 6 Dec 2007)] Current distribution installers, which boot from SRM, cannot be used.

==== Known issues ====

  * **Onboard Ethernet:** the 21143 often fails to auto-negotiate, particularly at 100 Mbit. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L2303|"Re: ruffian ether problems"]], Rich Payne, debian-alpha, 9 Dec 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L10904|"Re: Ruffian & 100Mbit/s"]], Stig Telfer, axp-list, 16 Oct 2000)] Forcing the media type (for example ''options tulip options=14'' for MII 100baseTx full duplex) may help. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L12835|"Re: Ruffian & 100Mbit/s"]], Michal Jaegermann, axp-list, 18 Oct 2000)]
  * **Memory:** boards with four DIMMs are sensitive to the choice of modules, because the 21174 does not drive the memory lines to the JEDEC standard; the [[hardware:motherboards:pc164lx|AlphaPC 164LX]], which uses the same chipset, is affected in the same way. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36191|"Re: UX4 memory problem"]], Brian Rerecich, axp-list, 23 Apr 1999)] Hard Data shipped UX systems with up to 1.5 GiB using selected modules. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36524|"Re: UX4 memory problem"]], Maurice Hilarius, axp-list, 23 Apr 1999)]
  * **PCI slots:** the onboard SCSI controller is behind the 21052 PCI-to-PCI bridge. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L3095|"Re: ruffian ether problems"]], Ron Farrer, debian-alpha, 13 Dec 2000)] A VGA card used as the console must be in the single 64-bit slot, in front of the bridge. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-June.mbox#L26949|"Re: Installing Linux on AlphaPC 164UX"]], Jay Estabrook, axp-list, 12 Jun 1998)]

==== History ====

DeskStation Technology designed the board and its firmware, and sold it as the Ruffian RPX164-2. DeskStation ported Linux to it in 1997, while prototypes were already running Windows NT at 633 MHz. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L2762|"Re: Deskstation Ruffian compatibility"]], Dean Hall, axp-list, 3 Jul 1997)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L34773|"Ruffian port status"]], Dean Hall, axp-list, 30 Jul 1997)]

Around late 1997, the rights to the design and to the ARCSBIOS firmware were bought by Samsung, which set up its Alpha subsidiary Alpha Processor, Inc. (API) in 1998, and the board was renamed AlphaPC 164UX/BX. [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}, Samsung, 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-November.mbox#L10168|"Re: clarification of board"]], Maurice Hilarius, axp-list, 4 Nov 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-July.mbox#L5925|"Re: What happened to Deskstation?"]], Jay Estabrook, axp-list, 20 Jul 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L6772|"RE: Samsung EV69"]], Maurice Hilarius, axp-list, 8 Aug 2002)] Samsung boards are labeled UX2 and UX4 after their L3 cache size. The cache chips are soldered to the board, so a 2 MiB board cannot be upgraded to 4 MiB. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L41654|"Re: (no subject)"]], Rich Payne, axp-list, 22 Dec 1999)]
