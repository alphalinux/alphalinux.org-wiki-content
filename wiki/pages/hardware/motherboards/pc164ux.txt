===== PC164UX / PC164BX =====

The AlphaPC 164UX is an ATX form factor motherboard based on the Alpha 21164 microprocessor and the 21174 core logic chip. It was designed by DeskStation Technology under the code name "Ruffian", which is also the name of its Linux platform.

==== Specifications ====

  * Alpha 21164 CPU, 300 to 800 MHz (selected by jumpers) [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}})]
  * 2 or 4 MiB onboard L3 backup cache (synchronous SSRAM)
  * 21174 core logic chip
  * 6x 168-pin DIMMs (three banks), supports 32 MiB to 3 GiB of unbuffered ECC SDRAM
  * 1x 33 MHz 64-bit PCI slot
  * 5x 33 MHz 32-bit PCI slots
  * 1x ISA slot
  * DEC 21052 PCI-to-PCI bridge
  * Intel 82371SB PCI-to-ISA bridge and EIDE
  * DEC 21143 10/100 Mbit Ethernet
  * Symbios 53C875 Ultra Wide SCSI controller
  * SMC FDC37C666 Super I/O controller (floppy, 2x serial, parallel)
  * PS/2 keyboard and mouse
  * 1 MiB flash ROM
  * DeskStation ARCSBIOS firmware (for Windows NT)

{{anchor:pc164bx}}
==== PC164BX ====

The AlphaPC 164BX is the same board as the 164UX, except that it lacks the Ethernet and Ultra Wide SCSI controllers and has only a 2 MiB L3 cache.

==== History ====

DeskStation Technology designed the board and its firmware, and sold it as the Ruffian RPX164-2. DeskStation ported Linux to it in 1997, while prototypes were already running Windows NT at 633 MHz [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L2762|"Re: Deskstation Ruffian compatibility"]], Dean Hall, axp-list, 3 Jul 1997)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L34773|"Ruffian port status"]], Dean Hall, axp-list, 30 Jul 1997)].

Around late 1997, Samsung and Alpha Processor, Inc. (API) bought the rights to the design and to the ARCSBIOS firmware, and the board was renamed AlphaPC 164UX/BX [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-November.mbox#L10168|"Re: clarification of board"]], Maurice Hilarius, axp-list, 4 Nov 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-July.mbox#L5925|"Re: What happened to Deskstation?"]], Jay Estabrook, axp-list, 20 Jul 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L6772|"RE: Samsung EV69"]], Maurice Hilarius, axp-list, 8 Aug 2002)]. Samsung boards are labeled UX2 and UX4 after their L3 cache size. The cache chips are soldered to the board, so a 2 MiB board cannot be upgraded to 4 MiB [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L41654|"Re: (no subject)"]], Rich Payne, axp-list, 22 Dec 1999)].

==== Firmware ====

The only firmware for the board is DeskStation's ARCSBIOS, which is distinct from both ARC and AlphaBIOS. No SRM console or AlphaBIOS was ever released for it, so operating systems and installers that require SRM cannot be used [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L29483|"Re: AlphaBios vs SRM"]], Rich Payne, axp-list, 15 Sep 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)].

  * ARCSBIOS updates are flashable, and the last versions were distributed by API [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)]. Samsung released a few updates for Y2K, but API never had the ARCSBIOS sources [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-September.mbox#L3760|"Re: Dekstation Raptor Reflex"]], Rich Payne, debian-alpha, 14 Sep 2000)].
  * One user reported that the 3.0.60 and 3.0.61 images from DeskStation left a Samsung board booting into the fail-safe ARCSBIOS, and that API's 3.0.61 image fixed it [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L48501|"RE: problem with firmware on a samsung 164ux board - help!"]], Paul Jakma, axp-list, 30 Apr 1999)].
  * There is no flash management utility for loading MILO into the flash ROM [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L2209|"Re: Flash management utility for ruffian?"]], Jay Estabrook, axp-list, 2 May 1999)].

==== Booting Linux ====

Linux is booted with MILO, which ARCSBIOS starts through a DeskStation-specific loader, ''ldmilo.exe''. The ''linload.exe'' used on AlphaBIOS systems does not work, because ARCSBIOS has its own console application interface. The ''ldmilo.exe'' later rebuilt by DEC works almost like ''linload.exe'', except that the MILO image must always be named ''milo'' [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-January.mbox#L43156|"Re: DeskStation/Ruffian booting methods"]], Jay Estabrook, axp-list, 18 Jan 1999)].

  * ''ldmilo.exe'', MILO, and the PALcode go on a small FAT partition, and an ARCSBIOS boot entry points ''OsLoader'' at ''ldmilo.exe'' and passes MILO commands in ''OsLoadOptions'' [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L17406|"Problem booting Samsung 164UX ("Ruffian") MB"]], Ivor Dvorecky, axp-list, 18 Oct 1998)].
  * ARCSBIOS is strict about the FAT boot sector. Partitions made on Alpha with ''mkdosfs'' of the time failed with "Not enough memory to load program", because ''mkdosfs'' used ''unsigned long'' (8 bytes on Alpha) for 4-byte boot sector fields. A ''mkdosfs'' with that bug fixed produces a bootable partition [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L2949|"Re: Problem booting Samsung 164UX ("Ruffian") MB - SOLUTION!"]], Andreas Haumer, axp-list, 11 Oct 1998)].
  * Early MILOs only worked with the video card in the slot closest to the memory [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L17749|"Re: Problem booting Samsung 164UX ("Ruffian") MB"]], Maurice Hilarius, axp-list, 18 Oct 1998)]. Later Ruffian MILOs removed this restriction [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L2669|"Re: Ruffian 64bit pci ?"]], Maurice Hilarius, axp-list, 4 Oct 2000)].
  * MILO 2.2-17 hangs when loading 2.4 kernels, and 2.2-18 loads them but hangs on reboot [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L9610|"milo on ruffian does not like kernel 2.4.x"]], Ingo T. Storm, axp-list, 18 Dec 2001)]. In May 2002, Jay Estabrook released test MILOs for Ruffian based on Stefan Reinauer's MILO 2.2-18, with support for ext2 filesystems larger than about 2 GiB [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L492|"XLT-PC164-Ruffian MILOs available for test"]], Jay Estabrook, axp-list, 1 May 2002)]. A user reported that this MILO reboots cleanly [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L1679|"Re: XLT-PC164-Ruffian MILOs available for test"]], Ingo T. Storm, axp-list, 2 May 2002)].
  * The board cannot boot from CD-ROM, only from floppy or a FAT partition on a hard disk. Debian woody was the last Debian release whose installer supported it; an installed system can reportedly be upgraded to newer releases [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2007-December.mbox#L616|"Re: Debian Etch on Samsung 164UX/BX Alpha"]], Lennart Sorensen, debian-alpha, 6 Dec 2007)].

==== Known Issues ====

  * **Onboard Ethernet:** The 21143 is well known for failing to auto-negotiate, particularly at 100 Mbit [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L2303|"Re: ruffian ether problems"]], Rich Payne, debian-alpha, 9 Dec 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L10904|"Re: Ruffian & 100Mbit/s"]], Stig Telfer, axp-list, 16 Oct 2000)]. Forcing the media type (for example ''options tulip options=14'' for MII 100baseTx full duplex) or trying another switch port may help [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L12835|"Re: Ruffian & 100Mbit/s"]], Michal Jaegermann, axp-list, 18 Oct 2000)].
  * **Memory:** Boards with four DIMMs are sensitive to the choice of modules, because the 21174 chipset does not drive the memory lines to the JEDEC standard (as a Compaq core logic engineer explained for the PC164LX, which uses the same chipset) [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36191|"Re: UX4 memory problem"]], Brian Rerecich, axp-list, 23 Apr 1999)]. Hard Data shipped UX systems with up to 1.5 GiB using selected modules [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36524|"Re: UX4 memory problem"]], Maurice Hilarius, axp-list, 23 Apr 1999)]. In 1998, several sites reported paging-related crashes under 2.0.x kernels with 256 MiB or more, while other users had no problems [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L19812|"Re: Unstable Ruffian"]], furio ercolessi, axp-list, 15 Sep 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-December.mbox#L42213|"Re: UX + lots of RAM?"]], Robert Harley, axp-list, 18 Dec 1998)].
  * **Linux 2.4:** The onboard SCSI controller is behind the 21052 PCI-to-PCI bridge [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L3095|"Re: ruffian ether problems"]], Ron Farrer, debian-alpha, 13 Dec 2000)]. Booting 2.4 kernels required fixes to PCI-to-PCI bridge setup and to type 1 PCI configuration space access, which failed randomly on this board, apparently because of timing [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L37511|"ux164 (ruffian) fixes"]], Ivan Kokshaysky, axp-list, 21 Nov 2000)].
  * **Linux 2.6:** One user reported that 2.6.22.19 was the last kernel that booted on a 164UX and that 2.6.23 was the first that did not [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2010-August.mbox#L709|"kernel regression on 164UX"]], Ian Las, debian-alpha, 3 Aug 2010)].
