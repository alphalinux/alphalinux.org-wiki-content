===== PC164UX / PC164BX =====

The AlphaPC 164UX is an ATX form factor motherboard based on the Alpha 21164A microprocessor and the 21174 core logic chip. It was designed by DeskStation Technology under the code name "Ruffian", which is also the name of its Linux platform.

==== Specifications ====

  * Alpha 21164A CPU at 466, 533, or 600 MHz, the same CPUs as the [[hardware:motherboards:pc164lx|PC164LX]]; the clock is selected by jumpers [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}})]
  * 2 or 4 MiB onboard L3 backup cache (synchronous SSRAM)
  * 21174 core logic chip
  * 6x 168-pin DIMMs (three banks), supports 32 MiB to 1.5 GiB of unbuffered ECC SDRAM. The manual's specifications give 3 GiB, but its configuration table ends at 1.5 GiB with 256 MiB DIMMs, [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}, pp. 10, 34)] and 1.5 GiB is the largest configuration reported in use. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-1999-April.mbox#L6572|"Re: HELP! 1GB on 164UX-4"]], Michael Müller, comp.os.linux.alpha, 24 Apr 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-May.mbox#L1680|"Problems on Ruffian ??"]], Peter Biechele, debian-alpha, 1 Jun 1999)]
  * 1x 33 MHz 64-bit PCI slot
  * 5x 33 MHz 32-bit PCI slots
  * 1x ISA slot
  * DEC 21052 PCI-to-PCI bridge
  * Intel 82371SB PCI-to-ISA bridge and EIDE
  * DEC 21143 10/100 Mbit Ethernet
  * Symbios 53C875 Ultra Wide SCSI controller
  * SMC FDC37C666 Super I/O controller (floppy, 2x serial, parallel)
  * PS/2 keyboard and mouse
  * 1 MiB flash ROM
  * DeskStation ARCSBIOS firmware (for Windows NT)

{{anchor:pc164bx}}
==== PC164BX ====

The AlphaPC 164BX is the same board as the 164UX, except that it lacks the Ethernet and Ultra Wide SCSI controllers and has only a 2 MiB L3 cache.

==== History ====

DeskStation Technology designed the board and its firmware, and sold it as the Ruffian RPX164-2. DeskStation ported Linux to it in 1997, while prototypes were already running Windows NT at 633 MHz. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L2762|"Re: Deskstation Ruffian compatibility"]], Dean Hall, axp-list, 3 Jul 1997)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-July.mbox#L34773|"Ruffian port status"]], Dean Hall, axp-list, 30 Jul 1997)]

Around late 1997, the rights to the design and to the ARCSBIOS firmware were bought by Samsung, which set up its Alpha subsidiary Alpha Processor, Inc. (API) in 1998, and the board was renamed AlphaPC 164UX/BX. [(>{{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}, Samsung, 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-November.mbox#L10168|"Re: clarification of board"]], Maurice Hilarius, axp-list, 4 Nov 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-July.mbox#L5925|"Re: What happened to Deskstation?"]], Jay Estabrook, axp-list, 20 Jul 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L6772|"RE: Samsung EV69"]], Maurice Hilarius, axp-list, 8 Aug 2002)] Samsung boards are labeled UX2 and UX4 after their L3 cache size. The cache chips are soldered to the board, so a 2 MiB board cannot be upgraded to 4 MiB. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L41654|"Re: (no subject)"]], Rich Payne, axp-list, 22 Dec 1999)]

==== Firmware ====

The only firmware for the board is DeskStation's ARCSBIOS, which is distinct from both ARC and AlphaBIOS. No SRM console or AlphaBIOS was ever released for it, so operating systems and installers that require SRM cannot be used. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L29483|"Re: AlphaBios vs SRM"]], Rich Payne, axp-list, 15 Sep 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)]

  * ARCSBIOS updates are flashable, and the last versions (a few Y2K updates) were distributed by API, which never had the ARCSBIOS sources. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-January.mbox#L19411|"RE: 164UX: This system is not compatible with Linux/Alpha..."]], Rich Payne, axp-list, 13 Jan 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-September.mbox#L3760|"Re: Dekstation Raptor Reflex"]], Rich Payne, debian-alpha, 14 Sep 2000)]
  * There is no flash management utility for loading MILO into the flash ROM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L2209|"Re: Flash management utility for ruffian?"]], Jay Estabrook, axp-list, 2 May 1999)]

==== Booting Linux ====

Linux is booted with MILO, which ARCSBIOS starts through a DeskStation-specific loader, ''ldmilo.exe''; the ''linload.exe'' used on AlphaBIOS systems does not work, because ARCSBIOS has its own console application interface. The version of ''ldmilo.exe'' later rebuilt by DEC works much like ''linload.exe'', except that the MILO image must be named ''milo''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-January.mbox#L43156|"Re: DeskStation/Ruffian booting methods"]], Jay Estabrook, axp-list, 18 Jan 1999)]

  * ''ldmilo.exe'', MILO, and the PALcode go on a small FAT partition, and an ARCSBIOS boot entry points ''OsLoader'' at ''ldmilo.exe'' and passes MILO commands in ''OsLoadOptions''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L17406|"Problem booting Samsung 164UX ("Ruffian") MB"]], Ivor Dvorecky, axp-list, 18 Oct 1998)]
  * The Ruffian MILOs released by Jay Estabrook in May 2002, based on Stefan Reinauer's MILO 2.2-18, load 2.4 and later kernels, support ext2 filesystems larger than about 2 GiB, and reboot cleanly; earlier MILO versions hang when loading 2.4 kernels or on reboot. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L9610|"milo on ruffian does not like kernel 2.4.x"]], Ingo T. Storm, axp-list, 18 Dec 2001)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L492|"XLT-PC164-Ruffian MILOs available for test"]], Jay Estabrook, axp-list, 1 May 2002)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L1679|"Re: XLT-PC164-Ruffian MILOs available for test"]], Ingo T. Storm, axp-list, 2 May 2002)]
  * The board cannot boot from CD-ROM, only from floppy or a FAT partition on a hard disk. Debian woody was the last Debian release whose installer supported it; an installed system can reportedly be upgraded to newer releases. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2007-December.mbox#L616|"Re: Debian Etch on Samsung 164UX/BX Alpha"]], Lennart Sorensen, debian-alpha, 6 Dec 2007)]

==== Known issues ====

  * **Onboard Ethernet:** the 21143 is well known for failing to auto-negotiate, particularly at 100 Mbit. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L2303|"Re: ruffian ether problems"]], Rich Payne, debian-alpha, 9 Dec 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L10904|"Re: Ruffian & 100Mbit/s"]], Stig Telfer, axp-list, 16 Oct 2000)] Forcing the media type (for example ''options tulip options=14'' for MII 100baseTx full duplex) may help. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-October.mbox#L12835|"Re: Ruffian & 100Mbit/s"]], Michal Jaegermann, axp-list, 18 Oct 2000)]
  * **Memory:** boards with four DIMMs are sensitive to the choice of modules, because the 21174 does not drive the memory lines to the JEDEC standard; the [[hardware:motherboards:pc164lx|PC164LX]], which uses the same chipset, is affected in the same way. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36191|"Re: UX4 memory problem"]], Brian Rerecich, axp-list, 23 Apr 1999)] Hard Data shipped UX systems with up to 1.5 GiB using selected modules. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36524|"Re: UX4 memory problem"]], Maurice Hilarius, axp-list, 23 Apr 1999)]
  * **PCI configuration:** the onboard SCSI controller is behind the 21052 PCI-to-PCI bridge. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-December.mbox#L3095|"Re: ruffian ether problems"]], Ron Farrer, debian-alpha, 13 Dec 2000)] Linux 2.4 needed fixes to bridge setup and to type 1 PCI configuration space access, which failed randomly on this board, apparently because of timing. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L37511|"ux164 (ruffian) fixes"]], Ivan Kokshaysky, axp-list, 21 Nov 2000)]
  * **Linux 2.6.23 and later:** 2.6.22.19 has been reported as the last kernel to boot on a 164UX, with 2.6.23 the first that does not. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2010-August.mbox#L709|"kernel regression on 164UX"]], Ian Las, debian-alpha, 3 Aug 2010)] The cause is the PT_NOTE program header that Linux 2.6.23 added to the kernel image, which MILO mistook for a loadable segment; a MILO fix was committed in May 2026 but has not yet been tested on a 164UX. [(>[[https://github.com/alphalinux-org/milo/commit/7a6701b734208c4fd36bb628996b32f811f6542a|"boot: skip non-PT_LOAD segments when loading kernel image"]], Matt Turner, MILO, 31 May 2026)]

==== Conflicting information ====

The following sources conflict with each other or with the account given above. They are listed here for further investigation.

  * **Maximum memory**
    * {{wiki:hardware:motherboards:pc164ux:pc164ux_windows_nt_user_manual.pdf?linkonly|AlphaPC 164UX/BX Motherboard Windows NT User's Manual}}: "Main memory 32MB to 3GB memory array"
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-November.mbox#L4719|"Ruffian maximum memory and debian"]], unai, debian-alpha, 12 Nov 2002: "the user's manual tell one place up to 3GB, but in other place up to 1,5GB"
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L35069|"Re: hardware ramblings  Re: Request For Comment: "]], Maurice Hilarius, axp-list, 11 Apr 2001: "the UX version with 1.5GB capacity."
  * **SRM firmware**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-January.mbox#L76569|"Re: Ruffian/UX to be unsupported"]], Maurice Hilarius, axp-list, 27 Jan 1999: "As there is SRM firmware available for the UX ( UX is not a DEC/Copaq part but a Deskstation/Samsung/API part) the only choice is the LX."
    * The same message concludes that the LX is the board to use for SRM, and other sources in the Firmware section say no SRM exists for the UX.
