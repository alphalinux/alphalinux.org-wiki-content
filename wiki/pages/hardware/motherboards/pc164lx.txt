The AlphaPC 164LX is an ATX form factor motherboard for the EV56 (21164A), released by Digital in 1997 and later also made by Samsung (see [[#firmware|Firmware]]). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1997-April.mbox#L1|"Press/Alpha 21164 Microprocessor Streaks to 600MHz, Sets New Records"]], Digital Press and Analysts News, biz.digital.announce, 2 Apr 1997)]

==== Specifications ====

  * 466, 533, or 600 MHz EV56 CPU [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_product_brief.pdf?linkonly|AlphaPC 164LX Motherboard Product Brief}})]
  * 2 or 4 MiB external L3 cache (Bcache)
  * 21174-CA chipset
  * 4x 168-pin DIMMs, supports up to 1 GiB of unbuffered ECC SDRAM
  * 2x 33 MHz 64-bit PCI slots
  * 2x 33 MHz 32-bit PCI slots
  * 2x ISA slots
  * CMD646 IDE on PCI
  * Intel 82378ZB PCI-to-ISA bridge
  * SMC FDC37C935 Super I/O controller
  * Floppy disk controller
  * PS/2 keyboard and mouse
  * 2x RS-232
  * 1x Parallel port
  * MMJ SROM console port
  * ATX board, 30.48 cm x 24.38 cm (12.0 in x 9.6 in) [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_technical_reference_manual.pdf?linkonly|AlphaPC 164LX Motherboard Technical Reference Manual}}, p. 3-2)]

The board is configured with jumper blocks J27 and J28. [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_technical_reference_manual.pdf?linkonly|AlphaPC 164LX Motherboard Technical Reference Manual}}, pp. 2-4 to 2-6)]

^ Jumper ^ Function ^ Settings ^
| J27 IRQ3 to IRQ0 (pins 1 to 8) | CPU speed | 466 MHz: in, out, out, out (default); 533 MHz: out, in, in, in; 600 MHz: out, in, in, out |
| J27 CF1, CF2 (pins 11 to 14) | Bcache size | 2 MiB: both out (default); 4 MiB: CF1 out, CF2 in; 1 MiB: CF1 in, CF2 out |
| J27 CF3 (pins 15, 16) | Password bypass | In bypasses and clears the AlphaBIOS password |
| J27 CF7 (pins 23, 24) | Boot option | Out loads the console (default); in loads the fail-safe booter |
| J28 | Flash ROM update | 2-3 write-enabled (default); 1-2 write-protected |

J27 CF0 and CF4 to CF6 are reserved and left out.

==== CPU ====

The 164LX can be jumpered for 466, 533, or 600 MHz. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-November.mbox#L873|"searching for a wide alpha cpu heatsink"]], Jay Estabrook, axp-list, 5 Nov 2008)] The PCI bus runs at its maximum speed only when the CPU speed is a multiple of 66 MHz, which is true of all three standard 164LX speeds. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-May.mbox#L16649|"Q: Miata vs LX, ASUS SC875 SCSI, Teles ISDN"]], Jay Estabrook, axp-list, 12 May 1998)] 21164A CPUs taken from Personal Workstations work, but their heatsinks have no fan, since the fan is part of the workstation enclosure. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2006-December.mbox#L580|"Samsung CPU on a 164LX mainboard"]], Jay Estabrook, axp-list, 8 Dec 2006)]

Some CPUs run AlphaBIOS at 600 MHz but are unstable under SRM; running them at a lower speed avoids the problem. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-February.mbox#L1660|"AlphaPC 164LX SRM version"]], Maurice Hilarius, axp-list, 24 Feb 2005)]

==== Memory ====

The 164LX requires unbuffered 168-pin SDRAM DIMMs with ECC (x72 organization), installed in pairs. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L14575|"Memory Issues on an 164LX"]], Maurice Hilarius, axp-list, 17 Jan 2002)] Non-ECC DIMMs are not detected, and the board repeatedly sounds five beeps to indicate that no memory is present. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2001-October.mbox#L872|"164SX Memory"]], Justin Graham, debian-alpha, 10 Oct 2001)] Registered DIMMs do not work. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-January.mbox#L210|"Memory for AlphaPC 164LX"]], Steven Moix, axp-list, 5 Jan 2005)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-May.mbox#L3212|"memory for an LX164"]], Steven Moix, axp-list, 12 May 2005)]

The manuals list 512 MiB (4x 128 MiB) as the maximum, but 4x 256 MiB (1 GiB) has been reported to work reliably. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15627|"Memory Issues on an 164LX"]], Maurice Hilarius, axp-list, 18 Jan 2002)] The lower documented limit is attributed to a capacitance issue with 4x 256 MiB. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15694|"Memory Issues on an 164LX"]], Greg Lindahl, axp-list, 18 Jan 2002)] 512 MiB DIMMs do not work [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L4788|"PX164LX memory"]], Doug Larrick, debian-alpha, 13 Nov 2001)]; SRM may report up to 2048 MiB, but the memory is not usable. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-December.mbox#L2318|"SX164 RAM - (current) state with 512MB dimms ?"]], Kevin Wood, axp-list, 4 Dec 2000)]

Not every module that meets the specification works. The board reads the module's SPD data and rejects modules it does not recognize, so some PC133 and high-density modules fail. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2004-April.mbox#L1670|"Which memory for a 164LX motherboard?"]], Maurice Hilarius, axp-list, 4 Apr 2004)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2006-January.mbox#L30|"memory for an LX164"]], Juhana Helovuo, axp-list, 11 Jan 2006)]

Memory reported to work with the 164LX (and by extension the [[hardware:motherboards:pc164sx|AlphaPC 164SX]], which also accepts non-ECC modules):

  * Kingston KVR100X72C2/256 [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-May.mbox#L967|"Max. memory on 164LX"]], Juhana Helovuo, axp-list, 5 May 2008)]
  * Micron MT18LSDT1672G-10EC2 [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-May.mbox#L1209|"Max. memory on 164LX"]], Kazuyoshi Furutaka, axp-list, 8 May 2008)]
  * Micron MT18LSDT3272AG-10EB1
  * Crucial CT16M72S4D8E (128 MiB) [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2003-January.mbox#L8866|"164LX RAM update"]], John Goerzen, debian-alpha, 23 Jan 2003)]
  * Crucial CT32M72S4D7E (256 MiB) [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L4788|"PX164LX memory"]], Doug Larrick, debian-alpha, 13 Nov 2001)]
  * Crucial CT32M72S4D8E (256 MiB) [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-March.mbox#L20698|"Memory for LX164 Alpha's"]], Peter Petrakis, axp-list, 18 Mar 2002)]

Memory reported not to work:

  * Kingston KVR133X72C3/256, due to wrong layout [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2006-January.mbox#L30|"memory for an LX164"]], Juhana Helovuo, axp-list, 11 Jan 2006)]
  * Any 512 MiB DIMM, any registered DIMM, and any non-ECC DIMM (see above)

==== Power supply and cooling ====

The 164LX is designed for an ATX soft-power supply, with the front-panel switch connected to the soft power header (J1). A machine using a hard-switched supply and no soft power connection may fail to power on after being unplugged. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1997-October.mbox#L18219|"164LXs won't start after being unplugged?"]], Stephen J. Gaudet, axp-list, 27 Oct 1997)] A jumper across the power switch pins, together with the SRM setting ''auto_action boot'', makes the machine power on and boot automatically after a power failure. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2002-July.mbox#L3116|"LX164 automatic reboot"]], Rich Payne, debian-alpha, 8 Jul 2002)]

A 300 W supply is sufficient for a typical workstation [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L3987|"PC164LX board in an ATX case?"]], Rich Payne, axp-list, 4 Jul 2001)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-May.mbox#L7009|"Electrical power for a 164LX ?"]], Maurice Hilarius, axp-list, 22 May 2005)]; faster CPUs with 4 MiB of cache or many disks need more. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L4051|"PC164LX board in an ATX case?"]], Maurice Hilarius, axp-list, 4 Jul 2001)]

The CPU fan connector uses a different pin order from PC fans. On the Alpha connector, pin 1 is +12 V, pin 2 is the tachometer signal, and pin 3 is ground; PC fans use ground, +12 V, and tachometer. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L4454|"Installing new cpu fan on Alpha 164LX Motherboard"]], Donald White, axp-list, 3 Apr 2002)] The pins in a PC fan's connector must be rearranged before use; a miswired fan can damage the fan, motherboard, or power supply, and the board does not start without a correctly connected fan. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L3582|"Installing new cpu fan on Alpha 164LX Motherboard"]], Maurice Hilarius, axp-list, 3 Apr 2002)] Even when rewired, some PC fans do not provide a tachometer signal the board accepts. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L1167|"Need 164SX CPU Fan"]], Donald White, axp-list, 6 Jan 2002)]

The original 164LX fan is a 60 mm Panasonic Panaflo (high-speed version). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-October.mbox#L17097|"Original Alpha 164lx fan"]], John Weez, axp-list, 30 Oct 2002)]

==== Firmware ====

The flash ROM holds only one console image at a time, either AlphaBIOS or SRM. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-April.mbox#L2115|"AlphaPC 164LX & SRM (again)"]], Jay Estabrook, axp-list, 6 Apr 2005)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2004-February.mbox#L913|"XL-266 install"]], Jay Estabrook, axp-list, 20 Feb 2004)] The final releases are SRM V5.8 [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L10963|"flashed the firmware...now I know the culprit"]], Jay Estabrook, axp-list, 14 Jan 2002)] and AlphaBIOS 5.7. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L5721|"SRM -> AlphaBios fails on PC164SX"]], KirkE, axp-list, 5 Apr 2001)] SRM V5.8-1 runs on both Digital and Samsung boards. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-February.mbox#L1623|"AlphaPC 164LX SRM version"]], Donald White, axp-list, 24 Feb 2005)]

Switching from AlphaBIOS to SRM is done by copying ''lx164srm.rom'' to a FAT-formatted floppy and flashing it with the upgrade utility in AlphaBIOS Setup. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2004-October.mbox#L888|"SRM on 164LX"]], Steven Moix, axp-list, 4 Oct 2004)] The flash is write-protected unless pins 2 and 3 of J28 are jumpered together, which is the default. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2002-January.mbox#L1202|"Updating AlphaBIOS to SRM on an AlphaPC 164LX"]], Harald Simon, debian-alpha, 6 Jan 2002)]

The ''SMMTABLE.TXT'' file on the V7.3 firmware CD lists SRM 5.8 as the last version for the board but names no update file for it (the entry is ''[ARCHIVE]NOFILE.EXE''). [(>''SMMTABLE.TXT'', Alpha Systems Firmware Update CD V7.3, 14 Mar 2007)] The ''api/LX'' directory of the [[https://github.com/alphalinux/firmware/tree/master/api/LX|alphalinux/firmware]] repository holds API's 164LX files: ''lx164srm.rom'' with ''fwupdate.exe'', whose accompanying ''fwreadme.txt'' (12 Oct 1998) describes SRM V5.3-3, and AlphaBIOS 5.68-1 (''LXbios_5.68-1.zip''). [(>[[https://github.com/alphalinux/firmware/blob/master/api/LX/fwreadme.txt|fwreadme.txt]], alphalinux/firmware repository)] According to its history file, AlphaBIOS 5.68-1 supports both the 28F008SA and 28F008S5 flash chips and is the version evaluated by Samsung. [(>''history.txt'' in [[https://github.com/alphalinux/firmware/blob/master/api/LX/LXbios_5.68-1.zip|LXbios_5.68-1.zip]], alphalinux/firmware repository)]

AlphaBIOS uses different keys on a serial console: <key>Tab</key> to move between menu items, <key>C-b</key> to enter setup (instead of <key>F2</key>), and <key>C-u</key> to save the operating system configuration (instead of <key>F10</key>). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/1999-December.mbox#L1926|"Headless install on LX164"]], Adam C Powell IV, debian-alpha, 7 Dec 1999)]

The 164LX was manufactured by both Digital and Samsung. Digital boards use an Intel 28F008SA flash chip, while some Samsung boards use an Intel 28F008S5, which has a slightly different command set [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L2490|"clearing SRM password for LX164"]], Peter Petrakis, axp-list, 3 May 2002)]; the change was a part substitution during production. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L2573|"clearing SRM password for LX164"]], Rich Payne, axp-list, 3 May 2002)]

=== SRM V5.8 hardware support ===

  * SRM V5.8 can boot from the onboard IDE controller. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L14042|"which ATI video does 164LX ARC firmware like?"]], Jay Estabrook, debian-alpha, 24 Jul 2003)]
  * SRM V5.8 on the 164LX and 164SX is the only pre-EV6 SRM that supports Adaptec SCSI controllers. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2002-December.mbox#L4657|"General questions about alphaserver 1200 (533AU2)"]], Jay Estabrook, debian-alpha, 9 Dec 2002)] Support is limited to the 2940UW and 39160; other models (2940U, 2940U2W, 29160, 3950) are not supported by SRM, although they work under Linux. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-June.mbox#L1688|"Help needed for install on 164SX"]], Jay Estabrook, axp-list, 9 Jun 2005)]
  * The console's BIOS emulator can initialize many later PCI video cards that older Alpha consoles cannot, including the ATI Rage 128 and Radeon [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-February.mbox#L20624|"ATI Radeon on PC164??"]], Jay Estabrook, axp-list, 27 Feb 2002)] (including the Radeon 9100 [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L14668|"which ATI video does 164LX ARC firmware like?"]], Jay Estabrook, debian-alpha, 27 Jul 2003)]), 3Dlabs Oxygen VX1 and Permedia 2, 3dfx Voodoo Banshee [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2004-October.mbox#L2929|"AC-0.9 Testing Results (was: Re: Alpha Core ISO Images)"]], Jay Estabrook, axp-list, 15 Oct 2004)], and nVidia TNT2 (ELSA Gloria Synergy II). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-September.mbox#L4322|"Well supported PCI graphics card for 164SX"]], Jay Estabrook, axp-list, 6 Sep 2002)]
  * SRM does not need the ''pci_device_override'' workaround on the 164LX to accept unrecognized cards in the 64-bit PCI slots. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2002-September.mbox#L2942|"3d on alpha?"]], Jay Estabrook, debian-alpha, 4 Sep 2002)]

==== Firmware recovery ====

A jumper on the board starts the fail-safe booter, which sounds one, two, and then three beeps, then loads ''fwupdate.exe'' or AlphaBIOS from a FAT-formatted floppy so that the console can be reflashed. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-May.mbox#L4362|"SRM Console on 164LX motherboard"]], Maurice Hilarius, axp-list, 5 May 1998)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L40072|"Oops! Lost the Failsafe loader on LX164"]], Maurice Hilarius, axp-list, 16 Aug 1998)]

The fail-safe booter itself is stored in block 0 of the flash ROM. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L39894|"Oops! Lost the Failsafe loader on LX164"]], Greg Johnson, axp-list, 16 Aug 1998)] If block 0 is overwritten (for example, by writing MILO there with the flash management utility), the jumper no longer helps, and restoring the booter requires either a debug SROM containing the mini-debugger or removing and reprogramming the flash chip. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L42585|"Oops! Lost the Failsafe loader on LX164"]], Kelvin Lunsford, axp-list, 17 Aug 1998)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L55319|"Flash ROM on LX164"]], David G. Koontz, axp-list, 28 Sep 1998)]

Switching from SRM back to AlphaBIOS on the 164LX and [[hardware:motherboards:pc164sx|164SX]] can fail. Running the AlphaBIOS update from SRM may hang when AlphaBIOS offers to initialize invalid NVRAM, leaving SRM in place. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36300|"Can't downgrade from SRM to AlphaBios on PC164SX ......"]], Thomas Leitner, axp-list, 23 Apr 1999)] A reported workaround is to start AlphaBIOS from floppy (with ''arc'' at the SRM prompt, or with the fail-safe booter), then flash it using the upgrade option of the AlphaBIOS copy running in memory. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L5721|"SRM -> AlphaBios fails on PC164SX"]], KirkE, axp-list, 5 Apr 2001)] This may take several attempts. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L6199|"SRM -> AlphaBios fails on PC164SX"]], Donald White, axp-list, 5 Apr 2001)]

The motherboard's password-clear jumper clears only the AlphaBIOS password. Clearing a forgotten SRM password requires erasing part of the flash ROM from the Debug Monitor. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L1505|"clearing SRM password for LX164"]], Peter Petrakis, axp-list, 2 May 2002)]

==== Beep codes ====

  * 4 beeps with "No valid header found in ROM; loading entire ROM": flash ROM contents are corrupt. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L54912|"Flash ROM on LX164"]], Bob McElrath, axp-list, 29 Sep 1998)]
  * 5 beeps, repeated: no usable memory is present (for example, non-ECC DIMMs). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2001-October.mbox#L872|"164SX Memory"]], Justin Graham, debian-alpha, 10 Oct 2001)]
  * 6 beeps: checksum error when the image was read back from memory. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-November.mbox#L4989|"six beeps from a 164LX machine"]], Kazuyoshi Furutaka, axp-list, 30 Nov 2008)]

==== Linux ====

Current kernels support the AlphaPC 164LX with ''CONFIG_ALPHA_LX164'' or a generic kernel; it boots from SRM with [[software:boot_loaders:aboot|aboot]]. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v7.3-rc1|arch/alpha/Kconfig]], Linux 7.3)] A kernel built for the LX164 is slightly faster than a generic one. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-September.mbox#L14019|"Hangs when trying to boot with SRM on PC164LX"]], Jay Estabrook, axp-list, 23 Sep 2002)] The onboard CMD646 IDE controller uses the ''pata_cmd64x'' driver. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/ata/pata_cmd64x.c?h=v7.3-rc1|drivers/ata/pata_cmd64x.c]], Linux 7.3)]

  * The CPU corresponds to GCC's ''-mcpu=ev56''; it has the BWX extension but not MVI. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-March.mbox#L39096|"different alpha cpu compatibility issues?"]], Jay Estabrook, axp-list, 28 Mar 2000)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L563|"Playing DVDs"]], Jay Estabrook, axp-list, 3 Jan 2002)] The [[hardware:chipsets#21174|21174]] core logic supports byte and word access to I/O space, which the kernel enables. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/core_cia.c?h=v7.3-rc1|arch/alpha/kernel/core_cia.c]], Linux 7.3)]
  * The boot message ''pci: failed valid tag invalid pte reload test (mcheck; workaround enabled)'' appears on every 164LX and is harmless: it reflects a known weakness of the 21174. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-April.mbox#L3188|"AlphaPC 164LX & SRM (again)"]], Jay Estabrook, axp-list, 13 Apr 2005)]

The SMC FDC37C935 Super I/O controller's devices use the standard PC drivers:
  * Serial ports: ''8250'', at the standard PC addresses listed in the Alpha serial port table. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/include/asm/serial.h?h=v7.3-rc1|arch/alpha/include/asm/serial.h]], Linux 7.3)]
  * Parallel port: ''parport_pc''; floppy: ''floppy''; keyboard and mouse: ''i8042''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/parport/parport_pc.c?h=v7.3-rc1|drivers/parport/parport_pc.c]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/block/floppy.c?h=v7.3-rc1|drivers/block/floppy.c]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/input/serio/i8042.c?h=v7.3-rc1|drivers/input/serio/i8042.c]], Linux 7.3)]
  * Clock: the Alpha platform code reads the time-of-year clock itself rather than using ''rtc-cmos''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/rtc.c?h=v7.3-rc1|arch/alpha/kernel/rtc.c]], Linux 7.3)]

==== Known issues ====

  * **Clock battery:** the DS1287-compatible time-of-year clock is backed up by a replaceable CR2032 coin cell at B1. [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_technical_reference_manual.pdf?linkonly|AlphaPC 164LX Motherboard Technical Reference Manual}}, pp. 2-3, 4-8)] Console settings that do not survive a power cycle usually mean the cell is exhausted; see [[hardware:systems#common_problems|Systems: Common problems]].
