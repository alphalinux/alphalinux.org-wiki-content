===== PC164LX =====

The AlphaPC 164LX is an OEM ATX form factor motherboard released in 1997.

<gallery right aligned nocrop>
wiki:hardware:motherboards:pc164lx:pc164lx-1.jpg Digital AlphaPC 164LX
</gallery>

==== Specifications ====

  * 466, 533, or 600 MHz EV56 CPU [(>{{wiki:hardware:motherboards:pc164lx:pc164lx_product_brief.pdf?linkonly|AlphaPC 164LX Motherboard Product Brief}})]
  * 2 or 4 MiB external L2 cache
  * 21174-CA chipset
  * 4x 168-pin DIMMs, supports up to 1 GiB of unbuffered ECC SDRAM
  * 2x 33 MHz 64-bit PCI slots
  * 2x 33 MHz 32-bit PCI slots
  * 2x ISA slots
  * CMD646 IDE on PCI
  * Intel 82378ZB PCI-to-ISA bridge
  * SMC FDC37C935 Super I/O controller
  * Floppy disk controller
  * PS/2 keyboard and mouse
  * 2x RS-232
  * 1x Parallel port
  * MMJ SROM console port

==== Memory ====

The 164LX requires unbuffered 168-pin SDRAM DIMMs with ECC (x72 organization), installed in pairs. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L14575|"Memory Issues on an 164LX"]], Maurice Hilarius, axp-list, 17 January 2002)] Non-ECC DIMMs are not detected, and the board repeatedly sounds five beeps to indicate that no memory is present. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-October.mbox#L872|"164SX Memory"]], Justin Graham, debian-alpha, 10 October 2001)] Registered DIMMs do not work. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-January.mbox#L210|"Memory for AlphaPC 164LX"]], Steven Moix, axp-list, 5 January 2005)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-May.mbox#L3212|"memory for an LX164"]], Steven Moix, axp-list, 12 May 2005)]

The manuals list 512 MiB (4x 128 MiB) as the maximum, but 4x 256 MiB (1 GiB) works; one system builder reported building over 400 such systems. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15627|"Memory Issues on an 164LX"]], Maurice Hilarius, axp-list, 18 January 2002)] Compaq reportedly attributed the lower documented limit to a capacitance issue with 4x 256 MiB. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15694|"Memory Issues on an 164LX"]], Greg Lindahl, axp-list, 18 January 2002)] 512 MiB DIMMs do not work [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L4788|"PX164LX memory"]], Doug Larrick, debian-alpha, 13 November 2001)]; they may be counted as up to 2048 MiB, but the memory is never actually used. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-December.mbox#L2318|"SX164 RAM - (current) state with 512MB dimms ?"]], Kevin Wood, axp-list, 4 December 2000)]

Not every module that meets the specification works. The board reads the module's SPD data and rejects modules it does not recognize, so some PC133 and high-density modules fail. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-April.mbox#L1670|"Which memory for a 164LX motherboard?"]], Maurice Hilarius, axp-list, 4 April 2004)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-January.mbox#L30|"memory for an LX164"]], Juhana Helovuo, axp-list, 11 January 2006)]

Memory reported to work with the 164LX (and by extension, the [[PC164SX]], which also accepts non-ECC modules):

  * Kingston KVR100X72C2/256 [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-May.mbox#L967|"Max. memory on 164LX"]], Juhana Helovuo, axp-list, 5 May 2008)]
  * Micron MT18LSDT1672G-10EC2 [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-May.mbox#L1209|"Max. memory on 164LX"]], Kazuyoshi Furutaka, axp-list, 8 May 2008)]
  * Micron MT18LSDT3272AG-10EB1
  * Crucial CT16M72S4D8E (128 MiB) [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-January.mbox#L8866|"164LX RAM update"]], John Goerzen, debian-alpha, 23 January 2003)]
  * Crucial CT32M72S4D7E (256 MiB) [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L4788|"PX164LX memory"]], Doug Larrick, debian-alpha, 13 November 2001)]
  * Crucial CT32M72S4D8E (256 MiB) [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-March.mbox#L20698|"Memory for LX164 Alpha's"]], Peter Petrakis, axp-list, 18 March 2002)]

Memory reported not to work:

  * Kingston KVR133X72C3/256, due to wrong layout [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-January.mbox#L30|"memory for an LX164"]], Juhana Helovuo, axp-list, 11 January 2006)]
  * Any 512 MiB DIMM, any registered DIMM, and any non-ECC DIMM (see above)

Memory listed as compatible by a memory vendor (untested):

KAC330/64, KAL7200/64, KGW0281/64, KGW-E0236/32, KTA-G3/256, KTA-G3100/256, KTA-G3100/32, KTA-G3100/64, KTA-G4/256, KTA-iMAC100/256, KTA-iMAC100/512, KTC3088/256, KTC6611/256, KTC6615/64, KTC-EN133/256, KTD-OPGX1N/128, KTD-OPGX1N/256, KTD-WS410/256, KTD-XPSR/64, KTD-XPSRN/256, KTH6521/64, KTH-PVL100/256, KTH-PVL100/32, KTM1133/64, KTM1136/256, KTT-EQ7100/32, KVR100X64C2/256, KVR100X64C2/32, KVR100X64C3/256, KVR100X64C3/32, KVR100X72C2/128, KVR100X72C2/32, KVR100X72C2/64, KVR100X72C3/32, KVR100X72C3/64, KVR133X64C3/256, KVR133X72C3/64, SAC-A330/32, SHP-VVL8/256

==== CPU Speed ====

The 164LX can be jumpered for 466, 533, or 600 MHz. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-November.mbox#L873|"searching for a wide alpha cpu heatsink"]], Jay Estabrook, axp-list, 5 November 2008)] The PCI bus runs at its maximum speed only when the CPU speed is a multiple of 66 MHz, which is true of all three standard 164LX speeds. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-May.mbox#L16649|"Q: Miata vs LX, ASUS SC875 SCSI, Teles ISDN"]], Jay Estabrook, axp-list, 12 May 1998)] Other clock settings exist, but the PCI bus frequency depends on the CPU clock, so not all of them may be usable. 21164A CPUs taken from Personal Workstations work, but their heatsinks have no fan, since the fan is part of the workstation enclosure. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-December.mbox#L580|"Samsung CPU on a 164LX mainboard"]], Jay Estabrook, axp-list, 8 December 2006)]

One system builder reports that some CPUs run AlphaBIOS at 600 MHz but are unstable under SRM, and recommends running them at a lower speed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-February.mbox#L1660|"AlphaPC 164LX SRM version"]], Maurice Hilarius, axp-list, 24 February 2005)]

==== Firmware ====

The flash ROM holds only one console image at a time, either AlphaBIOS or SRM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-April.mbox#L2115|"AlphaPC 164LX & SRM (again)"]], Jay Estabrook, axp-list, 6 April 2005)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-February.mbox#L913|"XL-266 install"]], Jay Estabrook, axp-list, 20 February 2004)] The final releases are SRM V5.8 [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L10963|"flashed the firmware...now I know the culprit"]], Jay Estabrook, axp-list, 14 January 2002)] and AlphaBIOS 5.7. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L5721|"SRM -> AlphaBios fails on PC164SX"]], KirkE, axp-list, 5 April 2001)] SRM V5.8-1 runs on both Digital and Samsung boards. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-February.mbox#L1623|"AlphaPC 164LX SRM version"]], Donald White, axp-list, 24 February 2005)]

To switch from AlphaBIOS to SRM, copy ''lx164srm.rom'' to a FAT-formatted floppy and flash it with the upgrade utility in AlphaBIOS Setup. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-October.mbox#L888|"SRM on 164LX"]], Steven Moix, axp-list, 4 October 2004)] The firmware archive page on ftp.digital.com once linked ''lx164_v5_8.exe'' as the "AlphaBIOS Update Floppy"; that is the wrong file, and AlphaBIOS rejects it with an invalid checksum. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-December.mbox#L3037|"164LX Firmware"]], Bryan Medsker, axp-list, 15 December 2003)] The flash is write-protected unless pins 2 and 3 of J28 are jumpered together, which is the default. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-January.mbox#L1202|"Updating AlphaBIOS to SRM on an AlphaPC 164LX"]], Harald Simon, debian-alpha, 6 January 2002)]

Around 1998, SRM for the Digital Semiconductor boards was licensed separately. It was obtained through the Evaluation Board Software Design Kit (part number QR-21B02-03, US$75) [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-May.mbox#L4265|"SRM Console on 164LX motherboard"]], Stephen J. Gaudet, axp-list, 5 May 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L3642|"SRM license issues"]], Jay Estabrook, axp-list, 6 January 1998)], and the images on Digital's FTP site could only upgrade an existing SRM installation. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-September.mbox#L40627|"Need SRM on my 164SX MotherBoard."]], Rich Payne, axp-list, 22 September 1999)]

=== SRM V5.8 Hardware Support ===

  * SRM V5.8 can boot from the onboard IDE controller. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L14042|"which ATI video does 164LX ARC firmware like?"]], Jay Estabrook, debian-alpha, 24 July 2003)]
  * SRM V5.8 on the 164LX and 164SX is the only pre-EV6 SRM that supports Adaptec SCSI controllers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-December.mbox#L4657|"General questions about alphaserver 1200 (533AU2)"]], Jay Estabrook, debian-alpha, 9 December 2002)] Support is limited to the 2940UW and 39160; other models (2940U, 2940U2W, 29160, 3950) are not supported by SRM, although they work under Linux. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-June.mbox#L1688|"Help needed for install on 164SX"]], Jay Estabrook, axp-list, 9 June 2005)]
  * The console's BIOS emulator can initialize many later PCI video cards that older Alpha consoles cannot, including the ATI Rage 128 and Radeon [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-February.mbox#L20624|"ATI Radeon on PC164??"]], Jay Estabrook, axp-list, 27 February 2002)] (including the Radeon 9100 [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-July.mbox#L14668|"which ATI video does 164LX ARC firmware like?"]], Jay Estabrook, debian-alpha, 27 July 2003)]), 3Dlabs Oxygen VX1 and Permedia 2, 3dfx Voodoo Banshee [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-October.mbox#L2929|"AC-0.9 Testing Results (was: Re: Alpha Core ISO Images)"]], Jay Estabrook, axp-list, 15 October 2004)], and nVidia TNT2 (ELSA Gloria Synergy II). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-September.mbox#L4322|"Well supported PCI graphics card for 164SX"]], Jay Estabrook, axp-list, 6 September 2002)]
  * SRM does not need the ''pci_device_override'' workaround on the 164LX to accept unrecognized cards in the 64-bit PCI slots. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-September.mbox#L2942|"3d on alpha?"]], Jay Estabrook, debian-alpha, 4 September 2002)]

==== Firmware Recovery ====

A jumper on the board starts the fail-safe booter, which sounds one, two, and then three beeps, then loads ''fwupdate.exe'' or AlphaBIOS from a FAT-formatted floppy so that the console can be reflashed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-May.mbox#L4362|"SRM Console on 164LX motherboard"]], Maurice Hilarius, axp-list, 5 May 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L40072|"Oops! Lost the Failsafe loader on LX164"]], Maurice Hilarius, axp-list, 16 August 1998)]

The fail-safe booter itself is stored in block 0 of the flash ROM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L39894|"Oops! Lost the Failsafe loader on LX164"]], Greg Johnson, axp-list, 16 August 1998)] If block 0 is overwritten (for example, by writing MILO there with the flash management utility), the jumper no longer helps. Restoring the booter then requires a debug SROM containing the mini-debugger, which the standard 164LX SROM lacks [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L42585|"Oops! Lost the Failsafe loader on LX164"]], Kelvin Lunsford, axp-list, 17 August 1998)], or removing and reprogramming the flash chip. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L55319|"Flash ROM on LX164"]], David G. Koontz, axp-list, 28 September 1998)]

Switching from SRM back to AlphaBIOS on the 164LX and 164SX can fail. Running the AlphaBIOS update from SRM may hang when AlphaBIOS offers to initialize invalid NVRAM, leaving SRM in place. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-April.mbox#L36300|"Can't downgrade from SRM to AlphaBios on PC164SX ......"]], Thomas Leitner, axp-list, 23 April 1999)] A reported workaround is to start AlphaBIOS from floppy (with ''arc'' at the SRM prompt, or with the fail-safe booter), then flash it using the upgrade option of the AlphaBIOS copy running in memory. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L5721|"SRM -> AlphaBios fails on PC164SX"]], KirkE, axp-list, 5 April 2001)] This may take several attempts. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-April.mbox#L6199|"SRM -> AlphaBios fails on PC164SX"]], Donald White, axp-list, 5 April 2001)]

The motherboard's password-clear jumper clears only the AlphaBIOS password. Clearing a forgotten SRM password requires erasing part of the flash ROM from the Debug Monitor. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L1505|"clearing SRM password for LX164"]], Peter Petrakis, axp-list, 2 May 2002)]

==== Linux ====

  * When building a kernel, select the LX164 system type, not PC164. A generic kernel also works, with slightly lower performance. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-September.mbox#L14019|"Hangs when trying to boot with SRM on PC164LX"]], Jay Estabrook, axp-list, 23 September 2002)] The CPU corresponds to GCC's ''-mcpu=ev56''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-March.mbox#L39096|"different alpha cpu compatibility issues?"]], Jay Estabrook, axp-list, 28 March 2000)]
  * The PYXIS (21174) core logic supports byte/word I/O, and consoles enable the BWX instruction set extension by default. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L18328|"ev56 optimization -> illegal instruction"]], Jay Estabrook, axp-list, 14 March 1998)] The 21164A CPU does not support the MVI extension. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L563|"Playing DVDs"]], Jay Estabrook, axp-list, 3 January 2002)]
  * The boot message ''pci: failed valid tag invalid pte reload test (mcheck; workaround enabled)'' appears on every 164LX and is harmless: it reflects a known weakness of the PYXIS chipset. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-April.mbox#L3188|"AlphaPC 164LX & SRM (again)"]], Jay Estabrook, axp-list, 13 April 2005)]
  * IDE: early kernels drove the CMD646 in PIO mode only. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-December.mbox#L9304|"SX EIDE perf? + LX summary (Was EIDE perf)"]], Jay Estabrook, axp-list, 7 December 1997)] Kernel 2.1.115 added a CMD646 driver with DMA support, which at first could only be enabled by editing the kernel configuration files [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L21641|"LX164 IDE - fast - working!!!"]], Dave Gilbert, axp-list, 8 August 1998)], until Richard Henderson added the option to his patch set. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L46757|"LX164 IDE - fast - working!!!"]], Richard Henderson, axp-list, 20 August 1998)]
  * Clock: early AlphaBIOS releases used a clock tick of 512 Hz instead of the usual 1024 Hz. Kernels booted through MILO therefore reported double the expected BogoMIPS and ran the clock at half speed, until updated MILO PALcode initialized the real-time clock correctly. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-April.mbox#L15444|"SX164 Clock Problem (was: Problems with the time)"]], Jay Estabrook, axp-list, 10 April 1998)]
  * AlphaBIOS uses different keys on a serial console: Tab to move between menu items, Ctrl-B to enter setup (instead of F2), and Ctrl-U to save the operating system configuration (instead of F10). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/1999-December.mbox#L1926|"Headless install on LX164"]], Adam C Powell IV, debian-alpha, 7 December 1999)]

==== Power Supply ====

The 164LX is designed for an ATX soft-power supply, with the front-panel switch connected to the soft power header (J1). A machine using a hard-switched supply and no soft power connection may fail to power on after being unplugged. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-October.mbox#L18219|"164LXs won't start after being unplugged?"]], Stephen J. Gaudet, axp-list, 27 October 1997)] To power on automatically after a power failure, place a jumper across the power switch pins and set ''auto_action'' to ''boot'' in SRM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-July.mbox#L3116|"LX164 automatic reboot"]], Rich Payne, debian-alpha, 8 July 2002)]

A 300 W supply is sufficient for a typical workstation [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L3987|"PC164LX board in an ATX case?"]], Rich Payne, axp-list, 4 July 2001)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-May.mbox#L7009|"Electrical power for a 164LX ?"]], Maurice Hilarius, axp-list, 22 May 2005)]; faster CPUs with 4 MiB of cache or many disks need more. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L4051|"PC164LX board in an ATX case?"]], Maurice Hilarius, axp-list, 4 July 2001)]

==== CPU Fan ====

The CPU fan connector uses a different pin order from PC fans. On the Alpha connector, pin 1 is +12 V, pin 2 is the tachometer signal, and pin 3 is ground; PC fans use ground, +12 V, and tachometer. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L4454|"Installing new cpu fan on Alpha 164LX Motherboard"]], Donald White, axp-list, 3 April 2002)] The pins in a PC fan's connector must be rearranged before use; a miswired fan can damage the fan, motherboard, or power supply, and the board does not start without a correctly connected fan. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L3582|"Installing new cpu fan on Alpha 164LX Motherboard"]], Maurice Hilarius, axp-list, 3 April 2002)] Even when rewired, some PC fans do not provide a tachometer signal the board accepts. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L1167|"Need 164SX CPU Fan"]], Donald White, axp-list, 6 January 2002)]

The original 164LX fan is a 60 mm Panasonic Panaflo (high-speed version). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-October.mbox#L17097|"Original Alpha 164lx fan"]], John Weez, axp-list, 30 October 2002)] An 80 mm fan on a 60 mm to 80 mm adapter has been used as a quieter replacement. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-August.mbox#L4938|"quiet CPU fan for 164LX?"]], Gregory P. Smith, debian-alpha, 13 August 2003)]

==== Beep Codes ====

  * 4 beeps with "No valid header found in ROM; loading entire ROM": flash ROM contents are corrupt. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-September.mbox#L54912|"Flash ROM on LX164"]], Bob McElrath, axp-list, 29 September 1998)]
  * 5 beeps, repeated: no usable memory is present (for example, non-ECC DIMMs). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-October.mbox#L872|"164SX Memory"]], Justin Graham, debian-alpha, 10 October 2001)]
  * 6 beeps: checksum error when the image was read back from memory. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-November.mbox#L4989|"six beeps from a 164LX machine"]], Kazuyoshi Furutaka, axp-list, 30 November 2008)] In one case this was fixed by cleaning the board and reseating the memory and expansion cards. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L33|"six beeps from a 164LX machine"]], Kazuyoshi Furutaka, axp-list, 2 December 2008)]

==== Digital and Samsung Boards ====

The 164LX was manufactured by both Digital and Samsung. Digital boards use an Intel 28F008SA flash chip, while some Samsung boards use an Intel 28F008S5, which has a slightly different command set [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L2490|"clearing SRM password for LX164"]], Peter Petrakis, axp-list, 3 May 2002)]; the change was a part substitution during production. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L2573|"clearing SRM password for LX164"]], Rich Payne, axp-list, 3 May 2002)] The speaker on Digital boards is known to be very quiet [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-November.mbox#L28263|"164LX speaker too faint"]], Marek Dohojda, axp-list, 10 November 1998)], while it is loud on Samsung boards. ==== Conflicting Information ====

The following sources disagree with each other or with this page. They are listed here for further investigation.

  * **Registered memory**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L3792|"Re: PC164LX board in an ATX case?"]], Maurice Hilarius, axp-list, 4 Jul 2001: "RAM: PC100 Registered ECC (in pairs)."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-March.mbox#L20919|"Re: Memory for LX164 Alpha's"]], Maurice Hilarius, axp-list, 18 Mar 2002: "You need SDRAM, PC100, ECC, Registered."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-May.mbox#L3212|"memory for an LX164"]], Steven Moix, axp-list, 12 May 2005: "Registered will NOT work..."
  * **Maximum memory**
    * {{wiki:hardware:motherboards:pc164lx:pc164lx_technical_reference_manual.pdf?linkonly|AlphaPC 164LX Motherboard Technical Reference Manual}}: "The AlphaPC 164LX supports a maximum of 512MB of main memory."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15627|"RE: Memory Issues on an 164LX"]], Maurice Hilarius, axp-list, 18 Jan 2002: "4 x 256MB works. We have built over 400 with that.."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L15694|"Re: Memory Issues on an 164LX"]], Greg Lindahl, axp-list, 18 Jan 2002: "According to Compaq, the manual said that because there's a capitance [sic]"
  * **Cache size and CPU speed**
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-December.mbox#L2469|"RE: SX164 RAM - (current) state with 512MB dimms ?"]], Kurt Ludwig, axp-list, 4 Dec 2000: "You could also get an LX board w/ 8MB of on board cache through Microway."
    * [[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L4051|"Re: PC164LX board in an ATX case?"]], Maurice Hilarius, axp-list, 4 Jul 2001: "And a 667 with 4MB cache likes more juice than that..."
    * The manuals list 2 or 4 MiB of cache and CPU speeds up to 600 MHz.
  * **Fail-safe loader jumper name**
    * Maurice Hilarius refers to the jumper as "CF7" in some messages and "JF7" in others.
