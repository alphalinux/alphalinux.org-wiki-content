The UP2000 and UP2000+ are dual-processor motherboards produced by Alpha Processor, Inc. (API), with the Tsunami chipset and a Slot B processor interface. [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}}, p. iii)]

==== Specifications ====

=== UP2000 ===

The UP2000 was introduced in 2000. [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, p. iii)]

  * 1-2 667 MHz EV67 CPUs with 2/4 MiB external L2 cache or 750 MHz EV67 CPUs with 8 MiB external L2 cache [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}})] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L11176|"Re: Can I swap the 21264A in a UP2000 processor cardridge ?"]], Rich Payne, axp-list, 21 Dec 2001)]
  * Tsunami chipset (1x Cchip, 4x Dchips, 2x Pchips)
  * 8x 168 pin DIMMs, supports 64 MiB to 2 GiB of ECC Registered RAM (2.67 GiB/s)
  * 256-bit memory bus running at 83 MHz
  * 64-bit 33 MHz PCI Bus with 2x 64-bit 33 MHz PCI slots and 1 32-bit 33 MHz slot
  * 32-bit 33 MHz PCI Bus with 3x PCI slots
  * AIC-7891 SCSI
  * Cypress CY82C693UB PCI-to-ISA bridge with EIDE and 2x USB ports; SMC FDC37C669 Super I/O with floppy, parallel, 2x serial, keyboard, and mouse [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, p. 1-2)]
  * 1x ISA slot (shared)
  * Extended ATX form factor, 12 in x 13 in [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, p. 1-1)]

The UP2000 has four configuration jumper blocks: J27, J29, and J34 together select the CPU speed and must all match the Slot B modules, and J36 selects the L2 cache size. [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, p. 2-4)] J29 also selects the recovery modes; the other J29 pins must stay at their defaults: [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, pp. 5-4 to 5-6)]

^ Mode ^ J29 0/1 ^ J29 6/7 ^ J29 14/15 ^
| Normal boot (default) | open | open | open |
| Restore factory defaults (bypass the password) | open | open | jumpered |
| Normal recovery | jumpered | open | open |
| Alpha Diagnostics recovery | jumpered | open | jumpered |
| Interactive Alpha Diagnostics (console) | jumpered | jumpered | open |
| Interactive Alpha Diagnostics (debug port J42/J43) | jumpered | jumpered | jumpered |
| Interactive reset PALcode (debug port J42/J43) | open | jumpered | open |

The debug ports, J43 for the primary Slot B module and J42 for the secondary, default to 9600 baud. [(>{{wiki:hardware:motherboards:up2000:up2000_user_manual.pdf?linkonly|UP2000 User Manual}}, p. 5-6)]

=== UP2000+ ===

The UP2000+ is a minor update to the UP2000; apart from the changes below, the hardware is the same. The UP2000+ detects the CPU frequency automatically, whereas the UP2000 required jumpered configuration. [(>[[https://www.theregister.com/on-prem/2000/09/15/api-messes-up-alpha-mobo-upgrade/1545403|"API messes up Alpha mobo upgrade"]], Mike Magee, The Register, 15 Sep 2000)]

  * 1-2 833 MHz EV68AL CPUs with 4/8 MiB external L2 cache (in addition to CPUs supported by UP2000) [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}})]
  * 2x 64-bit 33 MHz PCI Buses
    * 3x 64-bit Slots on bus 0
    * 1x 64-bit and 2x 32-bit slots on bus 1

The UP2000+ has two jumper blocks. J31 sets the processor voltage (see [[#cpu|CPU]]). [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}}, p. 2-6)] J29 sets the other options; by default only pins 13-14 are jumpered: [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}}, pp. 2-7 to 2-8)]

^ J29 pins ^ Function when jumpered ^
| 1-2 | Recover firmware (normal recovery) |
| 1-2 and 15-16 | Alpha Diagnostics recovery |
| 1-2 and 7-8 | Interactive Alpha Diagnostics on the operator console (with 15-16: on debug port J42/J43) |
| 7-8 | Interactive SROM code on debug port J42/J43 |
| 9-10 | Write-protect the flash ROM |
| 11-12 | Disable the L2 cache |
| 13-14 | Serial remote reset enabled (default; remove to disable) |
| 15-16 | Restore factory defaults and bypass the password |

==== CPU ====

  * The CPU is soldered to the Slot B module and cannot be replaced separately. The UP2000's SROM only has code for 667 MHz (2/4 MiB cache) and 750 MHz (8 MiB cache) processors. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L11176|"Re: Can I swap the 21264A in a UP2000 processor cardridge ?"]], Rich Payne, axp-list, 21 Dec 2001)]
  * 750 MHz processors run with a 75 MHz memory bus, compared to 83 MHz for 667 MHz and 833 MHz processors, which is why all 750 MHz modules sold had 8 MiB of cache. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-December.mbox#L10940|"Re: Can I swap the 21264A in a UP2000 processor cardridge ?"]], Maurice Hilarius, axp-list, 20 Dec 2001)] The 750 MHz modules use the most power of any Slot B module; the EV68 833 MHz modules use much less. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-September.mbox#L1467|"Re: FW: UP2000 MoBo test?"]], Kurt A. Ludwig, axp-list, 9 Sep 2003)]
  * The 833 MHz Slot B modules with 4 MiB DDR cache can only be used in the UP2000+, not the UP2000. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L11134|"Re: API Networks article on The Register"]], Rich Payne, axp-list, 6 Nov 2000)] EV67 Slot B modules reached end of life in early 2001, replaced by EV68 modules with 4 MiB DDR cache. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L1|"RE: UP2000"]], Maurice Hilarius, axp-list, 28 Feb 2001)]
  * On the UP2000+, jumper J31 selects the CPU voltage: no jumper for 21264/21264A processors, and a jumper for 21264B processors. [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}})]

==== Memory ====

DIMMs are installed in banks of four, and a system with fewer than four DIMMs does not start. Four 256 MiB DIMMs and eight 128 MiB DIMMs perform the same. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L20944|"Re: should I use 8 DIMMs for UP2000 M/B when I put two 667Mhz"]], Rich Payne, axp-list, 9 Nov 2000)]

==== Power supply and cooling ====

  * The power supply should be at least 450 W, with at least 35 A on 3.3 V, 30 A on 5 V, and 15 A on 12 V, and must provide the 20-pin ATX connector, a supplementary 6-pin connector, and a 4-pin drive connector for the motherboard. Supplementary fans connected to the motherboard use a nonstandard pinout. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-October.mbox#L16969|"UP2000 cse and power"]], Maurice Hilarius, debian-alpha, 26 Oct 2002)] A 500 W supply is advisable with two CPUs. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-September.mbox#L17010|"Re: Power Supply for UP 2000."]], Maurice Hilarius, axp-list, 21 Sep 2001)]
  * Each Slot B module needs at least 45 cfm of airflow. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L11336|"RE: API Networks article on The Register"]], Maurice Hilarius, axp-list, 6 Nov 2000)] API specified the systems for a maximum ambient temperature of 35 C. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-May.mbox#L15814|"RE: UP2000 Temperature"]], Tom Morris, axp-list, 23 May 2000)] A stopped Slot B fan can turn off the power good LED and prevent the system from starting. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L7983|"possible to check UP2000 fan status or CPU temperature?"]], Robert M. Riches Jr., axp-list, 8 May 2002)]
  * The board is extended ATX, and the Slot B fans extend beyond the edge of the board. Each Slot B module weighs about 2 lb (0.9 kg) and is held by four standoffs whose positions are not part of any ATX specification. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-October.mbox#L16483|"Re: up2000 too big for most cases?"]], T. Weyergraf, debian-alpha, 25 Oct 2002)] A drill template for the standoffs is available. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-October.mbox#L17066|"RE: up2000 too big for most cases?"]], Peter Petrakis, debian-alpha, 26 Oct 2002)] The case must be stiff enough to hold the modules without flexing; thin aluminum cases are not recommended. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-October.mbox#L17329|"Re: up2000 too big for most cases?"]], Maurice Hilarius, debian-alpha, 27 Oct 2002)]

==== Onboard devices ====

  * The Cypress (Contaq) CY82C693 south bridge has two IDE controllers, but only one is wired to a connector, limiting the board to two IDE devices. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2000-September.mbox#L4768|"Re: IDE Drives on UP2000 ?"]], Rich Payne, debian-alpha, 22 Sep 2000)]
  * SRM does not assign an interrupt to the onboard USB controller, so it generally cannot be used; a PCI USB card works instead. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-February.mbox#L724|"RE: USB on UP2000+ ??"]], Rich Payne, axp-list, 3 Feb 2003)]
  * The UP2000 can report CPU temperatures from its LM75 sensors; the UP2000+ can also report fan speeds. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-May.mbox#L8231|"RE: possible to check UP2000 fan status or CPU temperature?"]], Rich Payne, axp-list, 9 May 2002)]

==== Firmware ====

  * AlphaBIOS and the SRM console are both present in flash, but Linux cannot be booted from AlphaBIOS on the UP2000, so it is booted from SRM. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-September.mbox#L25979|"RE: Alpha-bios"]], Rich Payne, axp-list, 12 Sep 2000)]
  * The last SRM release for the UP2000 and UP2000+ is A5.8-81, dated 8 May 2001. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L4822|"Re: UP1500?"]], Maurice Hilarius, axp-list, 8 Jan 2003)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L3708|"how to get a Radeon 7500 to work in UP2000"]], Robert M. Riches Jr., axp-list, 7 Jan 2003)] After API's web site went offline, its firmware was mirrored by Peter Petrakis. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-July.mbox#L12574|"RE: API missing SRM firmware updates"]], Peter Petrakis, axp-list, 20 Jul 2002)]
  * The same A5.8-81 package, ''up2000_srm_5.8-81.zip'' (''UP20SRM.ROM'' and the ''UP2000FW.TXT'' file list), serves both the UP2000 and the UP2000+, and is kept in the [[https://github.com/alphalinux/firmware/tree/master/api/UP2000|alphalinux/firmware]] repository with earlier releases in its ''archive'' directory. SRM 5.8-65 or later is required for 833 MHz Slot B modules in a UP2000+. When ''lfu'' asks for the file list, ''up2000fw.txt'' must be typed, because the default, ''pc264fw.txt'', fails; ''update srm'' then writes the image. [(>''readme.1st'' in [[https://github.com/alphalinux/firmware/blob/master/api/UP2000/up2000_srm_5.8-81.zip|up2000_srm_5.8-81.zip]], alphalinux/firmware repository)]
  * Compaq's Alpha Systems Firmware CD identifies the UP2000 as a DS20, and flashing a UP2000 from it leaves the system without a working SRM console; API's own UP2000 SRM image must be used instead. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2002-November.mbox#L4001|"SUMMARY: converting UP2000 (Dual CPU) from Linux to Tru64 V5.1"]], Gerfried J. Kumbartzki, tru64-unix-managers, 5 Nov 2002)]
  * SRM is updated with ''lfu'' from a floppy. If ''lfu'' hangs reading the floppy, running it after ''set auto_action halt'' and a power cycle avoids the hang. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2008-November.mbox#L589|"Re: UP2000 plus SRM update"]], Juhana Helovuo, debian-alpha, 6 Nov 2008)]
  * If the system shows only a blue screen with a cursor, the console is probably set to the serial port; ''set console graphics'', entered from a terminal on the serial port, restores the graphics console. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L25384|"Re: Trouble w/SRM on UP2000 Dual Alpha"]], Rich Payne, axp-list, 20 Jul 2001)]
  * The BIOS emulator in the UP2000 and UP2000+ SRM cannot initialize newer ATI cards, such as the PCI Radeon 7500 and 9000. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-February.mbox#L13630|"Re: Radeon 9000 on UP2000+ ?"]], Jay Estabrook, axp-list, 17 Feb 2003)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-April.mbox#L4378|"Another test iso image from AC1.0"]], Jay Estabrook, axp-list, 18 Apr 2005)]

==== Firmware recovery ====

On the UP2000+, jumper block J29 pins 15-16 invoke the fail-safe boot recovery, and pins 1-2 recover the firmware. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-May.mbox#L53|"Trouble booting UP2000+"]], Matt Turner, axp-list, 15 May 2009)] If that does not work, the firmware can be recovered through the SROM serial debug port (a DEC MMJ connector): load the EBSDK debug monitor over the serial line, use it to load SRM, then reflash SRM from a floppy. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-May.mbox#L254|"Trouble booting UP2000+"]], Matt Turner, axp-list, 17 May 2009)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-May.mbox#L482|"Trouble booting UP2000+"]], Peter Petrakis, axp-list, 18 May 2009)] The debug monitor image is ''dp264dbm.cmp'', and transfers only work at 9600 baud. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2010-March.mbox#L157|"AW: Continuing UP2000+ problems"]], Ian Las, axp-list, 27 Mar 2010)]

==== Linux ====

Current kernels support both boards with ''CONFIG_ALPHA_DP264'' or a generic kernel, like other Tsunami systems, including both CPUs in SMP kernels; [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-February.mbox#L31906|"RE: UP2000"]], Rich Payne, axp-list, 28 Feb 2001)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/sys_dp264.c?h=v7.3-rc1|arch/alpha/kernel/sys_dp264.c]], Linux 7.3)] they boot from SRM with [[software:boot_loaders:aboot|aboot]]. The onboard devices use these drivers:
  * SCSI (Adaptec AIC-7891): ''aic7xxx'' [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/scsi/aic7xxx/aic7xxx_pci.c?h=v7.3-rc1|drivers/scsi/aic7xxx/aic7xxx_pci.c]], Linux 7.3)]
  * IDE (Cypress CY82C693): ''pata_cypress'' [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/drivers/ata/pata_cypress.c?h=v7.3-rc1|drivers/ata/pata_cypress.c]], Linux 7.3)]
  * USB: the onboard controller generally cannot be used, because SRM assigns it no interrupt; see [[#onboard_devices|Onboard devices]].

==== History ====

API, renamed API NetWorks at the end of 2000, [(>{{wiki:hardware:motherboards:up2000plus:up2000plus_user_manual.pdf?linkonly|UP2000+ User Manual}}, p. iii)] took over the barely started development of the UP2000 from Samsung. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L6772|"RE: Samsung EV69"]], Maurice Hilarius, axp-list, 8 Aug 2002)] The UP2000+ and the 833 MHz Slot B modules were announced in late 2000, but deliveries to resellers were delayed until June 2001. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L12658|"RE: Bye-bye our API...Drove my Alpha to the..."]], Maurice Hilarius, axp-list, 15 Jan 2002)]

The UP2000 is not an officially supported Tru64 UNIX platform. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L43541|"RE: UP2000 and Tru64?"]], Mike Foley, axp-list, 23 Dec 1999)]

The [[hardware:systems:shark|API NetWorks CS20]] is a 1U dual processor system similar to the UP2000+. It uses the Tsunami chipset, but has CPUs soldered to the board instead of Slot B modules, an ALi south bridge instead of the Cypress, LSI Ultra160 SCSI instead of Adaptec, and dual onboard Ethernet. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-November.mbox#L13502|"Re: 1U DUAL 833MHz Alpha"]], Rich Payne, axp-list, 7 Nov 2000)] Cray used the CS20 as the building block of its SuperCluster systems. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-January.mbox#L31275|"RE: Cray chooses Alpha Linux ..."]], Tom Morris, axp-list, 30 Jan 2001)] API designed the CS20 and sold the design to Compaq, which produced it as the [[hardware:systems:shark|AlphaServer DS20L]]. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-July.mbox#L18051|"Re: API / CS20"]], Rich Payne, axp-list, 30 Jul 2002)]
