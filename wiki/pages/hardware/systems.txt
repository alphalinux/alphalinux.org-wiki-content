===== Systems =====

This page covers complete Alpha systems sold by Digital, Compaq, HP, and others. Evaluation boards and OEM motherboards have their own pages under [[hardware:motherboards:motherboards|Motherboards]], and which operating systems each system runs is on the [[software:operating_systems#support_by_system|Operating Systems]] page.

The kernel platforms, core logic, and the systems each platform covers are from the kernel configuration. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] Codenames are from the kernel's system variation tables, [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] the Alpha AXP System Reference Manual, [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, pp. D-2 to D-6)] and lists posted by Digital engineers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L30004|"Re: AlphaServer 800"]], Jay Estabrook, axp-list, 25 Mar 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1365|"Re: Sanity checking needed of Alpha subarch codenames in d-i manual"]], Jay Estabrook, debian-alpha, 8 Nov 2004)] "To 6.9" means that Linux 6.9 was the last version to support the system (see [[software:operating_systems#linux|Operating Systems]]).

Since Linux 6.10, the kernel requires at least an EV56 (21164A) CPU; "the remaining EV5 based machines all support the slightly more modern EV56 generation as well." [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] Systems still fitted with an original 21164 need a CPU upgrade to run current kernels.

==== Naming ====

  * **Model numbers:** in a name such as AlphaServer 1000 4/233, the digit before the slash is the CPU generation and the number after it is the speed. On the AlphaServer 1000, 4/??? means an EV4 CPU daughtercard, and an EV5 system is "5/???, aka MIKASA Pinnacle or Primo". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L23114|"Re: kernel for mikasa"]], Jay Estabrook, axp-list, 19 Jan 1998)]
  * **Personal Workstation a and au:** "The only difference between the 'a' and 'au' are the options offered. an 'a' could be ordered with options only supported by NT. an 'au' could be ordered only with options that would run on all three OS's (NT, Unix and VMS)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L21490|"RE: Cheating on Half-Flash Alphas, was RE: Everyone's SRM woes"]], John Jemiolo, axp-list, 14 Mar 2001)]
  * **Digital Server:** the Digital Server 3300, 5300, and 7300 are Windows NT versions of the AlphaServer 800, 1200, and 4100. "The 5300 is the whitebox version of the AS1200 and the 3300 is the whitebox version of the AS800 ... Linux and *BSD work straight out of the box". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] "the 7300 is the NT only version of the 4xxx (Rawhide)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L12769|"RE: Linux on Alpha 7300"]], John Jemiolo, axp-list, 5 Mar 1999)] They can be switched to SRM from the AlphaBIOS setup menus. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L38797|"RE: Alpha taxonomy"]], John Jemiolo, axp-list, 26 Aug 1999)]
  * **Codenames:** the early systems were named after cars: "Jensen, Morgan (never sold), Mustang (AS200), Avanti (AS400 and Studebaker :-), Cabriolet, Miata, Sable." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L33987|"Re: Japanese names for Alpha machines?? why?"]], Jay Estabrook, axp-list, 14 May 1999)] The Rawhide name predates Red Hat's: "WE had the 'rawhide' name FIRST". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-October.mbox#L15721|"Re: Rawhide problems: TGA2 and SMP crash"]], Jay Estabrook, axp-list, 25 Oct 2002)]

==== Identifying a System ====

The SRM console command ''show config'' lists the model name, firmware versions, processors, memory, and PCI and EISA devices. [(>{{wiki:software:firmware:alphaserver_800_users_guide.pdf?linkonly|AlphaServer 800 User's Guide}}, pp. 6-3, 6-7)] Under Linux, ''/proc/cpuinfo'' shows the ''system type'' and ''system variation'' from the HWRPB, which name the kernel platform and variation in the table above, and the console's ''platform string''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] For example, a GS320 reports "system type : Wildfire" and "platform string : AlphaServer GS320 6/731". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-August.mbox#L1|"CentOS on wildfire"]], Robin Humble, axp-list, 13 Aug 2006)] The Digital Server "white box" systems report the negative of the real system type, which the kernel corrects. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)]

A generic kernel runs on every supported system: "A 'generic' kernel will run on any supported Alpha system. However, if you configure a kernel for your specific system, it will be faster and smaller." [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] A kernel built for one platform panics with "Unsupported system type" on any other. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] The ''alpha_mv='' boot option forces a machine vector; Richard Henderson suggested ''-flags "alpha_mv=Rawhide"'' for an AlphaServer 4100 that an old kernel misidentified. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L24874|"Re: Support for Alpha 4100 in RH6.0?"]], Richard Henderson, axp-list, 19 Jun 1999)]

The Titan, Wildfire, and Marvel systems "have really BIG console footprints (8MB or more, as contrasted to 2MB on older machines), those MUST have the kernel starting up beyond the console." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L4794|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] Kernels built with ''CONFIG_ALPHA_LEGACY_START_ADDRESS'' leave out support for these systems entirely. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/Makefile?h=v6.10|arch/alpha/kernel/Makefile]], Linux 6.10)]

==== Common Problems ====

  * **Dead battery:** if console settings do not survive a power cycle, "this is often a symptom that the mobo 3.3v battery has gone dead, as the console 'setting' is recorded in memory that's backed by it." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2010-August.mbox#L757|"Minifridge"]], Jay Estabrook, axp-list, 20 Aug 2010)]
  * **Clock epoch:** SRM and ARC keep the time of year clock differently. "The date formats (actually, contents of the TOY chip registers) are kept differently under the two consoles." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L5548|"Re: AS200 4/233 (clock?) install problem"]], Jay Estabrook, axp-list, 2 Jul 1998)] The kernel guesses the epoch from the year register, and the ''epoch='' boot option overrides the guess. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/rtc.c?h=v6.9|arch/alpha/kernel/rtc.c]], Linux 6.9)]
  * **Memory:** "I've found it's best to put identical DIMMs into any Alpha." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L6350|"Re: memory issues"]], Christopher C. Chimelis, debian-alpha, 29 Nov 2001)] Wider memory buses need more DIMMs per bank: "Some later machines took DIMM pairs (DS10), others quartets (XP1000/DS20). Memory bandwidth, of course, is better the wider the mem bus". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008)]
  * **Failed CPUs:** a bad CPU in a multiprocessor system can be disabled with the SRM ''cpu_enabled'' variable, a bit mask with bit 0 for CPU 0. [(>{{wiki:software:firmware:alphaserver_2000_2100_2100a_firmware_reference_guide.pdf?linkonly|AlphaServer 2000/2100/2100A Firmware Reference Guide}}, p. 1-43)] Richard Henderson: "if the cpu is bad, you *should* have it completely disabled via cpu_enabled." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-July.mbox#L2370|"problem with smp and isolcpus"]], Richard Henderson, axp-list, 28 Jul 2005)]
  * **Multiprocessor systems need SRM:** "MILO is unsupported on *ALL* the (potentially) SMP Alpha machines ... I do NOT want to modify MILO to handle multiple CPUs, when SRM does such a nice job". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L37024|"Re: SMP for AlphaServer?"]], Jay Estabrook, axp-list, 14 Jul 1998)] See [[software:boot_loaders|Boot Loaders]].

===== 21064 and 21066 Systems =====

==== Alpha Development Unit ====

Before any Alpha system shipped, Digital's operating system work was done on Alpha Development Units, prototype machines that were never sold. Farrell Woods of Digital's UNIX group described them in 1994: [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-1994-December.mbox#L5386|"Re: Ultrix for Alpha (?)"]], Farrell Woods, comp.sys.dec, 21 Dec 1994)]

<blockquote>
The machines were called ADU's, or Alpha Development Units. They were washing-machine sized boxes with DECstation 5000's sitting atop as a host/IO processor and front-end. The ADU was in a way a Turbochannel option on the DECstation; that's how they talked.

Ultrix ran on the ADU's initially, then OSF. Development of OSF for Alpha proceeded on the ADU for quite a while as the first examples of what would be known as the DEC 3000 model 500 started trickling in (this was known internally as the Flamingo.) Support for the ADU was dropped before the first release of DEC OSF/1 for Alpha shipped, but some intrepid souls within the company managed to keep them going for themselves through the first two releases of the OS.
</blockquote>

ULTRIX on Alpha was an advanced development effort only. It ran on the ADU and was never carried to the production machines, and was never a product. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-1994-December.mbox#L5386|"Re: Ultrix for Alpha (?)"]], Farrell Woods, comp.sys.dec, 21 Dec 1994)] OpenVMS went further back still: according to Fred Kleinsorge of the VMS group, it first booted on "Manniquin, a EVAX emulator running on VAX", before it ran on the ADU. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2001-July.mbox#L7344|"Re: Compaq kills Alpha"]], Fred Kleinsorge, comp.sys.dec, 30 Jul 2001)]

==== DEC 2000 AXP and DECpc 150 AXP (Jensen) ====

"The Jensen was an EISA-based system with a 21064 Alpha processor running at 150MHz." The DECpc 150 AXP and DEC 2000 AXP "differed only in the bundled software." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-March.mbox#L4787|"Jensen-HOWTO: First pass"]], Jim Paradis, axp-list, 15 Mar 1996)] The DEC 2000 Model 500 was code-named Culzean. [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, p. D-2)] The Jensen was the first machine to run Linux/Alpha, with a 32-bit kernel "on a JENSEN, followed by AVANTI (as400)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-July.mbox#L572|"first Linux port"]], Jay Estabrook, axp-list, 13 Jul 2006)]

  * The Jensen needs its own kernel: "Jensens can't boot the generic kernel image, they need a custom one". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2002-May.mbox#L8369|"Re: Debian on Alpha DEC 2000 AXP"]], Falk Hueffner, debian-alpha, 11 May 2002)] It is the only platform without PCI. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/sys_jensen.c?h=v6.9|arch/alpha/kernel/sys_jensen.c]], Linux 6.9)]
  * Early versions of aboot needed SRM firmware 1.7: "You should be running firmware version 1.7". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-November.mbox#L37622|"Re: Error received Installing RedHat AXP150"]], Jim Paradis, axp-list, 21 Nov 1996)] Digital later published the 1.7 firmware with an installation procedure. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-February.mbox#L6582|"Jensen firmware 1.7 on ftp.digital.com"]], Jim Paradis, axp-list, 13 Feb 1998)] See Conflicting Information.
  * Red Hat 7.2 "has been tested on JENSEN and will boot and install directly from CD-ROM." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-August.mbox#L11016|"Re: Installing RH 7.1 on Jensen"]], Jay Estabrook, axp-list, 14 Aug 2002)]
  * "The Jensen RTC is kind of strange - it's the same as a normal PC, except it's at the wrong address! (The whole Jensen IO subsystem is rather strange - DEC was just learning how to do it...)" [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-May.mbox#L6117|"Re: /dev/rtc on Jensen?"]], Linus Torvalds, axp-list, 8 May 1996)]
  * For X, "the only card supported on Jensen under XFree86 is an S3-based ISA card. The S3 driver had *extensive* hacking done to it to support Jensen". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-February.mbox#L13405|"Re: EISA video card for AlphaLinux Jensen XP 150"]], Jay Estabrook, axp-list, 9 Feb 2001)]
  * The Jensen and Noname "had only 64-bit mem bus, and thus required SIMMS in pairs, not quartets". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008)]

==== DEC 3000, DEC 4000, and DEC 7000 ====

These systems have no PCI bus, and Linux never supported them. "The DEC 3000 series was the first Alpha-based workstation ever produced. Its system bus was TurboChannel". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L63171|"Re: DEC 3000"]], Jim Paradis, axp-list, 6 Oct 1998)] The DEC 3000 Models 300 are Pelican, the 400, 600, and 700 Sandpiper, and the 500, 800, and 900 Flamingo; the Models 700 and 900 have EV45 CPUs. The DEC 4000 (Cobra and Fang) is a Futurebus+ server with up to two CPUs, and the DEC 7000 and 10000 (Ruby) have up to six. [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, pp. D-2, D-5, D-6)]

  * "Support for TC devices should work for DEC 3000 out of the box as drivers are platform-independent. Glue code is for the core chipset is missing". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-July.mbox#L6100|"Re: Flogging a dead computer - DEC 3000/300"]], Maciej W. Rozycki, axp-list, 21 Jul 2000)] Attempts at a port in 1999 and plans in 2009 did not result in support. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L22983|"tbia() on DEC 3000 question"]], Craig P Prescott, axp-list, 16 Aug 1999)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2009-September.mbox#L528|"[RFC] Dropping Alpha sparse mapping support from X"]], Maciej W. Rozycki, axp-list, 4 Sep 2009)]
  * "NetBSD has been ported to the TurboChannel machines." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-November.mbox#L45909|"Re: Install Linux AXP"]], Jim Paradis, axp-list, 25 Nov 1996)]
  * The DEC 7000 could be upgraded in its cabinet to an AlphaServer 8400 by changing the centerplane, since the 8400 "uses the same DEC/VAX 7000 cabinet, 3-phase power and cooling systems, and I/O options". [(>{{wiki:hardware:systems:alphaserver_8400:alphaserver_8200_8400_technical_summary.pdf?linkonly|AlphaServer 8200/8400 Systems Technical Summary}}, Digital, 1996, p. 4)]

==== Multia and AXPpci 33 (Noname) ====

The Multia, or UDB ("Universal Desktop Box"), is a small desktop with a 21066 or 21066A CPU, onboard TGA graphics, a 21040 Ethernet controller, and one PCI slot. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-February.mbox#L329|"BETA Xserver for TGA Available"]], Jay Estabrook, axp-list, 2 Feb 1996)] "DEC had an agreement with Microsoft that every "Multia" system would be shipped with Windows NT installed." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L4880|"Re: Unable to install redhat 5.0 on multia through serial port"]], Jim Paradis, axp-list, 7 Jan 1998)] The [[hardware:motherboards:axppci33|AXPpci 33]] is a Baby-AT motherboard: "The AXPpci33 (aka NoName), is based on the EB66 (includes the Multia UDB). This design was produced by Digital's Technical OEM (TOEM) group". [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)]

  * The two "use the same CPUs and have the same interrupt handling mechanisms", [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-September.mbox#L1751|"Re: interesting benchmarks"]], David A Rusling, axp-list, 3 Sep 1996)] and "we use the same identical MILO for both UDB and NONAME platforms." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L949|"Re: fmu on PC164"]], Jay Estabrook, axp-list, 2 Jan 1998)] MILO was originally written for the Noname, "to run LINUX on them without requiring SRM console (and its license fee)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-December.mbox#L32014|"Re: Linux_is_Great!"]], Jay Estabrook, axp-list, 15 Dec 1998)]
  * The 21066 "takes an EV4 processor core, removes half of the on-chip L1 cache, and adds a PCI interface on-chip. These two modifications tend to really bottleneck the memory access." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-April.mbox#L14880|"Re: UDB's"]], Jim Paradis, axp-list, 7 Apr 1997)] "A 166-MHz UDB performs about like a 90 or 100MHz Pentium. The 233-MHz UDB performs like a 120 or 133MHz Pentium." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L4880|"Re: Unable to install redhat 5.0 on multia through serial port"]], Jim Paradis, axp-list, 7 Jan 1998)]
  * The Multia's flash holds SRM in two chips and ARC in the third. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-October.mbox#L47543|"UDB flash and failsafe loader experiments"]], Eric Smith, axp-list, 29 Oct 1996)] MILO booted from SRM "defaults to 24Mb" of memory. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L64302|"Re: UDB only sees 24M of RAM"]], Jay Estabrook, axp-list, 26 Jul 1998)]
  * The Multia needs parity SIMMs; parity cannot be disabled. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-July.mbox#L9098|"Re: UDB RAM question"]], Jay Estabrook, axp-list, 23 Jul 1996)]

==== AlphaStation 500 and 600 and Alpha XLT ====

The AlphaStation 600 (Alcor), AlphaStation 500 (Maverick and Bret), and Alpha XL 300, 366, and 433 (XLT) share the CIA core logic, EISA, and one kernel platform. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L30004|"Re: AlphaServer 800"]], Jay Estabrook, axp-list, 25 Mar 1998)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.10|arch/alpha/Kconfig]], Linux 6.10)] The AlphaStation 600 "has the EV5 CPU, plus PCI and EISA busses. There's a TGA in there ... also a COMBO card as well, with a DEC TULIP Ethernet controller on it and a pair of QLogic 1020ISP SCSI F/W controllers on it." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1996-May.mbox#L17455|"Re: Linux on Alpha 600"]], Jay Estabrook, axp-list, 29 May 1996)] "XLT stands for XL-Turbo, not XL-True". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-December.mbox#L30289|"Re: Can't load RAMDISK on XL-266"]], Jay Estabrook, axp-list, 23 Dec 1997)]

  * The kernel has separate Alcor and XLT machine vectors, and tells them apart "by looking for a 21040 TULIP in slot 6, which is built into XLT and BRET/MAVERICK, but not available on ALCOR." [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/sys_alcor.c?h=v6.10|arch/alpha/kernel/sys_alcor.c]], Linux 6.10)] "Running an ALCOR kernel on a true XLT will cause additional bits in the interrupt summary register to be treated as real interrupts, causing im most circumstances what looks like a hang but is really just taking continuous bogus interrupts." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-January.mbox#L79961|"Re: Alpha XL300 (aka XLT) problems"]], Jay Estabrook, axp-list, 28 Jan 1999)]
  * The AlphaStation 600 is best booted from SRM: "I don't recommend running an ALCOR from ARC console, booting MILO ... It would be much better to run it from SRM console, booting a kernel directly (via "aboot" of course, or BOOTP). This is how Linus runs his". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-October.mbox#L10317|"Re: Kernel 2.1.125 testing"]], Jay Estabrook, axp-list, 15 Oct 1998)]
  * "There is no *official* SRM console for the XLT; it was designed/sold strictly for WindowsNT." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-October.mbox#L20901|"Re: Milo booting other OSes?"]], Jay Estabrook, axp-list, 29 Oct 1997)] "It's best to keep using MILO with XLT, as well as XL." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-October.mbox#L3405|"AC-0.9 Testing Results (was: Re: Alpha Core ISO Images)"]], Jay Estabrook, axp-list, 18 Oct 2004)]
  * On the AlphaStation 500, "You should have the best luck with an XLT MILO, as the BRET and XLT are extremely close, architecture-wise." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-April.mbox#L18099|"Re: AlphaStation 500 MILO problems + Voodoo questions"]], Jay Estabrook, debian-alpha, 28 Apr 2003)] "the Maverick takes EDO SIMM memory, which is hard to find, while the Alcor takes more normal SIMMs, and has a great many more slots for it." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-February.mbox#L2057|"Re: Alphas worth saving?"]], Jay Estabrook, debian-alpha, 5 Feb 2003)]
  * "the CIA-1 core logic in AS500/333 as well as EB164 and XLT ... is flawed", which the 2.4.13 PCI changes exposed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-June.mbox#L8071|"Re: [LONG] CIA breakage in 2.4.13 (was Re: AS500 and 2.4 SCSI blues)"]], Jay Estabrook, axp-list, 9 Jun 2002)] The kernel still avoids the affected DMA windows on CIA revision 1. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/core_cia.c?h=v6.10|arch/alpha/kernel/core_cia.c]], Linux 6.10)]
  * The AlphaStation 500 and AlphaServer 800 have a built-in QLogic 1020, which failed with the Red Hat 7.1 ''qlogicisp'' driver but worked with the newer QLogic driver. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-January.mbox#L1901|"Re: QLogic ISP problem"]], Jay Estabrook, axp-list, 8 Jan 2002)] The AlphaStation 500 "has no IDE". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-March.mbox#L1770|"[Fwd: Re: Qlogic 1280 driver blues]"]], Jay Estabrook, axp-list, 24 Mar 2006)]
  * "the built in sound card in the 500/500 (aka brett) was actually on an EISA bus. You might have to run the Eisa Configuration Utility". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-February.mbox#L51|"as500/500 soundcard?"]], Jeff Donsbach, axp-list, 8 Feb 2006)]

==== Personal Workstation (Miata) ====

"The internal code-name for the PWS series is 'Miata'." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1997-June.mbox#L4503|"Re: Personal Workstation 433a"]], Jim Paradis, axp-list, 3 Jun 1997)] "MIATA motherboard has 2 64-bit PCI slots in front of a builtin PCI-PCI bridge, which is where the remaining 3 32-bit PCI slots live. Core logic is PYXIS, same as on the LX and SX and UX." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-August.mbox#L34900|"Re: PWS-500a ext cache question..."]], Jay Estabrook, axp-list, 13 Aug 1998)] "MIATAs were never built with EV5, only with EV56". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-April.mbox#L1885|"Re: 2.1.92 and PWS 433a (21164 CPU, not 21164A!)"]], Jay Estabrook, axp-list, 2 Apr 1998)] The flash holds both SRM and AlphaBIOS. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2005-June.mbox#L4706|"Re: PWS AlphaBIOS to SRM"]], Jay Estabrook, debian-alpha, 9 Jun 2005)]

There are two generations. "There are two flavours of the Miata: the old MX5 with the CMD646 IDE controller and a newer MiataGL with a Cypress 82C693 IDE controller." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L9612|"Re: IDE disk problems with RH7.2 on DPW500a"]], Magnus Lindstrom, axp-list, 22 Jan 2003)] The Miata GL has an onboard QLogic SCSI controller, "And it was never made obvious from the model numbers". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-December.mbox#L22318|"Re: Can someone check the specs of this machine?"]], Jay Estabrook, axp-list, 11 Dec 1999)] Compaq's catalog calls the later models "Enhanced" and the earlier ones "Classic Digital Personal Workstations (DPW without onboard SCSI)". [(>{{wiki:hardware:systems:personal_workstation:personal_workstation_a_au_series_catalog.pdf?linkonly|Compaq DPW Enhanced a-Series & au-Series}}, Systems and Options Catalog, September 2000, p. 8)]

  * **DMA bug:** the 21174 "has a bug that corrupts DMA transfers that crosses a page boundary ... on the primary PCI bus, but that is where the IDE controller is located." Use an add-on IDE controller "in one of the free 32-bit PCI-slots. Don't use a 64-bit slot." "The MiataGL doesn't have the DMA bug, it was fixed with a factory installed hardware patch." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L9612|"Re: IDE disk problems with RH7.2 on DPW500a"]], Magnus Lindstrom, axp-list, 22 Jan 2003)] "Early MIATA had the most problems, LX and SX many fewer, and final MIATA (aka MIATA-GL) none to speak of". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-April.mbox#L2335|"Second IDE port not working on PC164"]], Jay Estabrook, axp-list, 8 Apr 2004)] See also [[hardware:other#personal_workstation_64-bit_slots|Personal Workstation 64-bit Slots]].
  * On a first generation PWS 433a, the ''cmd64x'' driver ignores ''ide=nodma'', so DMA has to be disabled with ''hdparm''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2007-August.mbox#L7000|"Re: Hmm, IDE DMA seems broken with Etch on my PWS433a (Miata MX5)."]], Lennart Sorensen, debian-alpha, 31 Aug 2007)]
  * "There are two versions of MIATA motherboards: they differ in the PCI "slot" where the onboard PCI-to-PCI bridge lives". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L2291|"Re: PWS 433a"]], Jay Estabrook, axp-list, 3 Jan 1998)]
  * Kernels before 2.2.18 limited Pyxis systems to 1 GB: "a problem a while ago, with PYXIS support (MIATA/LX/SX) being limited to 1GB of RAM ... This was fixed". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L38336|"Re: PYXIS machine checks w/ 1.5GB RAM"]], Jay Estabrook, axp-list, 29 Mar 2001)]
  * "MIATA has an ES1888 builtin, which is (at least) SBPro compatible". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L23336|"Re: Sound on Miata (PWS500a)"]], Jay Estabrook, axp-list, 9 Jul 1998)]

Trade it in for a Wildfire or Marvel... ;-}" [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2003-September.mbox#L17415|"Re: AlphaServer GS140 (8400)"]], Jay Estabrook, debian-alpha, 23 Sep 2003)]

[(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L9448|"Re: linux on gs80?"]], Peter Rival, axp-list, 21 Jan 2003)]
  * In 2006, on a 32-CPU GS320, CentOS 4.3's SMP kernel "invariably stops after Freeing unused kernel memory", while kernel.org 2.6.17.8 was "close to working though - except for a lost irq4". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-August.mbox#L1|"CentOS on wildfire"]], Robin Humble, axp-list, 13 Aug 2006)] A typo "that undoubtedly prevents WILDFIRE support from working" was fixed in Linux 2.6.22. [(>[[https://git.kernel.org/torvalds/c/d7083174a2ca|"ALPHA: misc fixes"]], Linux 2.6.22)] No later success has been reported.

==== AlphaServer DS15, DS25, ES45, and TS202c (Titan) ====

"DS15 (aka HyperBrick), DS25 (aka Granite), and ES45 (Privateer) are all TITAN-based machines". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1365|"Re: Sanity checking needed of Alpha subarch codenames in d-i manual"]], Jay Estabrook, debian-alpha, 8 Nov 2004)] "DS15 CPU is indeed EV68, I think around 1GHz. DS15 core logic is TITAN, successor to TSUNAMI, and used in DS25/ES45. DS15 is intended as replacement/upgrade from DS10, necessitated primarily because of EOL on TSUNAMI chipset by INTEL." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-October.mbox#L8451|"Re: Blimey New Alpha Workstation"]], Jay Estabrook, axp-list, 27 Oct 2003)] In 2002 the ES45 was the only Alpha with 66 MHz PCI. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-April.mbox#L7350|"Re: Looking for a "good" video card for a DS5305"]], Jay Estabrook, axp-list, 5 Apr 2002)] The TS202c (Falcon) firmware lists only Tru64 UNIX. [(>{{wiki:software:firmware:alphaserver_ts202c_v6.8b_firmware_release_notes.pdf?linkonly|AlphaServer TS202c V6.8B Firmware Release Notes and Update Procedures}}, September 2005, p. 6)]

  * These systems need a kernel without ''CONFIG_ALPHA_LEGACY_START_ADDRESS'': "On the TITAN-based machines (DS15/DS25/ES45) the console (SRM) lives in that area, so the base address of the kernel needs to be AT LEAST 8MB and better 16MB." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-August.mbox#L1628|"Re: AlphaServer DS25 failure"]], Jay Estabrook, debian-alpha, 6 Aug 2004)]
  * Peter Rival on the ES45 in 2001: "Works wonderfully. :) I use it all the time - just select "Titan" for your kernel type." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-October.mbox#L15863|"Re: Linux 2.4 on ES45?"]], Peter Rival, axp-list, 18 Oct 2001)]
  * The DS15 "TITAN P-Chip (aka PA-chip) supports 2 PCI buses (or 1 PCI and 1 AGP), so the builtin devices (NIC/etc) are on 1 PCI bus, and the riser PCI slots are on the other; note also that two of the PCI slots are capable of 66MHz speed, and NONE of the slots support 5V cards." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-October.mbox#L8940|"Re: Blimey New Alpha Workstation"]], Jay Estabrook, axp-list, 27 Oct 2003)] 2004 kernels crashed on it because "core_titan.c:titan_agp_info() code expects there to be two PA chips, and when there is only one (as in DS15), a machine check will occur". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-February.mbox#L3848|"Re: Dbian Linux (woody) for AXP can't boot on DS15"]], Jay Estabrook, debian-alpha, 9 Feb 2004)]
  * "both the SYMBIOS 1010 and the Adaptec 29160 and 39160 have been successfully used here on ES45 under Linux". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-February.mbox#L3437|"Re: U160 controllers for ES45/Alpha Linux????"]], Jay Estabrook, axp-list, 5 Feb 2002)]
  * Debian's SMP kernels were broken on the ES45 and DS25 from 5.4 until about 6.0. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2022-February.mbox#L260|"MP kernels broken with version 5.4.0-1"]], Frank Scheiner, debian-alpha, 20 Feb 2022)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2022-November.mbox#L1|"Linux 6.0.7 MP kernel works on DS25"]], Frank Scheiner, debian-alpha, 11 Nov 2022)]
  * A Debian build daemon, "an ES45 with three 1.25GHz CPUs and 4 Gbyte memory", drew about 600 W. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2012-April.mbox#L4811|"Re: Alpha ES45 buildd"]], Michael Cree, debian-alpha, 30 Apr 2012)]

===== 21364 Systems =====

==== AlphaServer ES47, ES80, and GS1280 (Marvel) ====

The ES47 and ES80 have "Up to 8 Alpha 21364 EV7 processors at 1150 MHz and 1000 MHz" with "up to 8 GB of RDRAM memory per CPU"; each two-processor building block drawer has "5 PCI-X/PCI slots and one AGP slot". [(>{{wiki:hardware:systems:alphaserver_es47:alphaserver_es47_es80_quickspecs.pdf?linkonly|HP AlphaServer ES47/ES80 QuickSpecs}}, July 2007, p. 4)] The GS1280 was sold in models with up to 64 CPUs. [(>{{wiki:hardware:systems:alphaserver_es47:alphaserver_es47_es80_gs1280_io_drawer_upgrade.pdf?linkonly|HP AlphaServer ES47/ES80/GS1280 I/O Drawer Upgrade}}, p. 1-3)] "the gs320 and gs160 are both large smp ev6 based machines. They are not Marvels, thats the gs1280/es80." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-January.mbox#L13814|"RE: Fwd: Marvel"]], Colin Sauze, axp-list, 28 Jan 2003)]

  * "The AlphaServer ES47/ES80 "serial" console is not a serial port. It is an interface provided by system management software ... ttyS0 cannot be used ... be sure to specify "console=srm" when booting." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2003-July.mbox#L2911|"Installation HPWrapper ISO for ES47, ES80, 2100A and DAC960 systems for RH-7.2."]], George France, axp-list, 11 Jul 2003)]
  * Linux supports at most 32 CPUs, because "MARVEL support is limited to 32 CPUs whan using 42-bit KSEG - one needs 48-bit KSEG to handle up to 64, and we've never supported 48-bit KSEG." [(>[[https://git.kernel.org/torvalds/c/d7083174a2ca|"ALPHA: misc fixes"]], Linux 2.6.22)]
  * The Marvel has no real PC clock: "RTC accesses are emulated via PAL calls. Unfortunately, for unknown reason these calls work only on CPU #0." [(>[[https://git.kernel.org/torvalds/c/5f7dc5d75076|"alpha: fix RTC on marvel"]], Linux 2.6.29)]
  * For Alpha Core 3 in 2007, "support for MARVEL (ES47/ES80/GS1280) is back after a long hiatus; I've only an ES47 to test on". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2007-March.mbox#L1087|"Torrents galore...but has anyone actually tried it?"]], Jay Estabrook, axp-list, 7 Mar 2007)] Jay Estabrook's Fedora 8 based release listed "No NUMA support on MARVEL (ES47 et al)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-April.mbox#L1|"Fedora 8-based distro for Alpha CD Announcement"]], Jay Estabrook, axp-list, 14 Apr 2008)]
  * Linux 7.3 fixed interrupt setup bugs on the Marvel dating from 2.6.38. [(>[[https://git.kernel.org/torvalds/c/3a3ac1f6c6a6|"alpha: marvel: Fix irq_set_status_flags to use correct IRQ number"]], Linux 7.3)] [(>[[https://git.kernel.org/torvalds/c/24d68db713d6|"alpha: marvel: Fix lock ordering in init_io7_irqs()"]], Linux 7.3)]
