===== Systems =====

This page covers complete Alpha systems sold by Digital, Compaq, HP, and others. Each system has its own page, listed in the table below; the prototype [[hardware:systems:alpha_development_unit|Alpha Development Unit]], which was never sold, has one too. Evaluation boards and OEM motherboards have their own pages under [[hardware:motherboards:motherboards|Motherboards]], and which operating systems each system runs is on the [[software:operating_systems#support_by_system|Operating Systems]] page.

The kernel platforms, core logic, and the systems each platform covers are from the kernel configuration. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] Codenames are from the kernel's system variation tables, [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] the Alpha AXP System Reference Manual, [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, pp. D-2 to D-6)] and lists posted by Digital engineers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L30004|"Re: AlphaServer 800"]], Jay Estabrook, axp-list, 25 Mar 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1365|"Re: Sanity checking needed of Alpha subarch codenames in d-i manual"]], Jay Estabrook, debian-alpha, 8 Nov 2004)] "To 6.9" means that Linux 6.9 was the last version to support the system (see [[software:operating_systems#linux|Operating Systems]]).

Since Linux 6.10, the kernel requires at least an EV56 (21164A) CPU; "the remaining EV5 based machines all support the slightly more modern EV56 generation as well." [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] Systems still fitted with an original 21164 need a CPU upgrade to run current kernels.

==== Naming ====

  * **Model numbers:** in a name such as AlphaServer 1000 4/233, the digit before the slash is the CPU generation and the number after it is the speed. On the AlphaServer 1000, 4/??? means an EV4 CPU daughtercard, and an EV5 system is "5/???, aka MIKASA Pinnacle or Primo". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L23114|"Re: kernel for mikasa"]], Jay Estabrook, axp-list, 19 Jan 1998)]
  * **Personal Workstation a and au:** "The only difference between the 'a' and 'au' are the options offered. an 'a' could be ordered with options only supported by NT. an 'au' could be ordered only with options that would run on all three OS's (NT, Unix and VMS)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L21490|"RE: Cheating on Half-Flash Alphas, was RE: Everyone's SRM woes"]], John Jemiolo, axp-list, 14 Mar 2001)]
  * **Digital Server:** the Digital Server 3300, 5300, and 7300 are Windows NT versions of the AlphaServer 800, 1200, and 4100. "The 5300 is the whitebox version of the AS1200 and the 3300 is the whitebox version of the AS800 ... Linux and *BSD work straight out of the box". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] "the 7300 is the NT only version of the 4xxx (Rawhide)". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L12769|"RE: Linux on Alpha 7300"]], John Jemiolo, axp-list, 5 Mar 1999)] They can be switched to SRM from the AlphaBIOS setup menus. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L38797|"RE: Alpha taxonomy"]], John Jemiolo, axp-list, 26 Aug 1999)]
  * **Codenames:** the early systems were named after cars: "Jensen, Morgan (never sold), Mustang (AS200), Avanti (AS400 and Studebaker :-), Cabriolet, Miata, Sable." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L33987|"Re: Japanese names for Alpha machines?? why?"]], Jay Estabrook, axp-list, 14 May 1999)] The Rawhide name predates Red Hat's: "WE had the 'rawhide' name FIRST". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2002-October.mbox#L15721|"Re: Rawhide problems: TGA2 and SMP crash"]], Jay Estabrook, axp-list, 25 Oct 2002)]

==== Identifying a System ====

The SRM console command ''show config'' lists the model name, firmware versions, processors, memory, and PCI and EISA devices. [(>{{wiki:software:firmware:alphaserver_800_users_guide.pdf?linkonly|AlphaServer 800 User's Guide}}, pp. 6-3, 6-7)] Under Linux, ''/proc/cpuinfo'' shows the ''system type'' and ''system variation'' from the HWRPB, which name the kernel platform and variation in the table above, and the console's ''platform string''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] For example, a GS320 reports "system type : Wildfire" and "platform string : AlphaServer GS320 6/731". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-August.mbox#L1|"CentOS on wildfire"]], Robin Humble, axp-list, 13 Aug 2006)] The Digital Server "white box" systems report the negative of the real system type, which the kernel corrects. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)]

A generic kernel runs on every supported system: "A 'generic' kernel will run on any supported Alpha system. However, if you configure a kernel for your specific system, it will be faster and smaller." [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] A kernel built for one platform panics with "Unsupported system type" on any other. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] The ''alpha_mv='' boot option forces a machine vector; Richard Henderson suggested ''-flags "alpha_mv=Rawhide"'' for an AlphaServer 4100 that an old kernel misidentified. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L24874|"Re: Support for Alpha 4100 in RH6.0?"]], Richard Henderson, axp-list, 19 Jun 1999)]

The Titan, Wildfire, and Marvel systems "have really BIG console footprints (8MB or more, as contrasted to 2MB on older machines), those MUST have the kernel starting up beyond the console." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L4794|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] Kernels built with ''CONFIG_ALPHA_LEGACY_START_ADDRESS'' leave out support for these systems entirely. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/Makefile?h=v6.10|arch/alpha/kernel/Makefile]], Linux 6.10)]

==== Common Problems ====

  * **Dead battery:** if console settings do not survive a power cycle, "this is often a symptom that the mobo 3.3v battery has gone dead, as the console 'setting' is recorded in memory that's backed by it." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2010-August.mbox#L757|"Minifridge"]], Jay Estabrook, axp-list, 20 Aug 2010)]
  * **Clock epoch:** SRM and ARC keep the time of year clock differently. "The date formats (actually, contents of the TOY chip registers) are kept differently under the two consoles." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L5548|"Re: AS200 4/233 (clock?) install problem"]], Jay Estabrook, axp-list, 2 Jul 1998)] The kernel guesses the epoch from the year register, and the ''epoch='' boot option overrides the guess. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/rtc.c?h=v6.9|arch/alpha/kernel/rtc.c]], Linux 6.9)]
  * **Memory:** "I've found it's best to put identical DIMMs into any Alpha." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L6350|"Re: memory issues"]], Christopher C. Chimelis, debian-alpha, 29 Nov 2001)] Wider memory buses need more DIMMs per bank: "Some later machines took DIMM pairs (DS10), others quartets (XP1000/DS20). Memory bandwidth, of course, is better the wider the mem bus". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008)]
  * **Failed CPUs:** a bad CPU in a multiprocessor system can be disabled with the SRM ''cpu_enabled'' variable, a bit mask with bit 0 for CPU 0. [(>{{wiki:software:firmware:alphaserver_2000_2100_2100a_firmware_reference_guide.pdf?linkonly|AlphaServer 2000/2100/2100A Firmware Reference Guide}}, p. 1-43)] Richard Henderson: "if the cpu is bad, you *should* have it completely disabled via cpu_enabled." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-July.mbox#L2370|"problem with smp and isolcpus"]], Richard Henderson, axp-list, 28 Jul 2005)]
  * **Multiprocessor systems need SRM:** "MILO is unsupported on *ALL* the (potentially) SMP Alpha machines ... I do NOT want to modify MILO to handle multiple CPUs, when SRM does such a nice job". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L37024|"Re: SMP for AlphaServer?"]], Jay Estabrook, axp-list, 14 Jul 1998)] See [[software:boot_loaders|Boot Loaders]].

==== Tsunami Systems ====

These notes apply to the [[hardware:systems:monet|XP1000]], [[hardware:systems:webbrick|DS10, DS10L, and XP900]], [[hardware:systems:goldrush|DS20 and DS20E]], [[hardware:systems:clipper|ES40]], and [[hardware:systems:shark|DS20L and CS20]]. The Tsunami systems share one kernel platform: "Various 21264 systems with the tsunami core logic chipset. API Networks: 264DP, UP2000(+), CS20; Compaq: DS10(E,L), XP900, XP1000, DS20(E), ES40." [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] Hewlett-Packard's Red Hat Linux 7.2 "has been tested on specific AlphaServers, namely the DS10/DS10L, DS20E, DS20L, ES40, and ES45." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/axp-kernel-2002-June.mbox#L1364|"Red Hat 7.2 Alpha from HP (CPQ) released!"]], David Addison, axp-kernel, 14 Jun 2002)]

  * "The latest consoles for the DS10/DS20/ES40/XP1000 all now have a separate device for IDE, rather than SCSI emulation as previous boxes." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L8097|"Re: booting from IDE drive on DS10's"]], Jay Estabrook, axp-list, 7 Jun 1999)]
  * Early kernels only supported VGA on PCI bus 0, while "SRM and Tru64 know how to talk VGA to bus 1." [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L30857|"Re: XP1000-667MHz no boot"]], Jay Estabrook, axp-list, 23 Jul 2001)] Current kernels have ''CONFIG_VGA_HOSE'' for "several platforms which always have multiple hoses". [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.10|arch/alpha/Kconfig]], Linux 6.10)]
