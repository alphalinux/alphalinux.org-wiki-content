===== Systems =====

Complete Alpha systems were sold by Digital, Compaq, HP, and others. Each has its own page, listed in the table below; the prototype [[hardware:systems:alpha_development_unit|Alpha Development Unit]], which was never sold, has one too. Evaluation boards and OEM motherboards have their own pages under [[hardware:motherboards|Motherboards]], and which operating systems each system runs is on the [[software:operating_systems#support_by_system|Operating Systems]] page.

The kernel platforms, core logic, and the systems each platform covers are from the kernel configuration. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] Codenames are from the kernel's system variation tables, [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] the Alpha AXP System Reference Manual, [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, pp. D-2 to D-6)] and lists posted by Digital engineers. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L30004|"Re: AlphaServer 800"]], Jay Estabrook, axp-list, 25 Mar 1998)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1365|"Re: Sanity checking needed of Alpha subarch codenames in d-i manual"]], Jay Estabrook, debian-alpha, 8 Nov 2004)] "To 6.9" means that Linux 6.9 was the last version to support the system, and "21164A only; others to 6.9" means that current kernels support only the system's 21164A (EV56) configurations (see [[software:operating_systems#linux|Operating Systems]]).

Since Linux 6.10, the kernel requires at least an EV56 (21164A) CPU; "the remaining EV5 based machines all support the slightly more modern EV56 generation as well." [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] Systems still fitted with an original 21164 need a CPU upgrade to run current kernels.

==== Identifying a system ====

The SRM console command ''show config'' lists the model name, firmware versions, processors, memory, and PCI and EISA devices. [(>{{wiki:software:firmware:alphaserver_800_users_guide.pdf?linkonly|AlphaServer 800 User's Guide}}, pp. 6-3, 6-7)] Under Linux, ''/proc/cpuinfo'' shows the ''system type'' and ''system variation'' from the HWRPB, which name the kernel platform and variation in the table above, and the console's ''platform string''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] For example, a GS320 reports "system type : Wildfire" and "platform string : AlphaServer GS320 6/731". [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2006-August.mbox#L1|"CentOS on wildfire"]], Robin Humble, axp-list, 13 Aug 2006)] The Digital Server "white box" systems report the negative of the real system type, which the kernel corrects. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)]

A generic kernel runs on every supported system, while a kernel configured for a specific system is faster and smaller. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] A kernel built for one platform panics with "Unsupported system type" on any other. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] The ''alpha_mv='' boot option forces a machine vector, for example ''-flags "alpha_mv=Rawhide"''. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L24874|"Re: Support for Alpha 4100 in RH6.0?"]], Richard Henderson, axp-list, 19 Jun 1999)]

The Titan, Wildfire, and Marvel consoles occupy 8 MiB or more of memory, compared with 2 MiB on older systems, so the kernel must be linked to start above the console. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L4794|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] Kernels built with ''CONFIG_ALPHA_LEGACY_START_ADDRESS'' leave out support for these systems entirely. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/Makefile?h=v6.10|arch/alpha/kernel/Makefile]], Linux 6.10)]

==== Common problems ====

  * **Dead battery:** console settings are kept in memory backed by the motherboard's 3.3 V battery, so settings that do not survive a power cycle usually indicate that the battery has failed. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2010-August.mbox#L757|"Minifridge"]], Jay Estabrook, axp-list, 20 Aug 2010)]
  * **Clock epoch:** SRM and ARC store the time of year clock registers differently. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L5548|"Re: AS200 4/233 (clock?) install problem"]], Jay Estabrook, axp-list, 2 Jul 1998)] The kernel guesses the epoch from the year register, and the ''epoch='' boot option overrides the guess. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/rtc.c?h=v6.9|arch/alpha/kernel/rtc.c]], Linux 6.9)]
  * **Memory:** banks should be populated with identical DIMMs. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L6350|"Re: memory issues"]], Christopher C. Chimelis, debian-alpha, 29 Nov 2001)] Systems with wider memory buses need more DIMMs per bank: pairs in the DS10, and sets of four in the XP1000 and DS20. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008)]
  * **Failed CPUs:** a bad CPU in a multiprocessor system should be disabled with the SRM ''cpu_enabled'' variable, a bit mask with bit 0 for CPU 0. [(>{{wiki:software:firmware:alphaserver_2000_2100_2100a_firmware_reference_guide.pdf?linkonly|AlphaServer 2000/2100/2100A Firmware Reference Guide}}, p. 1-43)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2005-July.mbox#L2370|"problem with smp and isolcpus"]], Richard Henderson, axp-list, 28 Jul 2005)]
  * **Multiprocessor systems need SRM:** MILO does not support multiprocessor systems. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L37024|"Re: SMP for AlphaServer?"]], Jay Estabrook, axp-list, 14 Jul 1998)] See [[software:boot_loaders|Boot Loaders]].

==== Tsunami systems ====

These notes apply to the [[hardware:systems:monet|XP1000]], [[hardware:systems:webbrick|DS10, DS10L, and XP900]], [[hardware:systems:goldrush|DS20 and DS20E]], [[hardware:systems:clipper|ES40]], and [[hardware:systems:shark|DS20L and CS20]]. The Tsunami systems share one kernel platform, which also covers API's 264DP, UP2000, UP2000+, and CS20. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)]
  * Later consoles for the DS10, DS20, ES40, and XP1000 present IDE disks as a separate device rather than through SCSI emulation. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L8097|"Re: booting from IDE drive on DS10's"]], Jay Estabrook, axp-list, 7 Jun 1999)]
  * The SRM console can use a VGA card on the second PCI bus. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L30857|"Re: XP1000-667MHz no boot"]], Jay Estabrook, axp-list, 23 Jul 2001)] Linux supports this with ''CONFIG_VGA_HOSE'', for platforms that always have multiple PCI hoses. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.10|arch/alpha/Kconfig]], Linux 6.10)]

==== Naming ====

  * **Model numbers:** in a name such as AlphaServer 1000 4/233, the digit before the slash is the CPU generation and the number after it is the speed. On the AlphaServer 1000, 4/xxx denotes an EV4 CPU daughtercard, and 5/xxx an EV5-generation system, also called Mikasa Pinnacle or Primo. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L23114|"Re: kernel for mikasa"]], Jay Estabrook, axp-list, 19 Jan 1998)]
  * **AlphaStation and AlphaServer names:** the scheme is "AlphaMumble S G/M", in which S is a rough size class, G the chip generation, and M the clock speed in MHz, with one exception that was rounded for marketing reasons. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1995-March.mbox#L21927|"Name confustion (was: alphastation 100/166/233 running osf1)"]], John L. Henning, comp.unix.osf.osf1, 11 Mar 1995)]
  * **Personal Workstation a and au:** the two differ only in the options offered. An "a" could be ordered with options supported only by Windows NT, and an "au" only with options supported by all three operating systems (Windows NT, Digital UNIX, and OpenVMS). [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L21490|"RE: Cheating on Half-Flash Alphas, was RE: Everyone's SRM woes"]], John Jemiolo, axp-list, 14 Mar 2001)]
  * **Digital Server:** the Digital Server 3300, 5300, and 7300 are Windows NT versions of the AlphaServer 800, 1200, and 4100. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L12769|"RE: Linux on Alpha 7300"]], John Jemiolo, axp-list, 5 Mar 1999)] The 3300 and 5300 run Linux and the BSDs without modification. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] They can be switched to SRM from the AlphaBIOS setup menus. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L38797|"RE: Alpha taxonomy"]], John Jemiolo, axp-list, 26 Aug 1999)]
  * **Codenames:** the early systems were named after cars: Jensen, Morgan (never sold), Mustang (AlphaStation 200), Avanti (AlphaStation 400), Cabriolet, Miata, and Sable. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L33987|"Re: Japanese names for Alpha machines?? why?"]], Jay Estabrook, axp-list, 14 May 1999)] The codenames were intended for internal use only. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-September.mbox#L19594|"Re: Will DEC OSF/1 become usable on "small" machines?"]], Steve Lionel, comp.unix.osf.osf1, 10 Sep 1994)]

==== History ====

The AlphaStation and AlphaServer names were introduced together on 3 November 1994, with eight systems: the [[hardware:systems:avanti|AlphaStation 200 4/166, 200 4/233, and 400 4/233]], the [[hardware:systems:mikasa|AlphaServer 1000 4/200]], the [[hardware:systems:sable|AlphaServer 2000 4/200 and 2100 4/275]], and the [[hardware:systems:dec_3000_4000_7000|DEC 7000 Model 700]]. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1994-November.mbox#L2921|"Press/Digital's Alpha Salvo Scores Direct Hit; Eight-System Lineup"]], Digital Press and Analysts News, biz.digital.announce, 3 Nov 1994)] The systems shared PCI with EISA or ISA as their I/O bus, and a choice of DEC OSF/1, OpenVMS, or Windows NT. [(>[[https://github.com/alphalinux-org/mailing-list-archives/blob/main/biz-digital-articles-mbox/googlegroups-1994-November.mbox#L5156|"Next Generation of AlphaStation and AlphaServer Systems"]], Customer Update, biz.digital.articles, 3 Nov 1994)]
