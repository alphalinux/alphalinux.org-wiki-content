The kernel platforms, core logic, and the systems each platform covers are from the kernel configuration. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] Codenames are from the kernel's system variation tables, [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] the Alpha AXP System Reference Manual, [(>{{wiki:documentation:references:alpha_axp_system_reference_manual_v6.pdf?linkonly|Alpha AXP System Reference Manual}}, Version 6, 1994, pp. D-2 to D-6)] and lists posted by Digital engineers. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-March.mbox#L30004|"Re: AlphaServer 800"]], Jay Estabrook, axp-list, 25 Mar 1998)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2004-November.mbox#L1365|"Re: Sanity checking needed of Alpha subarch codenames in d-i manual"]], Jay Estabrook, debian-alpha, 8 Nov 2004)]

The firmware column gives the last SRM version released for the system, from [[software:firmware:srm#final_versions|Final versions]], and whether it also has the ARC or AlphaBIOS firmware. The Linux column says whether current kernels support the system. "Linux 6.9 and earlier" marks systems whose processors Linux 6.10 dropped, and the AlphaServer 2100A and 2000A, whose platform it dropped. "Supported (21164A models); others Linux 6.9 and earlier" means that current kernels support only the system's EV56 (21164A) configurations, and that configurations with older processors ran up to Linux 6.9 (see [[software:operating_systems#linux|Operating Systems]]). "Untested" means that current kernels contain support for the system but no one has reported booting one on it.

Since Linux 6.10, the kernel requires at least an EV56 (21164A) CPU; "the remaining EV5 based machines all support the slightly more modern EV56 generation as well." [(>[[https://git.kernel.org/torvalds/c/a4184174be36|"alpha: drop pre-EV56 support"]], Linux 6.10)] Systems still fitted with an original 21164 need a CPU upgrade to run current kernels; see [[:status#processor_baseline|Current Status]]. For the systems marked "Linux 6.9 and earlier", the newest maintained kernel is Linux 6.6, the last long-term release before 6.10; kernel.org projects its end of life for December 2027. [(>[[https://www.kernel.org/category/releases.html|Active kernel releases]], kernel.org, retrieved 23 Sep 2026)]

==== Identifying a system ====

The SRM console command ''show config'' lists the model name, firmware versions, processors, memory, and PCI and EISA devices. [(>{{wiki:software:firmware:alphaserver_800_users_guide.pdf?linkonly|AlphaServer 800 User's Guide}}, pp. 6-3, 6-7)] Under Linux, ''/proc/cpuinfo'' shows the ''system type'' and ''system variation'' from the HWRPB, which name the kernel platform and variation in the table above, and the console's ''platform string''. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] For example, a GS320 reports "system type : Wildfire" and "platform string : AlphaServer GS320 6/731". [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2006-August.mbox#L1|"CentOS on wildfire"]], Robin Humble, axp-list, 13 Aug 2006)] The Digital Server "white box" systems report the negative of the real system type, which the kernel corrects. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)]

A generic kernel runs on every supported system, while a kernel configured for a specific system is faster and smaller. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] A kernel built for one platform panics with "Unsupported system type" on any other. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/setup.c?h=v6.9|arch/alpha/kernel/setup.c]], Linux 6.9)] The ''alpha_mv='' boot option forces a machine vector, for example ''-flags "alpha_mv=Rawhide"''. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L24874|"Re: Support for Alpha 4100 in RH6.0?"]], Richard Henderson, axp-list, 19 Jun 1999)]

The Titan, Wildfire, and Marvel consoles occupy 8 MiB or more of memory, compared with 2 MiB on older systems, so the kernel must be linked to start above the console. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2004-September.mbox#L4794|"Alpha Core ISO Images"]], Jay Estabrook, axp-list, 29 Sep 2004)] A generic kernel built with ''CONFIG_ALPHA_LEGACY_START_ADDRESS'', which the default configuration enables, is linked at the old address for boot loaders that hardcode it. Such a kernel leaves out Titan, Wildfire, and Marvel support entirely, so kernels for these systems must be built with the option off; see [[documentation:kernel#kernel_start_address|Kernel]]. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/Makefile?h=v7.3-rc1|arch/alpha/kernel/Makefile]], Linux 7.3)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/configs/defconfig?h=v7.3-rc1|arch/alpha/configs/defconfig]], Linux 7.3)]

==== Common problems ====

  * **Dead battery:** console settings are kept in memory backed by the motherboard's 3.3 V battery, so settings that do not survive a power cycle usually indicate that the battery has failed. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2010-August.mbox#L757|"Minifridge"]], Jay Estabrook, axp-list, 20 Aug 2010)] The battery varies: the Personal Workstation uses a CR2032 coin cell, and when it dies the machine starts in AlphaBIOS instead of SRM. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-September.mbox#L19901|"RE: Alpha a-series work station install"]], Tom Linden, axp-list, 25 Sep 2001)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2002-November.mbox#L347|"Re: PW 500au boot problem"]], ICUSC, comp.sys.dec, 15 Nov 2002)] On one system with a CR2032, a dead cell also reset the clock to 1 January 1995, and the console settings had to be entered again. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2017-January.mbox#L4217|"undone by a dead CR2032 button cell"]], Bob Tracy, debian-alpha, 23 Jan 2017)] Older boards such as the AXPpci 33 use a Dallas DS1287 clock module with a built-in battery, which can be replaced with a DS12887. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2010-August.mbox#L1208|"Re: AXPpci33 TOY Battery, DS12887+"]], Ralf Folkerts, comp.sys.dec, 6 Aug 2010)]
  * **Power supplies:** aging power supplies fail, most often through their capacitors. The DS20L and CS20 supplies are particularly prone to failure, which shows as the front LED changing from flashing green to steady red. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2007-July.mbox#L1197|"API CS20 / DS20L power supply flaw"]], SDF Poster, comp.sys.dec, 23 Jul 2007)] The XP1000 and Personal Workstation use standard ATX supplies, of 350 W and 300 W, which are easy to replace. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2006-April.mbox#L969|"Re: Compaq XP1000 powering off"]], thursday@allidaho.com, comp.os.linux.alpha, 18 Apr 2006)] Some server supplies are built for 200 to 240 V only: an ES45 "B" model reports every supply as failed on 120 V. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2008-April.mbox#L2183|"Re: ES45 says power supply failed"]], David Turner, comp.sys.dec, 30 Apr 2008)]
  * **Fans:** the systems monitor their fans, and halt or shut down when one stops; the PC164 halts if its CPU fan stops, [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/gmane-2007-February.mbox#L612|"Re: Looking for ev6 or later workstation.."]], Erik E. Fair, port-alpha, 16 Feb 2007)] and the DS10 and DS25 shut down on a fan failure. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/tru64-unix-managers-mbox/gmane-2006-January.mbox#L85|"DS10 Environmental Monitoring"]], James Eiler, tru64-unix-managers, 4 Jan 2006)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/netbsd-port-alpha-mbox/gmane-2026-June.mbox#L120|"Changes for mpt* between NetBSD 10 and NetBSD 11"]], John Klos, port-alpha, 24 Jun 2026)] A dead fan in a power supply should be replaced at once: on the CS20, "A working PSU with dead fan will die within hours." [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2009-February.mbox#L868|"Re: PSU fans on CS20/DS20L"]], DEMAINE Benoit-Pierre, comp.sys.dec, 3 Feb 2009)]
  * **Mismatched CPUs:** in multiprocessor systems, not every CPU module can be mixed with every other, even at the same speed. For the DS20 and DS20E, compatibility goes by module part number, and some revisions of the same speed cannot be combined; [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2011-September.mbox#L445|"Re: Adding a second CPU to a DS20E"]], John Reagan, comp.sys.dec, 13 Sep 2011)] on the ES40, pass 2.3 and pass 2.5 EV6 processors cannot be mixed. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-sys-dec-mbox/googlegroups-2002-January.mbox#L6716|"Re: Problems with early ES40's & DS20's?"]], Bob Lail, comp.sys.dec, 24 Jan 2002)] Use identical modules, with the same part number and revision, and check the system's configuration guide. A secondary CPU that fails to start shows in the kernel log as "SMP: Processor 1 failed to start". [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-April.mbox#L11851|"UP2K SMP problem"]], W Bauske, axp-list, 17 Apr 2000)]
  * **Chipset and board failures:** a significant number of UP2000+ boards have chipsets that have failed through electromigration. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L152|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 12 Nov 2012)]
  * **Clock epoch:** SRM and ARC store the time of year clock registers differently. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L5548|"Re: AS200 4/233 (clock?) install problem"]], Jay Estabrook, axp-list, 2 Jul 1998)] The kernel guesses the epoch from the year register, and the ''epoch='' boot option overrides the guess. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/rtc.c?h=v6.9|arch/alpha/kernel/rtc.c]], Linux 6.9)]
  * **Memory:** banks should be populated with identical DIMMs. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2001-November.mbox#L6350|"Re: memory issues"]], Christopher C. Chimelis, debian-alpha, 29 Nov 2001)] Systems with wider memory buses need more DIMMs per bank: pairs in the DS10, and sets of four in the XP1000 and DS20. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2008-December.mbox#L1027|"Alpha hardware"]], Jay Estabrook, axp-list, 5 Dec 2008)]
  * **Failed CPUs:** a bad CPU in a multiprocessor system should be disabled with the SRM ''cpu_enabled'' variable, a bit mask with bit 0 for CPU 0. [(>{{wiki:software:firmware:alphaserver_2000_2100_2100a_firmware_reference_guide.pdf?linkonly|AlphaServer 2000/2100/2100A Firmware Reference Guide}}, p. 1-43)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2005-July.mbox#L2370|"problem with smp and isolcpus"]], Richard Henderson, axp-list, 28 Jul 2005)]
  * **Multiprocessor systems need SRM:** MILO does not support multiprocessor systems. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-July.mbox#L37024|"Re: SMP for AlphaServer?"]], Jay Estabrook, axp-list, 14 Jul 1998)] See [[software:boot_loaders|Boot Loaders]].

==== Choosing a system today ====

For running a current distribution, a system needs an EV56 or later processor, an SRM console, and enough memory, and the 21264 systems are much faster than the 21164A ones. Other considerations are noise, power, and whether parts are available.

  * **DS10, DS15, XP1000:** single-processor 21264 systems. The DS10 and DS15 are the most practical choice for a hobbyist. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L280|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 13 Nov 2012)] The XP1000 uses an ATX power supply, and draws between 300 and 500 W. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2012-April.mbox#L2255|"Re: Alpha ES45 buildd"]], Witold Baryluk, debian-alpha, 9 Apr 2012)]
  * **DS20E, DS25, ES40, ES45:** multiprocessor servers, faster but power-hungry: a DS20E or DS25 draws about 500 W at idle. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L280|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 13 Nov 2012)] Some ES45 models need a 200 to 240 V supply.
  * **DS20L and CS20:** compact but loud, [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/gentoo-alpha-mbox/2011-February.mbox#L1|"[gentoo-alpha] ABOOT problem..."]], Romuald Lobet, gentoo-alpha, 26 Feb 2011)] with unreliable power supplies. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L152|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 12 Nov 2012)]
  * **UP1000 and UP1100:** limited to 768 MiB of single-channel SDRAM. The UP1500 has DDR memory and is better, but rare. The UP2000 and UP2000+ need an Extended ATX case and about 600 W. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L280|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 13 Nov 2012)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-os-linux-alpha-mbox/googlegroups-2012-November.mbox#L73|"Re: WTD: UP1500 or UP2000+ motherboard"]], Marc Schlensog, comp.os.linux.alpha, 11 Nov 2012)]
  * **Personal Workstation:** a 21164A workstation, and a quiet one, [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/debian-alpha-mbox/2008-August.mbox#L1436|"Re: lenny+1 and the future of the alpha port?"]], Bob Tracy, debian-alpha, 22 Aug 2008)] but early models have a DMA bug in their 64-bit PCI slots; see [[hardware:other#personal_workstation_64-bit_slots|Other Hardware]].
  * **EV56 servers:** the [[hardware:systems:noritake|AlphaServer 800 and 1000A]], [[hardware:systems:mikasa|1000]], [[hardware:systems:rawhide|1200, 4000, and 4100]], and [[hardware:systems:sable|2000 and 2100]] still run current kernels when fitted with 21164A (EV56) processors, but are much slower than the 21264 systems.
  * **EV4, EV45, and EV5 systems** run nothing newer than Linux 6.9, and so no current distribution kernel; NetBSD and OpenBSD still support them.

Whatever the system, a serial console, the last SRM version, and a new battery are the first steps; see [[documentation:installation|Installation]]. Add-in cards known to work are listed under [[hardware:other#cards_known_to_work_with_current_kernels|Other Hardware]].

==== Tsunami systems ====

These notes apply to the [[hardware:systems:monet|XP1000]], [[hardware:systems:webbrick|DS10, DS10L, and XP900]], [[hardware:systems:goldrush|DS20 and DS20E]], [[hardware:systems:clipper|ES40]], and [[hardware:systems:shark|DS20L and CS20]]. The Tsunami systems share the kernel's DP264 platform code: the DS20L and CS20 use its Shark variant, selected with ''CONFIG_ALPHA_SHARK'', and the others use ''CONFIG_ALPHA_DP264'', which also covers API's 264DP, UP2000, and UP2000+. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.9|arch/alpha/Kconfig]], Linux 6.9)] [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/kernel/Makefile?h=v6.9|arch/alpha/kernel/Makefile]], Linux 6.9)]
  * Later consoles for the DS10, DS20, ES40, and XP1000 present IDE disks as a separate device rather than through SCSI emulation. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-June.mbox#L8097|"Re: booting from IDE drive on DS10's"]], Jay Estabrook, axp-list, 7 Jun 1999)]
  * The SRM console can use a VGA card on the second PCI bus. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-July.mbox#L30857|"Re: XP1000-667MHz no boot"]], Jay Estabrook, axp-list, 23 Jul 2001)] Linux supports this with ''CONFIG_VGA_HOSE'', for platforms that always have multiple PCI hoses. [(>[[https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/arch/alpha/Kconfig?h=v6.10|arch/alpha/Kconfig]], Linux 6.10)]

==== Naming ====

  * **Model numbers:** in a name such as AlphaServer 1000 4/233, the digit before the slash is the CPU generation and the number after it is the speed. On the AlphaServer 1000, 4/xxx denotes an EV4 CPU daughtercard, and 5/xxx an EV5-generation system, also called Mikasa Pinnacle or Primo. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1998-January.mbox#L23114|"Re: kernel for mikasa"]], Jay Estabrook, axp-list, 19 Jan 1998)]
  * **AlphaStation and AlphaServer names:** the scheme is "AlphaMumble S G/M", in which S is a rough size class, G the chip generation, and M the clock speed in MHz. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1995-March.mbox#L21927|"Name confustion (was: alphastation 100/166/233 running osf1)"]], John L. Henning, comp.unix.osf.osf1, 11 Mar 1995)]
  * **Personal Workstation a-series and au-series:** the two differ only in the options offered. An "a" could be ordered with options supported only by Windows NT, and an "au" only with options supported by all three operating systems (Windows NT, Digital UNIX, and OpenVMS). [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2001-March.mbox#L21490|"RE: Cheating on Half-Flash Alphas, was RE: Everyone's SRM woes"]], John Jemiolo, axp-list, 14 Mar 2001)]
  * **Digital Server:** the Digital Server 3300, 5300, and 7300 are Windows NT versions of the AlphaServer 800, 1200, and 4100. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-March.mbox#L12769|"RE: Linux on Alpha 7300"]], John Jemiolo, axp-list, 5 Mar 1999)] The 3300 and 5300 run Linux and the BSDs without modification. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/2000-August.mbox#L8635|"RE: switching from ARC back to SRM"]], Kurt Ludwig, axp-list, 14 Aug 2000)] They can be switched to SRM from the AlphaBIOS setup menus. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-August.mbox#L38797|"RE: Alpha taxonomy"]], John Jemiolo, axp-list, 26 Aug 1999)]
  * **Codenames:** the early systems were named after cars: Jensen, Morgan (never sold), Mustang (AlphaStation 200), Avanti (AlphaStation 400), Cabriolet, Miata, and Sable. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/axp-list-mbox/1999-May.mbox#L33987|"Re: Japanese names for Alpha machines?? why?"]], Jay Estabrook, axp-list, 14 May 1999)] The codenames were intended for internal use only. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/comp-unix-osf-osf1-mbox/googlegroups-1994-September.mbox#L19594|"Re: Will DEC OSF/1 become usable on "small" machines?"]], Steve Lionel, comp.unix.osf.osf1, 10 Sep 1994)]

==== History ====

The AlphaStation and AlphaServer names were introduced together on 3 November 1994, with eight systems: the [[hardware:systems:avanti|AlphaStation 200 4/166, 200 4/233, and 400 4/233]], the [[hardware:systems:mikasa|AlphaServer 1000 4/200]], the [[hardware:systems:sable|AlphaServer 2000 4/200 and 2100 4/275]], and the [[hardware:systems:dec_3000_4000_7000|DEC 7000 Model 700]]. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/biz-digital-announce-mbox/googlegroups-1994-November.mbox#L2921|"Press/Digital's Alpha Salvo Scores Direct Hit; Eight-System Lineup"]], Digital Press and Analysts News, biz.digital.announce, 3 Nov 1994)] The systems shared PCI with EISA or ISA as their I/O bus, and a choice of DEC OSF/1, OpenVMS, or Windows NT. [(>[[https://github.com/alphalinux/mailing-list-archives/blob/main/biz-digital-articles-mbox/googlegroups-1994-November.mbox#L5156|"Next Generation of AlphaStation and AlphaServer Systems"]], Customer Update, biz.digital.articles, 3 Nov 1994)]
